# Сохранённые поисковые профили

19.10: отдельно реализовано [расписание точных URL](FEATURE_URL_SCHEDULES.md).
Оно не исполняет фразы, поэтому не потребляет эти профили. Привязка profile_id+
revision к поисковому запуску/расписанию остаётся OPEN до подтверждённого доступа.

## Назначение

В «Сверке» → «Источники» → «Дополнительный поиск Threads» → «Подготовить фразы
RU/KZ» аналитик может сохранить параметры текущего помощника1.0. Это подготовка
серверных настроек для будущих запусков. Поиск и расписание не запускаются.

## Пользовательский сценарий

1. Выберите город, язык фразы, тему и необязательное название ЖК, задайте имя
   профиля. «Сохранить как новый профиль» создаёт v1 общую для команды.
2. После сохранения ссылка содержит `query_profile_id` и `query_profile_revision`;
   прежние candidate_id/q/section и другие фильтры сохраняются.
3. Перезагрузка позволяет открыть сохранённую версию. «Применить параметры» явно
   загружает её в конструктор; это не отправка фразы в Threads. Выбор отдельной
   фразы и запуск поиска остаются прежними самостоятельными действиями.
4. «Сохранить новую версию» создаёт снимок текущих параметров, сохраняя предыдущие.
   Номер версии + «Показать версию» читает историю; можно применить старую версию
   или создать из неё отдельный профиль. Историческую версию не перезаписывают.
5. При409 текущий ввод не меняется. «Обновить сохранённую версию» перечитывает
   метаданные; выберите актуальный номер и проверьте параметры перед явной записью.
   Ошибка загрузки повторяет GET, повтор сохранения — тот же UUID и payload.

Обычный ввод/раскрытие/выбор профиля/версии/обновление читают данные. Единственные
записи — явно подписанные кнопки сохранения. При поиске Threads DISABLED можно
подготовить и сохранить профиль; это не обходит проверку доступа платформы.
Словарь помощника1.0 не является переданным пользователем Social Monitoring v2.

## Данные и API

Миграция `bd67c945e138` после `ac56b834d027`, обычный `alembic upgrade head`.
Сохраняются параметры, готовые фразы, версия/байтовый SHA общего JSON, имя,
автор/время и ревизия. Набор запросов компилируется на сервере, присланный клиентом
compiled_queries отвергается. GET читает прежний снимок без перекомпиляции.

- GET `/api/v1/monitoring/query-profiles?page=1&page_size=20` — общая страница.
- GET `/api/v1/monitoring/query-profiles/{id}?revision=1` — заданный снимок;
  без revision — текущий. Ответ содержит также current_revision.
- POST `/api/v1/monitoring/query-profiles` — `{name, parameters}`.
- POST `/api/v1/monitoring/query-profiles/{id}/versions` — те же поля и
  `expected_revision`. Обе команды требуют analyst/session/CSRF/UUID Idempotency-Key.

parameters: dictionary_version=`1.0`, city из9алиасов, language=`ru|kk`,
topic=`all|booking|payment|installment|sales`, project<=100. Имя1–100символов;
пробельное имя/управляющие символы/неизвестные поля/параметры отклоняются.
Проект нормализуется по whitespace. Слабые геоалиасы сохраняются только с
строительным контекстом в скомпилированной фразе; это не подтверждение географии.
Конфликт ревизии —409, отсутствие профиля/версии —404, неверный ввод —422.
Одновременные изменения сериализуются row lock, одна новая версия при одном
expected_revision. Повтор команды возвращает её неизменённый исторический ответ.

Контракт0.28: аддитивные маршруты/DTO, роли старых endpoints не изменялись.
AuditEvent QUERY_PROFILE_VERSION_SAVED фиксирует авторство и старую/новую ревизии.
Подробности/ограничения упаковки JSON — [ADR-023](decisions/ADR-023-versioned-monitoring-query-profiles.md).

## Проверка и ограничения

Backend `test_query_profiles.py`: версии, повторы/conflict/concurrency, validation,
права/CSRF, история, неизменность предметных таблиц и отсутствие поиска.
Browser `monitoring-query-profiles.spec.ts`: ошибка/повтор с тем же ключом,
reload, история/409, сохранность ввода и query context. Opt-in
`SAQ_QUERY_PROFILES_LIVE=1` + QA URL localhost:3090 запускает
`zz-query-profiles-live.spec.ts` с реальным API и создаёт DEMO-профили только QA.
Рабочие результаты/restore и границы — PROJECT_STATUS.

Несохранённый ввод помощника остаётся mounted state и сбрасывается при reload;
сохранённая версия восстанавливается с сервера явной кнопкой. Если сохранение
прошло, но ответ потерян, проверьте список профилей/повторите тот же запрос.
Профиль не активируется автоматически. Нет удаления/архива/админки словаря,
расписания, новых источников, нового извлечения или оценки риска.
