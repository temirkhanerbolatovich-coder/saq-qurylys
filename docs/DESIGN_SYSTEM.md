## Визуальное направление

Светлое поле, графитовый текст, белая верхняя навигация и глубокий зелёный акцент главного действия. Зелёный бренд связан с проверяемой, спокойной рабочей средой; он не означает правовую безопасность объекта. Зоны риска получают отдельные текстовые подписи и семантические цвета. Тёплый нейтральный фон уменьшает визуальный шум. Основной реестр — карточки с названием, адресом, датой, серверным баллом и причинами; в подробном режиме доступны прежние таблица и карта.

Обзор имеет крупный короткий заголовок, одно основное действие «Добавить публикацию», пояснение трёх шагов, счётчик новых публикаций и три приоритетных объекта. Нет рекламного слайдера, чужих фотографий зданий, декоративных графиков и анимаций. Карточки используют фактические данные; приоритет основан на прежнем серверном балле в загруженной выборке до 100 объектов с явной подписью охвата.

Простой режим убирает из начального экрана KPI-полосу и набор дополнительных переходов, из меню — проверку/сигналы/сверку, из реестра — map/table и дополнительные фильтры, из досье — формы документов/историю/создание сигнала/техническую метаинформацию. «Инструменты аналитика» возвращает эти средства, не меняя URL, данные или полномочия. Уже заданные URL-фильтры остаются видимыми chips со сбросом. DEMO, UNKNOWN, источники, даты, факторы, доказательства и правовые оговорки сохраняются. Вводимые решения/выбранные файлы не размонтируются при переключении режима; URL/дата в формах раскрываются native details.

Режим хранится локально как `saq-detailed-interface`; при отсутствии/недоступности storage простой вид остаётся рабочим. Доступ по прежним ссылкам сохраняется, включая review после сохранения материала. Это сокращение основного интерфейса, а не удаление предметных возможностей/API.

## Сетка, отступы и поверхности

Шрифт и шкала заголовков задаются `--font-sans`, `--text-h1`…`--text-h6`, `--text-body`, `--text-caption`; уровень выбирается по структуре документа, не ради размера. H4–H6 готовы как базовые styles, но не создают новые уровни в экранах без смысловой необходимости. `--space-10/12` — 40/48 px, `--shadow-popover` зарезервирован для настоящего floating UI, не для всех panels.

- Базовая шкала: 4, 8, 12, 16, 24, 32, 40, 48 px. Контекстные интервалы 20 px допустимы для строк таблицы/текста.
- Верхняя навигация при любой ширине; до 1200 px пункты переносятся на следующую строку, до 600 px — открытая сетка по три пункта. Контент до 1440 px; padding 40 px desktop, 24 px tablet, 16 px phone. Карточки: 3 колонки, до 900 px — 2, до 600 px — 1.
- Две колонки dossier/review только при достаточной ширине; `minmax(0, 1fr)` и `min-width: 0`. Формы максимум 760–900 px, поля на всю ширину соответствующей колонки.
- Радиусы: 4 px badges, 6 px controls, 8 px documents. Большие pill-радиусы только у аватара/метки карты. Граница 1 px; focus 3 px с offset 3 px.
- Тени не нужны таблицам/документам. Лёгкая тень допустима у всплывающего меню/dialog и существующих меток карты.

## Компоненты и состояния

**Кнопка:** существующий `components/ui/button.tsx` (CVA/Radix Slot), варианты primary/outline/ghost/danger. Primary — главное действие локального блока; подтверждение и отклонение визуально различаются. Min-height 40 px desktop и 44 px touch. Disabled — `not-allowed`, не `wait`; ожидание обозначается текстом и `aria-busy` у настоящей кнопки. Hover меняет фон/границу, active слегка затемняет, focus остаётся видимым. Иконка не заменяет текст, icon-only требует accessible name и hit-area 44 px.

**Поля:** native input/select/textarea, видимые labels, граница control-border, подсказка рядом. Hover/focus повышают различимость. Required объявлен нативным атрибутом, ошибка не только цветом. Не менять names/ids/validation/API payload при визуальных изменениях. Файловое поле показывает нативное имя выбранного файла; выбор не считается сохранением.

**Таблица:** один заголовок на столбец, `scope=col`, названия объектов — ссылки. Строки разделены тонкими линиями, hover помогает отслеживанию. Коды риска дополняются короткой расшифровкой; детали доступны из карточки. На узком экране таблица прокручивается внутри подписанного focusable контейнера; сама страница не переполняется. Нельзя скрывать существенные столбцы только ради mobile.

**Карточка/документ:** заголовок, локальные действия и содержимое. Не оборачивать каждый параграф в отдельный box. KPI в подробном обзоре образуют общую сводную полосу; в простом обзоре она отсутствует. Формы отделены от read-only фактов.

**Навигация:** три текстовых пункта «Обзор / Объекты / Реклама»; подробный режим добавляет «Проверка / Сигналы / Сверка». `aria-current=page`, активное подчёркивание, явный keyboard focus; toggle использует `aria-pressed`. Профиль/роль/выход доступны при любой ширине. Skip link ведёт к main. В подробном досье обычные anchor-links к разделам; это не ARIA tabs и не размонтирует формы.

**Меню/modal:** не добавлять без задачи. Текущие дополнительные формы используют native details/summary; keyboard Enter/Space и состояние раскрытия сохраняются браузером. Если потребуется blocking dialog, использовать Radix Dialog с title/description, Escape, focus trap и возвратом фокуса; portal не должен закрывать активное поле. Не имитировать dialog одним div. Нативный select остаётся меню выбора, без новой UI-библиотеки.

**Loading:** текст с `role=status`, конкретное название операции, disabled защищает от повторного submit. Skeleton допустим только с зарезервированной геометрией. **Empty:** объяснить отсутствие данных и ближайшее доступное действие. **Error:** читаемый `role=alert`, повтор при сетевом отказе, введённые данные сохраняются. **Success:** явный результат и следующий шаг. **Selected:** `aria-current`/`aria-pressed` и различимый фон/граница; не только цвет.

## Адаптивность и WCAG 2.2 AA

Проверка материала использует последовательность четырёх этапов с буквальным состоянием API: сохранённый оригинал не помечается проверенным, «Проверено N из M» считает только CONFIRMED/CORRECTED/REJECTED hypotheses. Навигация — обычные anchors, не новые бизнес-команды и не заблокированный wizard. На desktop четыре колонки, при <768 px две; панель не sticky и не закрывает focus. Доступ к привязке/R2 объясняет прежние условия готовности, не ослабляя их.

Формы ввода используют section headings с небольшими функциональными номерами, labels и связанные helper text. Текстовый счётчик не является live region на каждый символ. Выбранный файл показывает имя/размер с переносом; превышенный размер объявляется aria-invalid, исходная проверка submit/сервер остаётся. После сохранения фокус направляется к результату операции; primary ведёт к проверке, secondary — к оригиналу.

Каталог повторного использования — [UI_COMPONENTS](UI_COMPONENTS.md). Pagination общая для реестра/сигналов, с серверными metadata и polite объявлением страницы; TableRegion задаёт доступную scroll-область. Сброс фильтров — один видимый control, сохраняющий list/map и возвращающий focus в поиск.

Светлая тема реализована; тёмная пока не реализована. Семантические `--color-*` позволяют позднее определить значения под `[data-theme=dark]` без смены names компонентов. Перед включением потребуются отдельные проверки всех состояний/контраста/карты/исходников и консолидация legacy raw colors; одного media prefers-color-scheme недостаточно. Наличие tokens не означает текущую поддержку dark mode.

Контрольные ширины 375/768/1024/1440 px. Навигация всегда сверху; <640 px действия и формы переносятся, поля 16 px. Оригинал/гипотезы на узком экране идут последовательно. Таблицы и карта имеют собственную область; не использовать глобальный overflow-x:hidden для маскировки дефекта.

Целевые критерии: text contrast ≥4,5:1 (крупный ≥3:1), control/focus ≥3:1, reflow при 320 CSS px, zoom 200%, WCAG 2.5.8 минимум 24×24 CSS px с допустимыми исключениями; проектный touch target — 44×44. Все действия доступны без мыши, логичный порядок фокуса, skip link, landmarks, visible labels, reduced-motion, состояния не полагаются только на цвет. Sticky-области не перекрывают фокус. Autofill/password manager/paste не запрещать.

Это целевой стандарт, а не сертификат соответствия. Наблюдавшиеся проверки и ограничения — [UI_AUDIT](UI_AUDIT.md). Ручной screen-reader аудит и UX с 3–5 людьми проводятся отдельно.

Реальный mobile login использует короткий заголовок 20/28 px и компактный контекст над формой; декоративной hero-области нет. В signals выбранная версия выделяется границей и подчёркиванием, а не только цветом.

## Основания решений

Первый редизайн 16.10.2026 сохранён в подробном режиме: обзор — пять приоритетных объектов с явным охватом API-выборки и рабочей колонкой; RiskSummary — общий серверный score/zone, confirmed codes, revision/as_of и правовая оговорка; данные не пересчитываются в браузере. Реестр сохраняет table rows, active filters и выделяет выбранный на карте объект текстом/границей. Досье и signals используют underlined anchor-links, сохраняя формы mounted. Read-only документы и editable решения имеют разные поверхности; native details/fieldset/legend сохранены. Headings/бренд явно наследуют системный sans-serif; Inter/Golos/Manrope не подключены: offline-доступность и существующая RU/KZ типографика важнее нового font payload.

Motion tokens: `--motion-hover:150ms`, `--motion-state:200ms`, `--ease-standard:cubic-bezier(0.2,0,0,1)`. Controls меняют цвет/фон/границу; появление результата/ошибки/доказательств — opacity и 4 px translate. Табличные строки и маршруты не анимируются; reduced-motion выключает переходы. Новых dialog/drawer/tooltip без сценария нет. Референсы, screen audit и фактические проверки — [UI_AUDIT](UI_AUDIT.md).

Просмотрено 15.10.2026: [shadcn/ui](https://ui.shadcn.com/) — владение компонентами и доступные defaults; [Radix Primitives](https://www.radix-ui.com/primitives) — keyboard/focus сложных элементов; [Lucide](https://lucide.dev/) — согласованная функциональная иконография; [Refactoring UI](https://www.refactoringui.com/) — публичные материалы о hierarchy/spacing (платная книга не прочитана); [NN/g heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) — видимость состояния, узнаваемость, контроль; [WCAG 2.2](https://www.w3.org/WAI/WCAG22/quickref/).

[UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) установлен в `.agents/skills/ui-ux-pro-max` на commit `56ea9cf174ed86786187daa9de0e6247cb0747e4`; локальные searches/generator preview и Codex discovery проверены. Результаты — advisory: автоматические sales patterns и замена палитры/шрифтов отвергнуты; existing API не переносится в Server Actions ради generic hint. Этот документ остаётся единственным проектным master. Pin/безопасность/установка и библиотечная матрица — [UI_IMPLEMENTATION_PLAN](UI_IMPLEMENTATION_PLAN.md).

[Linear public features](https://linear.app/features) использован как пример ясной иерархии рабочих действий, без копирования бренда/композиции. Изучены публичные Mobbin/Untitled UI; закрытые экраны/платные ресурсы не просматривались, Pageflows недоступен через текущий web-инструмент. Новых UI/runtime dependencies нет; существующие Tailwind/Radix Slot/Lucide сохранены. Magic UI/Motion совместимы, но не нужны для текущих задач аналитика.
