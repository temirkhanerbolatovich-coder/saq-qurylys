## Что измеряется

`scripts/evaluate_ocr.py` вызывает существующие `validate_image → recognize → extract → match_candidates`, без API, очереди, Settings/.env и БД. Передаётся отдельный каталог названий/алиасов; правильный ключ и payment label не передаются в проверяемые функции. Рендер использует только текст и стиль. Отдельный exact-text baseline проходит extraction/matching без OCR; это не теоретический верхний предел.

- Payment — бинарное наличие хотя бы одной `PAYMENT_TERM` в документе: TP/FP/FN/TN, precision, recall среди завершённых и end-to-end recall с ошибками обработки в знаменателе. Это не точность суммы/валюты, всех отдельных условий или подтверждения R2.
- Matching top-1/top-3 — точный expected key среди кандидатов / все читаемые known-target примеры; ошибки обработки остаются в знаменателе. Для отсутствующего объекта отдельно показана доля успешно обработанных примеров с любыми кандидатами. Similarity — строковое сходство, не вероятность.
- CER — сумма Levenshtein distances / сумма reference characters после NFKC и объединения пробелов. Регистр, пунктуация и KZ буквы сохраняются; CER может быть >1. Пустой успешный OCR считается удалениями; ошибки OCR исключены только из CER, с отдельным покрытием по примерам и символам. Raw OCR сохраняется даже при сбое последующей extraction.
- Разрезы all/RU/KZ, ошибки стадий, гипотезы и причины/score кандидатов сохранены. У нечитаемых отдельно считаются текст, payment hypotheses и candidates; нет выдуманной правильной отрицательной метки.

Предлагаемые цели команды: precision ≥0,90, end-to-end recall ≥0,85 и top-3 ≥0,90 при полном покрытии. Gate также требует ≥30 примеров, >3 объектов каталога, ≥12 читаемых и хотя бы один нечитаемый/positive/negative для каждого языка; маленький subset — exploratory. Это проектные цели, не требование организаторов. CI проверяет выполнение инструмента и сохраняет результат, **не объявляет качество принятым**. `--require-targets` включает ненулевой exit при недостижении целей.

## Правила 1.2 и границы результата

- Сегментация сохраняет `тыс.` внутри суммы и соединяет только продолжение суммы/незавершённого платёжного выражения через один LF/CRLF. Пустой абзац, включая строку с пробелами, и завершённое предложение остаются границами. Исходный текст, offsets и bbox не преобразуются.
- Добавлены «резервирование», «плата за бронь», «алдын ала төлеңіз», отрицания/free/zero regressions. Выбирается ближайшая допустимая сумма конкретного условия; цена квартиры больше не превращает нулевой аванс в платёж. `т/Т` не объявляется валютой: прямое требование платы может дать PAYMENT_TERM с `money=null`.
- Локальные признаки пересказа прошлой акции исключаются. Новое предложение после исторического условия сохраняется; одно слово «архив» или дата исходной рекламы не отменяет буквальное предложение. Это ограниченные правила, не универсальная модель понимания времени.
- После неудачи точного поиска названия fallback допускает только известные пары казахских букв (`ң/н`, `қ/к`, `ұ/у` и аналогичные), зарегистрированное имя/alias не короче 6 букв и границы целого слова. Произвольный edit distance не добавлен; ЖК/ТК и exact name имеют прежний приоритет. Гипотеза содержит реально прочитанное имя, предупреждение о диакритике и PENDING; matcher/порог не менялись.
- У длинного условия ограниченное окно до 2000 символов включает фактический термин и сумму. Если они не помещаются, PAYMENT_TERM не создаётся и выводится предупреждение.
- Новые automatic/manual extractions имеют `rules-1.2`. Сохранённые результаты, решения, риск и snapshots не переписываются. API/БД/зависимости/Tesseract/методика evaluator и labels не менялись. Отдельное архитектурное решение не требовалось.

Финальный `--require-targets` вернул 0; source hashes совпали с кодом после запуска, manifest и все 36 image hashes совпали с alias-fix-v1. CER не улучшился: изменения исправляют extraction/candidate generation, а не распознавание символов Tesseract. Публичные evidence: [report](../data/evaluation/results/2026-10-15/rules-1.2-report.json), [все cases](../data/evaluation/results/2026-10-15/rules-1.2-cases.jsonl); исходные images — ignored `output/evaluation/rules-1.2-reviewed`.

Текущий набор использован при исправлении правил и является regression-набором. **Нужны новый непросмотренный внешний holdout с правами на материалы и проверка KZ-разметки человеком**; только после этого можно обсуждать качество для пилота. Payment score не измеряет правильность всех сумм/валют и не устанавливает R2.

## Исправление и оставшиеся ошибки

Извлечение без префикса «ЖК/ТК» раньше проверяло только canonical name, хотя matching уже использовал aliases. Теперь точный registered alias тоже выделяется с исходными offsets/bbox и PENDING. Полное имя имеет приоритет над вложенным алиасом; дубликаты/совпадения внутри слова не создают лишние гипотезы. Версия pipeline для новых автоматических и ручных extraction повышена до `rules-1.1`; старые extraction и решения не переписываются. Порог matching/риск/контракт/БД не менялись.

Исторический разбор ошибок alias-fix-v1, исправленных в rules-1.2:

- False positives оплаты `ru-10`, `kz-10`, `kz-16`: исторические упоминания завершённых акций пока принимаются за текущее предложение.
- False negatives `ru-01`: перенос суммы и неверно распознанный знак ₸; `ru-04`: «тыс.» разбивает предложение до валюты; `ru-13`: «резервирование» отсутствует в словаре; `kz-02`: глагольное «алдын ала төлеңіз» не охвачено правилом.
- Пропуски matching `kz-03/04/05/09/11/12`: OCR меняет казахскую диакритику/написание названий, exact fallback не находит исходное имя/alias. Поиск нечёткой гипотезы названия вне префикса ещё не реализован.
- Отсутствующий `ru-13` получил похожего кандидата: candidate generation требует ручного подтверждения, не является доказанной привязкой.

Эталонные ответы/пороги после просмотра не менялись. Добавлены отдельные regression tests отрицаний/исторического контекста, сокращений, переносов, валюты, source spans и KZ fallback. Внешняя приёмка качества остаётся OPEN.

## Запуск и evidence

На Linux с установленными backend dependencies и Tesseract rus/kaz/eng:

```bash
python scripts/evaluate_ocr.py --output output/evaluation/new-run
python scripts/evaluate_ocr.py --output output/evaluation/new-gated-run --require-targets
python -m unittest discover -s scripts -p 'test_*.py' -v
```

`--manifest`, `--font`, `--tesseract`, `--languages` позволяют выбрать локальные входы. Manifest schema 1 допускает внешние PNG/JPEG через относительное `image` внутри каталога manifest; provenance.kind=external требует original image. Ссылки наружу/escaping symlinks, дубли IDs, неизвестные keys и неверные labels отклоняются. Применяются image/size limits приложения. Это CLI для доверенного локального набора, не endpoint загрузки недоверенного manifest.

Новая output-папка создаётся без перезаписи прежнего прогона: manifest snapshot, оригиналы images, cases.jsonl, report.json. Runtime preflight (binary/models/font) выполняется до создания каталога; ошибка останавливает запуск. Ошибки обработки отдельных изображений сохраняются и дают exit 2; `--require-targets` при полном, но недостаточно точном прогоне даёт exit 1. Хеши source/manifest/font в начале и конце проверяются, изменения делают результат неприемлемым. Traineddata хешируются на preflight; модели не должны меняться во время прогона. Пауза/сбой питания может оставить частичный каталог: используйте новое имя, не удаляя прежнее evidence.

Фактические прогоны выполнены через `docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --memory 1g --cpus 2 --pids-limit 128`, с tmpfs /tmp и read-only source/manifest mounts; writable только новый output-каталог. Рабочие storage/БД/env в контейнер не подключались. Сборка/обычный CI могут требовать сеть для установки зависимостей; собственно evaluator сетевых запросов не делает.
