# Импорт материалов CSV

Первый согласованный срез SAQ Social Monitor (ТЗ пользователя от 19.10.2026).
Это ручное поступление материалов в существующий workflow; автоматический сбор
соцсетей, расписание и разрешённые внешние коннекторы остаются отдельными этапами.

## Использование

Откройте «Проверка → Сверка → Импорт CSV» (`/monitoring?section=imports`).
Скачайте пустой шаблон, выберите файл и режим REAL/DEMO, нажмите «Проверить файл».
Предпросмотр показывает строки, исходный текст/ссылку, новые материалы, повторы,
новые версии и до трёх возможных объектов по названию. Это подсказки, а не связь.
«Сохранить пакет» — отдельная команда. Журнал показывает новые/повторные материалы,
точный исходный CSV и переходы к существующей проверке публикации.

Выбранный файл и предпросмотр остаются при переключении локальных вкладок.
Файл не сохраняется в localStorage: после полной перезагрузки его выбирают заново.
`csv_batch_id` восстанавливает сохранённый пакет, `csv_page` — страницу журнала;
остальные query-параметры и выбранные ID сохраняются. При ошибке фокус переходит
к сообщению над формой; нет команд при раскрытии текста или навигации.

## Форматы и границы

- UTF-8 с BOM или без, разделитель запятая/точка с запятой, 1–100 записей,
  максимум 256 КиБ и 30000 символов на поле. Кавычки и многострочный текст поддержаны.
- Стандартные обязательные заголовки: `source_label,source_url,text`.
  Дополнительные: `published_at,platform,external_id,project_name,city`.
  Неизвестные/повторные заголовки и неверное число столбцов отклоняют весь файл.
- Источник обязателен; нужен текст или HTTP(S)-URL без credentials. Ссылки только
  сохраняются, сервер не обращается к ним. `external_id` требует `platform`.
  `published_at` — ISO 8601 с часовым поясом; отсутствие даты остаётся неизвестным.
- Поддержан точный набор русских заголовков пользовательского социального аудита
  `saq_oskemen_social_ads_2026-10-19.csv`. Строки одного ЖК и URL объединяются,
  все строки/оговорки остаются. Такой материал явно обозначен как пересказ автора,
  а дата автора не становится проверенной датой публикации.
- Запись без текста помечается «Ссылка без оригинала». Импорт не извлекает HTML,
  изображение, OCR или содержимое профиля, не подтверждает нарушение.

Число «материалов» может отличаться от числа строк. Исторические пакеты внешнего
offline importer не появляются в новом журнале задним числом. Их публикации
распознаются при предпросмотре по URL и сохранённым исходным строкам.

## Хранение и повторные загрузки

`csv_import_batches` содержит неизменяемую квитанцию: SHA файла, режим, автора,
дату получения, числа новых/повторных материалов и снимок предпросмотра.
`csv_imported_materials` связывает fingerprint содержимого с Advertisement.
Точный CSV — отдельный Asset (MIME text/csv, внутренняя .txt для совместимости
storage/backup, скачивание .csv). Текст каждого нового материала — собственный Asset.

Одинаковые байты в том же режиме возвращают прежнюю квитанцию, даже с новым
Idempotency-Key. Одинаковый материал в другом файле сохраняет Advertisement ID.
Идентичность: platform+external_id, иначе URL; без обоих — источник+точный текст.
URL-нормализация убирает fragment, www, default port и известные tracking-параметры;
пути и остальные query-параметры не угадываются. REAL/DEMO всегда разделены.
Fingerprint включает тип материала, содержимое и уточнения проекта/города/даты.
Изменившийся материал с известной идентичностью создаёт новый Advertisement,
ссылается на прежний; существующий текст и решения не перезаписываются.
ID строки социального файла не определяет идентичность; остальные оговорки учитываются.

Preview не пишет в БД/storage. Commit повторно проверяет digest предпросмотра,
при изменении состояния возвращает 409 с требованием повторить проверку.
PostgreSQL advisory lock сериализует CSV commits; unique fingerprints и command key
защищают повтор. Записи пакета, материалов, аудита и команды фиксируются одной
транзакцией. Ошибка откатывает БД; content-addressed файл, созданный перед rollback,
может остаться без ссылки, как в существующем upload. Backup включает только Assets.

## API и права

Добавлены `/api/v1/monitoring/csv-imports` GET (page/page_size/is_demo) и POST,
`/preview` POST, `/template` GET, `/{id}` GET. Контракт 0.26.0 в openapi.yaml.
POST multipart: file и is_demo; commit также preview_digest и Idempotency-Key.
Оба POST требуют analyst и CSRF/Origin. Viewer читает журнал/пакеты/исходники.
Не меняются роли, формула R1–R6, подтверждения OCR/match/фактора/сигнала, старые URL.
Загрузка не создаёт досье, analysis job, confirmed property link или фактор.

## Проверка и ограничения

`backend/tests/test_csv_import.py`: валидация, отсутствие записей preview,
атомарность/конкурентность/retry, оригинальные байты, версии, права/CSRF,
совместимость с прежним social import и контракт.
`frontend/tests/csv-import.spec.ts`: реальный CSV preview/commit/download/reload,
повтор, ошибки, сохранность вкладок, RU/KZ и 375/768/1024/1440 px.
Запускать изменяющие E2E только в отдельной тестовой среде.
Фактические результаты текущего запуска — PROJECT_STATUS и UI_AUDIT.

Первый срез не включает XLSX, исторические backfill-журналы, fuzzy-дедупликацию,
геокодирование, расписание и фоновые social fetch jobs. Legacy URL lookup читает
список сохранённых URL; при существенно большем объёме понадобится индексированная
нормализованная идентичность для старых материалов. Новая зависимость не добавлена.


## Сквозная техническая приёмка ·19.10.2026

`frontend/tests/zz-tz-v2-journey.spec.ts` теперь начинает сценарий с CSV preview/
commit в UI, а не прямой подготовки материала API. Это DEMO в отдельной БД:
источник example.org, отдельные кандидат/досье/привязка/гипотеза/R2/сигнал,
затем скачанный PDF и новая версия с сохранением прежнего PDF. Даты публикации
и получения, оригинальный CSV/текст и SHA проверяются самостоятельно.
Новые результаты пишутся в UUID-папки `output/qa/intake-journey-20261019/`.

Запускать только в уже подготовленном изолированном QA3090:

```powershell
cd frontend
$env:SAQ_E2E_BASE_URL = 'http://localhost:3090'
$env:SAQ_ISOLATED_ACCEPTANCE = '1'
npx playwright test tests/csv-import.spec.ts tests/zz-tz-v2-journey.spec.ts tests/monitoring-sources.spec.ts tests/open-sources.spec.ts
```

Проверка артефактов из корня с pypdf из backend requirements:

```powershell
python scripts/verify_intake_journey.py "output/qa/intake-journey-20261019/<UUID из лога>"
```

После неё отрисуйте `signal-archived.pdf` через Poppler и просмотрите **каждую**
страницу. Script проверяет хеши/содержимое/A4/пагинацию, но не верстку по пикселям.
Здесь используются существующие изолированные Compose/БД/storage; подготовка
новой чистой машины является отдельным незакрытым этапом. Не запускайте такой
тест на рабочей БД. Локальный3000 пропускается даже при opt-in; прежний CI
одноразового GitHub Actions на3000 сохраняется через явную проверку окружения.

Фактически18browser PASS и3страницы PDF проверены. Это техническая DEMO-приёмка,
не предметная проверка реальных компаний, не оценка OCR и не социальный parser-v2.
Команды/границы/fingerprints и точная итоговая папка — PROJECT_STATUS.
