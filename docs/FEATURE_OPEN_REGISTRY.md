# Открытый документ КЖК: версии и поиск

Реальный временный источник — [публичный реестр гарантий КЖК](https://khc.kz/ru/equity/uslugi/357/3260/). Это справочный документ о гарантиях, не закрытый утверждённый реестр заказчика и не полный список всех применимых механизмов. Первичный документ на дату среза, очереди и действительность конкретного основания проверяет аналитик.

## Пользовательский путь

В «Сверке» аналитик открывает «Добавить новую версию PDF», скачивает документ с сайта КЖК и загружает PDF вместе с исходной ссылкой `https://khc.kz/upload/…pdf`. Приложение само эту ссылку не загружает: robots сайта ограничивает обход `/upload/`, лицензия повторного использования не установлена. Операторское происхождение указано явно; ссылка и SHA не удостоверяют подлинность файла у издателя.

Сохраняются оригинальные байты как authenticated attachment, SHA-256, издатель, ссылка, дата состояния из документа, страницы с текстом, автор/время загрузки. Повтор того же PDF возвращает прежний документ; новый файл создаёт отдельную версию. История не переписывается. Просмотр и поиск доступны analyst/viewer, загрузка — analyst + session/CSRF/Idempotency-Key.

Поиск требует все введённые слова на странице, показывает её номер, фрагмент и совпавшие слова. Они могут относиться к разным строкам; это объяснимый поиск документа, не установленное совпадение объекта. Отсутствие результата не доказывает отсутствие основания. Никаких изменений Property/DEMO-снимков/факторов/сигналов/Telegram он не выполняет.

## Контракт и ограничения

- `POST /api/v1/monitoring/open-registry`: multipart `file,source_url` → документ.
- `GET /api/v1/monitoring/open-registry`: серверная пагинация; UI показывает последние 100 с указанием ограничения при превышении.
- `GET /api/v1/monitoring/open-registry/search?document_id=…&q=…`: найденные страницы выбранной версии.

PDF: 5 MiB, 50 страниц, 30 000 символов на страницу, 250 000 всего; строгая проверка пассивного PDF, извлечение в Linux subprocess с ограничениями CPU/memory/wall time (10 секунд). Windows fail-closed 503; рабочий путь — Linux Docker. Размер HTTP-body ограничен до multipart parsing. Не поддерживаются сканы без текстового слоя, автоматический OCR, обновление по расписанию и назначение ACTIVE/REVOKED/сроков применимости.

17.10.2026 получен [PDF КЖК](https://khc.kz/upload/sprint.editor/c25/ow5xv10xtplffwlzezegbfjydfm4e5bs.pdf): 883125 bytes, SHA `26a19cd23ed3a7ac30605ed019c68feb2d183f1aeb6199f995848e99f1b3c739`, состояние 02.10.2026,12 страниц. Извлечены 23679 символов. Заголовок заявляет56 договоров, нумерованных строк54 (6 и8 отсутствуют). Цветовой статус не интерпретируется; дата подписания не назначается `valid_from`, срок строительства не назначается `valid_until`. Это основание сохранять UNKNOWN и проверять оригинал.

Проверки: `pytest -q backend/tests/test_open_registry.py`; Windows mocks Linux subprocess проверяют контракт и ошибки, настоящий bounded parser отдельно проверяется в Linux. Точные текущие результаты runtime/browser — [PROJECT_STATUS](../PROJECT_STATUS.md).
