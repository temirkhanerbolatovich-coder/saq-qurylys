## Решение и точный следующий шаг

Первый кандидат по соответствию контенту и географии — AN GROUPS /payment;
это предложение исследователя, не утверждённый источник. Исторический YK.KZ
Novy Bereg пригоден для обследования структуры/дат после согласования владельцем.

Для перевода одного кандидата в APPROVED нужны проверяемые условия, допускающие
ограниченный автоматический GET, точное внутреннее хранение оригинала/текста/SHA
и показ происхождения аналитику. Затем проверить robots для выбранного UA,
границы host/path, отсутствие login/JS-заглушки, структуру и известность даты.
Это проектная граница [AGENTS.md](../../AGENTS.md): collector только по
разрешённому источнику; отсутствующее разрешение не выдумывается.

Если появится такое основание, следующий implementation-срез: один reviewed
host/path adapter → существующий IMPORT_URL job/lease → original+text/provenance
→ отдельный запуск анализа/проверка человеком. Сначала disposable acceptance;
на рабочую базу — после проверки и backup. C-01 закрывать только по настоящему
разрешённому импорту, дублю, ошибке и recovery. Scheduler до этого не включать.

Проверки этого research-среза: фактические web-page/rules observations выше,
offline отказ текущего allowlist для трёх кандидатов и git diff --check.
Новых API/миграций/конфигурации/runtime изменений и импортов в БД нет.
Полные backend/browser suites не повторяются для изменения только документации.
