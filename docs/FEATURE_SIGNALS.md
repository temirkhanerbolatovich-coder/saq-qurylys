# Сигналы и PDF

Сигнал сохраняет проверяемый исторический снимок для решения аналитика. Он не устанавливает факт правонарушения и не отправляется автоматически во внешние органы. При DEMO-данных маркировка сохраняется в карточке и PDF.

## Пользовательский сценарий

1. В карточке объекта создать сигнал по текущей ревизии риска. Сервер сохраняет DRAFT: создание снимка не подтверждает сигнал.
2. В «Сигналах» проверить объект/очередь, основания, факторы, доказательства, неизвестные сведения и исходники.
3. Аналитик явно подтверждает либо возвращает DRAFT с непустой причиной. Автор и время решения фиксируются. Одно решение завершает эту версию.
4. PDF решения ставится в очередь автоматически. Можно отдельно запросить PDF черновика, проверить состояние и скачать готовый файл.
5. Для доработки создать новую версию с `previous_signal_id` последнего сигнала этого объекта. Предыдущая версия, решение и её файлы сохраняются.

## Данные и актуальность

`Signal.snapshot` содержит объект и рассчитанный backend риск, правовые основания, все статусы факторов, связанные доказательства и метаданные исходников (`assets`, включая SHA-256), неизвестные сведения и дисклеймер: «Сигнал необходимости проверки; не устанавливает факт правонарушения». Имена автора и проверяющего копируются в запись: последующее переименование пользователя не меняет историю.

На создании и решении проверяются сохранённые байты исходников по SHA-256. Контрольная сумма показывает целостность копии, но не доказывает её подлинность или достоверность.

`is_stale` вычисляется при чтении: учитываются ревизия объекта, содержимое текущих фактов/области/источников, применимость правовых оснований на текущую дату и наличие более новой версии сигнала. Течение времени может изменить применимость основания без изменения ревизии. Служебный `risk.as_of`, равный текущему времени для ещё не проверенного объекта, сам по себе не делает снимок устаревшим.

Решение требует совпадения `expected_revision` сигнала и `expected_risk_revision` объекта, а также актуального снимка. Конфликт возвращает 409; требуется новый снимок. Исторический JSON/PDF при этом не переписывается. Цепочка версий одна на объект: пропущенный или чужой predecessor, повторное продолжение старой версии и повторное решение отклоняются.

## API и компоненты

| Операция | Результат |
|---|---|
| `GET /api/v1/signals` | Фильтры объекта, состояния, актуальности; пагинация |
| `POST /api/v1/signals` | DRAFT по текущей ревизии риска |
| `GET /api/v1/signals/{id}` | Снимок, решение и состояние PDF |
| `POST /api/v1/signals/{id}/decision` | CONFIRMED/RETURNED и очередь PDF новой ревизии |
| `POST /api/v1/signals/{id}/pdf` | 202 и durable job; повтор использует текущую задачу |
| `GET /api/v1/signals/{id}/pdf` | 200 PDF, 202 ожидание, 404 ещё не запрошен, 503 сбой/повреждение |

Чтение доступно авторизованным analyst/viewer; команды — analyst с CSRF/Origin и Idempotency-Key. GET не создаёт задач и не восстанавливает файлы скрытно. История команд и решений записывается в аудит.

Основные файлы: `backend/app/signals.py`, `signal_dto.py`, `api/signals.py`, `signal_pdf.py`, `api/signal_pdf.py`, `pdf_render.py`; модель Signal и миграция `e87f4d01a921`. UI — `frontend/components/signals-workspace.tsx`. Архитектурное решение — [ADR-006](decisions/ADR-006-immutable-signals-pdf.md).

## Очередь, PDF и безопасность

Используется существующая PostgreSQL-очередь AnalysisJob с `kind=RENDER_PDF`, nullable advertisement target и отдельными `signal_id`/`target_revision`; отдельный сервис очередей не добавляется. Команды блокируют property, затем signal. Worker перед сохранением дополнительно блокирует job и проверяет claim_token, ревизию решения и текущий pdf_job_id. Поздний worker не подменяет PDF нового решения.

Файл получает собственный Asset, связанный с точной ревизией. После решения PDF черновика остаётся историческим файлом; текущий указатель переключается на PDF решения. Состояние генерации отдельно: NOT_REQUESTED → QUEUED → READY/FAILED. При сбое сигнал сохраняется; явный повтор ставит новую задачу. Lease позволяет восстановить прерванную работу в пределах настроенного числа попыток.

PDF создаёт WeasyPrint 70 в отдельном subprocess. Поддерживаемый путь запуска — Linux Docker с Pango и системными DejaVu для RU/KZ. Шаблон получает только экранированный текст; HTML пользователя не исполняется. URL fetcher запрещает все ресурсные URL, включая локальные файлы и сеть; адрес источника выводится текстом.

`PDF_TIMEOUT_SECONDS` по умолчанию 60, допустимо 1–90. JSON-вход ограничен 5 000 000 байт; результат — `MAX_UPLOAD_BYTES` (по умолчанию 10 MiB). Timeout, сбой рендера, превышение размера, повреждение хранения и устаревшая задача дают диагностируемую ошибку. Это ограничения MVP, а не полная изоляция произвольного HTML: пользовательский HTML здесь не принимается.

## Проверка и ограничения

Полный итоговый прогон 15.10.2026: **217 backend-тестов в Linux passed (124.31s)** и **16 browser-тестов passed (47.2s)**, включая настоящий PDF, решения, версии, конфликт 409 и сохранение причины. Логи: `.local/signals-final-container-pytest.log`, `.local/signals-final-browser.log` (локальные, исключены из Git). Ранее отдельно прошли 18 core-тестов сигналов; host PDF дал 6 passed / 1 skipped без native Pango. Этот skip закрыт полным Linux-прогоном.

Полная проверка выполнялась во временном Linux test container Compose api: source/contracts подключены read-only, dev-зависимости установлены в отдельный временный venv с `--system-site-packages`, cache/pyc отключены. Команда тестов — `pytest -q`, БД — отдельная случайная schema. Рабочие API-зависимости не изменялись.

Образ backend содержит Pango/Harfbuzz и DejaVu. При самостоятельной установке в Linux нужны `libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0 fonts-dejavu-core`; затем `pip install -r backend/requirements-dev.txt` и из backend `python -m pytest -q`. Каталог contracts должен быть доступен рядом с backend. Для отдельного focused-прогона укажите `tests/test_signals.py tests/test_signal_pdf.py` после `pytest -q`. На Windows без системных библиотек WeasyPrint частичный host-прогон не заменяет полный Linux-тест.

В тестах покрыты неизменяемость, автор, хеши, роли/CSRF, optimistic revisions, идемпотентность, запрет ветвлений и параллельных решений, временная применимость, очередь/ошибки/повтор, исторические assets и защита шаблона. Десятистраничный синтетический PDF дополнительно отрендерен; текстовые DEMO/RU/KZ-маркеры проверены. Все 10 страниц просмотрены на contact sheet, страницы 1 и 9 дополнительно в полном размере: читаемо, перекрытий не обнаружено. Локальный артефакт — `output/pdf/signal-demo.pdf` (около 37 KiB, исключён из Git).

PDF не заменяет правовую проверку. Supporting PDF upload ещё не реализован: экспорт сигнала не закрывает загрузку исходного PDF-документа. Retention исторических файлов, большой объём снимков и приёмка на другом ПК остаются отдельными задачами: [чеклист](REMAINING_CHECKLIST.md).
