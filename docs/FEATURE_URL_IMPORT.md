AN GROUPS: извлекаются три мобильные карточки `t1073__col`, их заголовки и
описания. Это явно указано на форме импорта, в карточке материала и проверке.

Корни категорий, неизвестные/вложенные рубрики и непроверенные KZ-подрубрики отклоняются. Footer прямо указывает CC BY4.0. Рекламный C-01 остаётся OPEN: официальная информация о жилищной программе не является коммерческим объявлением. Историческое PLANNED ниже относится к состоянию16.10.

Рабочий путь: `/advertisements/new` → «Открытая публикация по ссылке» → `POST /api/v1/advertisements/import-url` → существующий `AnalysisJob(kind=IMPORT_URL)` → worker → сохранённая публикация. Только analyst/session/CSRF/Idempotency-Key; `is_demo=false`. URL проверяется до очереди и повторно worker; клиент не задаёт политику/парсер. Fetch выполняется вне DB-транзакции с прежними DNS/IP/TLS/redirect/size/time ограничениями. Одновременно не более10 активных URL jobs; одинаковый активный URL переиспользуется. Lease/claim token отсекает поздний worker, исчерпанные попытки завершаются ошибкой.

Сохраняются точные HTML-байты/SHA/private attachment, текст выбранной статьи, конечный/запрошенный URL/redirects/UTC-время получения, издатель/CC BY4.0/описание преобразования. Footer/Telegram/scripts не включаются в текст. Неизвестная дата не подменяется временем загрузки: показанная сайтом дата без timezone остаётся null в `published_at`. В интерфейсе лицензия и преобразования доступны рядом с сохранённым материалом. Ссылка на источник не означает одобрения проекта издателем.

Дедуп по конечному URL+извлечённому тексту+известной опубликованной дате сериализован PostgreSQL lock. Повтор неизменённой статьи с новым ключом открывает существующий материал; новый текст создаёт новый неизменяемый оригинал. Повтор команды с прежним ключом возвращает прежний job. После terminal UI создаёт новый ключ для нового намерения; после неопределённой сетевой ошибки сохраняет ключ. Автоматического анализа/подтверждений/баллов/уведомлений от импорта нет.

Ошибки источника/формата/таймаута не создают фиктивный материал. UI хранит URL, показывает состояние и явный повтор/ручной ввод. JS-shell без ожидаемой статьи отклоняется. После запуска ID задания сохраняется в query `?job=<UUID>`; reload/ссылка/Back восстанавливают статус только GET-запросами, без нового импорта/анализа. Проверяются ID/kind, устаревшие ответы не заменяют выбранное задание. Некорректный ID не отправляется на сервер; ошибка чтения допускает явную повторную проверку и «Новый импорт». Исходный URL не хранится в browser storage/query: после reload для повторного импорта FAILED/BLOCKED нужно ввести его снова. Роли/CSRF/idempotency сохранены. Расписание, discovery, коммерческие площадки и общий rate limit источника — последующие этапы.

Проверки: `pytest -q backend/tests/test_url_import.py backend/tests/test_url_fetcher.py`; реальная загрузка, повторы и browser результаты — [PROJECT_STATUS](../PROJECT_STATUS.md). Решение — [ADR-011](decisions/ADR-011-open-information-and-register-documents.md).

## Что реализовано

`backend/app/url_fetcher.py`: `fetch_html(url, policy)` возвращает исходные HTML-байты, запрошенный и конечный URL, цепочку переходов, Content-Type и UTC-время получения. Функция не сохраняет материал в БД/storage, не извлекает текст или дату публикации, не выполняет HTML/JavaScript и не загружает картинки/iframe/CSS. Дата публикации не подменяется временем получения.

`SourcePolicy` — доверенная серверная конфигурация одного точного домена и разрешённых поддеревьев путей. Её нельзя принимать от клиента. В проекте **нет включённого источника**; `fetch_html(url)` без политики возвращает `SOURCE_NOT_APPROVED` до запуска процесса или сети. Создание объекта конфигурации само по себе не подтверждает разрешение владельца сайта.

| Ограничение | Реализация |
|---|---|
| URL | Только HTTPS/443, точный hostname без wildcard/поддоменов, credentials/IP literals/fragments запрещены; контрольные символы, неоднозначные пути, traversal и повторное кодирование отклоняются |
| DNS/SSRF | Проверяются все A/AAAA адреса; весь ответ отклоняется при непубличном, multicast, reserved или переходном IPv6 адресе; только global unicast IPv6 из 2000::/3 с дополнительными исключениями |
| Rebinding/TLS | Socket подключается к проверенному числовому IP без повторного DNS; SNI и проверка сертификата используют исходный hostname; TLS verification включена |
| Redirect | Не более 3 по умолчанию, максимум 5; повторная проверка URL и DNS на каждом переходе, обнаружение циклов; запрет перехода на другой домен/путь/HTTP |
| Размер | 2 MiB по умолчанию, максимум конфигурации 10 MiB; ранняя проверка Content-Length и чтение не более limit+1, включая chunked/ответ без длины |
| Время | 20 секунд по умолчанию, 1–60 секунд конфигурации; subprocess timeout покрывает DNS, TLS, заголовки, все redirects и slow body; по timeout процесс завершается с ожиданием его выхода |
| HTTP | Только GET, успешный статус 200 и единственный `text/html`; без Cookie/Authorization/прокси окружения; `Accept-Encoding: identity`, сжатые ответы отклоняются без распаковки |
| Ошибки | Стабильный код, сообщение на русском, признак допустимости явного повтора; адреса инфраструктуры, исключения и тело страницы не попадают в пользовательскую ошибку |

Одна попытка использует первый проверенный DNS-адрес. Автоматического перебора адресов и повторов нет. Временные DNS/network/timeout/408/429/5xx ошибки имеют `retryable=true`; запрет источника, 401/403/404, TLS, формат, размер и нарушения политики требуют ручного действия. Все сообщения предлагают ручной ввод. Безопасная идемпотентность job и пользовательский retry ещё не реализованы этим модулем.


Тесты запрещают реальную сеть/DNS. Для HTTP framing используется настоящий stdlib HTTPResponse с синтетическими байтами. Проверяются mixed public/private DNS, IPv4/IPv6, закрепление IP и TLS hostname, redirects, framing/size limits, ошибки, точное сохранение байтов и происхождения. Остановка зависшего процесса проверяется настоящим subprocess timeout; отдельный настоящий subprocess отклоняет запрещённый URL до сети. Это не проверка реального DNS/TLS сайта и не внешний импорт. Набор включается в существующий CI через обычный `pytest`, но удалённый CI текущих локальных изменений ещё не выполнялся.

## Следующий связный блок

1. Установить один рекламный источник с разрешением на автоматический GET, сохранение оригинала/текста, внутренний анализ и показ происхождения. Зафиксировать домен, пути, конкретный URL, основание разрешения, условия и дату их проверки; проверить robots для согласованного User-Agent. Robots не заменяет разрешение.
2. Проверить ограниченный реальный образец, определить извлечение именно рекламного материала и опубликованной даты. HTML-заглушка/login/CAPTCHA не должна становиться успешной рекламой; неизвестная дата остаётся null. Если сайт требует JS/сжатие/внешние изображения, отдельно согласовать минимальное расширение транспорта.
3. Подключить существующие jobs, lease/claim token, idempotency и audit. Сохранить HTML-оригинал/SHA, текст и происхождение; выдавать оригинал только authenticated attachment. Не смешивать fetch и автоматическое подтверждение OCR/match/R1–R6.
4. Добавить UI URL → job → результат/понятная ошибка → явный безопасный повтор либо ручной ввод. Проверить контракт, права/CSRF, гонки, рестарт и browser E2E.
5. Закрыть C-01 только после фактического разрешённого импорта с сохранённым оригиналом и проверенными failure/recovery сценариями.

Решение об HTTPS, закреплении IP и subprocess — [ADR-008](decisions/ADR-008-bounded-url-transport.md). Нагрузка, общий concurrency/quota лимит и egress firewall остаются задачами интеграции/пилота; модуль не является полной границей изоляции сети ОС.
