# SAQ QURYLYS — локальная копия и проверка восстановления

Инструмент для локального Docker MVP: сохраняет PostgreSQL вместе с исходниками и PDF, затем проверяет копию в отдельном временном окружении. Рабочую БД он не восстанавливает и не перезаписывает. Это проверка восстановления на текущем компьютере; она не заменяет запуск на втором ПК, внешнюю резервную копию или промышленную стратегию аварийного восстановления.

## Создание копии

Нужны Python 3.12+, работающий Docker Desktop с Linux engine и существующее локальное окружение SAQ из README. Дополнительные Python-пакеты на хосте не нужны. Перед снимком завершите ручные изменения и не запускайте параллельные тесты или SQL-запись.

Из корня проекта:

```powershell
python scripts/backup_local.py create
```

Команда создаёт новую папку в игнорируемом `.local/backups/` и сообщает её путь. API и worker SAQ кратко приостанавливаются на время снимка, чтобы сопоставить одну БД с её файлами и контрольными суммами. После снимка команда возобновляет только те контейнеры, которые сама приостановила, в том числе при обычной ошибке. Другие проекты не затрагиваются. Пока API приостановлен, UI-запросы могут ждать или завершиться ошибкой; избегайте повторного нажатия изменяющих действий.

Копия содержит:

- `database.dump` в custom-формате PostgreSQL;
- `storage/` с файлами, на которые ссылаются записи Asset;
- `manifest.json` с ревизией кода, образом API, количеством и хешем строк каждой public-таблицы, метаданными файлов и SHA-256 дампа.

Внебазовые файлы storage, например незавершённые временные файлы и сироты, не являются частью восстановления записей и не копируются. Если зарегистрированного файла нет, размер или SHA не совпали, снимок считается неуспешным. Незавершённую папку не следует принимать за готовую копию.

Копия приватная: дамп содержит учётные записи, хеши паролей, сессии и историю. Не прикладывайте его к публичному GitHub/CI. `.env` и пароль в копию не включаются; текущая `.env` нужна для последующей проверки входа. Необходимые секреты и нужный образ приложения сохраняйте отдельно в согласованном защищённом месте. SHA выявляет повреждение, но не удостоверяет доверенного автора копии.

## Проверка восстановления

Подставьте путь, который выдала команда `create`:

```powershell
python scripts/backup_local.py verify ".local/backups/ИМЯ_КОПИИ"
```

Перед восстановлением проверяются манифест, пути и контрольные суммы. Восстанавливайте только свою доверенную копию: [pg_restore выполняет содержащиеся в дампе команды](https://www.postgresql.org/docs/17/app-pgrestore.html), а совпадение SHA не делает чужой дамп безопасным.

Проверка создаёт отдельный PostgreSQL 17.9 в контейнере с уникальным именем, без опубликованных портов, с `network none` и временным PGDATA. Storage копируется в новую приватную папку `.local/restore-checks/`. Существующие таблицы, исходные файлы и рабочие volumes не подменяются.

Сначала сравниваются все public-таблицы: число строк и хеш их содержимого, включая решения, снимки сигналов, evidence и аудит. Затем приложение из зафиксированного локального образа запускается на восстановленной БД: без seed, миграций и worker. HTTP-проверка выполняет вход и скачивает ранее сохранённые материалы/PDF, сверяя их SHA. Изменения сессии от тестового входа относятся только к временной БД. Повторный рендер PDF не заменяет проверку сохранённого файла.

Рабочая база после удаления DEMO может не содержать сигналов. Это допустимо:
проверяются все существующие записи, а нулевое покрытие сигналов/исторических PDF
явно записывается в result.json. Отсутствующие решения не создаются ради проверки.

Проверочный API использует сетевое пространство изолированной БД, отдельную строку подключения и восстановленный storage только для чтения. Для чтения скопированных файлов с режимом `0600` только этот одноразовый API-процесс запускается как root; рабочие API/worker остаются со штатными правами. Исходная `.env` передаётся только локальному проверочному контейнеру, содержимое секретов не печатается.

По окончании удаляется только созданный проверкой временный контейнер. Сама копия, восстановленные файлы и отчёт остаются под `.local/`. При прерывании питания/принудительном завершении процесса блок `finally` не гарантирован: проверьте состояние именно SAQ API/worker и наличие временного контейнера, прежде чем продолжать. Не используйте `docker compose down -v` или общую очистку Docker ради этой проверки.

## Ограничения

- Это один локальный проект и один public schema, а не резервирование всего кластера PostgreSQL: роли/глобальные настройки/другие базы не входят в процедуру.
- Все writers текущего MVP должны проходить через приостанавливаемые API/worker. Параллельные SQL-клиенты и тесты нарушают предпосылку согласованного снимка.
- Для HTTP-проверки нужны текущие рабочие bootstrap credentials и локально доступный зафиксированный образ API; несовпадение пароля или отсутствие образа не подменяется новым seed.
- Очередь и lease сохраняются в БД, но worker в проверке не запускается. Это не доказательство аварийного восстановления выполнявшегося OCR или PDF job.
- Проверка на одном диске не защищает от потери компьютера. Внешнее хранение, шифрование, retention, расписание и регулярные учения остаются отдельными задачами пилота.

Основание выбора: существующая архитектура хранит БД и файлы отдельно, а [pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html) сохраняет только БД. Поэтому проверяется именно пара БД+файлы и чтение сохранённых PDF через приложение. Контракт API и формула риска не меняются.

## Граница чистой установки и source-архива

Versioned helper требует git rev-parse HEAD. В source-архиве без .git revision не определяется; используйте Git checkout либо отдельный ручной рецепт из [BACKUP_RESTORE](operations/BACKUP_RESTORE.md). Verify требует минимум один non-SIGNAL_PDF asset и записи аудита; пустая установка до первого материала этим HTTP-покрытием не принимается. DB/schema/SHA restore для неё проверяется отдельно.
