# ADR-025: История словаря и сохранённые V2 профили

Статус: принято для локального QA. Дата:19.10.2026.

## Контекст

Словарь V2 и offline compiler уже существуют. Нужна явная активация с автором,
причиной и историей; смена bytes/правил не должна переписывать сохранённый профиль.
Существующие профили1.0 и UI продолжают работать с прежним контрактом параметров.

## Варианты

Хранить только путь/SHA и компилировать при чтении; изменять единственный active
флаг; либо хранить bytes и отдельный журнал выбора с замороженным preview.
Первый вариант зависит от будущей поставки, второй теряет историю/усложняет гонки.

## Решение и причины

Две таблицы: уникальные по SHA версии с original/v2 bytes и append-only активации
с монотонной revision. Null ID означает явную деактивацию. Общая transaction
advisory lock и expected_revision разрешают только одного победителя гонки;
та же lock охватывает сохранение V2 профиля. Используем существующие команды,
audit, auth/CSRF и профили вместо нового параллельного механизма.

Профиль фиксирует dictionary ID/SHA и полный результат compiler, включая query
IDs и происхождение. Чтение не запускает compiler. Schema профиля неизменна;
старые list/detail по умолчанию1.0, V2 требует явного фильтра2.0.
Регистрация ограничена двумя проверенными файлами поставки, без upload/URL.

## Последствия и риски

Данные воспроизводимы после restart/переключения словаря. Хранение preview/bytes
увеличивает БД; общий lock последовательно выполняет короткие локальные операции.
Неизменяемость гарантируется API, не привилегиями администратора БД. Проверка SHA
обнаруживает повреждение при использовании, но не заменяет резервные копии.
Downgrade с непустой V2 историей запрещён, чтобы не удалить проверенные данные.

## Дальнейшая работа

Immutable findings, связь с существующими runs/import, UI, end-to-end и независимый
holdout. Активация словаря не предоставляет доступ к источнику и не включает сбор.
