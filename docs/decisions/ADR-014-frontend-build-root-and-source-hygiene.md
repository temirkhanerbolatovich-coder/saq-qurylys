# ADR-014: явная граница frontend сборки и только исходники в Git

Status: Accepted · Date: 2026-10-17

## Context

Frontend был загружен54файлами в корень и ZIP с другой версией, .env/credentials,
storage/output. Корневой package-lock изменил автоматически выбранный Next root:
build прошёл, но npm start искал отсутствующий standalone/server.js вместо
standalone/frontend/server.js. Рабочий frontend и backend уже содержали функции,
которые старые загруженные копии не сохраняли.

## Options Considered

1. Заменить весь frontend одним из наборов: теряются функции либо работа другой версии.
2. Оставить дубли и менять только start path: сохраняется неоднозначность сборки.
3. Объединить функции в frontend/, удалить ошибочные uploads из нового дерева,
   явно ограничить build root и проверять структуру исходников в CI.

## Decision

Выбран вариант3. Сохранены обе исходные версии локально, интегрированы их намеренные
визуальные изменения с текущими API/workflows. Next outputFileTracingRoot и
turbopack.root указывают на каталог конфигурации frontend. Регрессия использует
настоящий Next config loader с родительским lockfile; подтверждается build/start.
CI отвергает tracked runtime/private directories, env кроме example, архивы и
плоскую загрузку frontend в корень; содержимое секретов не выводится.

## Reasoning

Это устраняет наблюдавшийся дефект и повторную ошибку размещения, сохраняя
существующую monorepo/Compose структуру без новых dependencies/frameworks.

## Consequences

Исходники хранятся в правильных путях; оба интерфейсных источника учтены, working
data/env не переносятся. Новый history-preserving merge оставляет55remote additions
в прежних коммитах, но исключает их из текущего source tree.

## Risks

Удаление ZIP из нового дерева не удаляет раскрытые значения из истории.
Четыре локальных конфигурационных секрета отличаются от опубликованного ZIP;
чужой runtime не доступен, его владелец должен заменить раскрытые доступы.
Локальная конфигурация/рабочая БД не изменяются ради видимости исправления.
Переписывание общей Git history не выполняется без согласованного действия команды.
CI hygiene — проверка структуры, а не универсальный сканер любых секретов.

## Future Work

Согласованная очистка старого GitHub artifact/history и отзыв раскрытых доступов
владельцем соответствующего runtime; внешняя UX и предметная приёмка отдельно.
