# ADR-013: ограниченное сравнение сохранённых DB-текстов

Статус: принято. Дата:17.10.2026.

## Context

У материалов есть неизменный original_text, оригинальные Assets и отдельные
extraction/ручные расшифровки. Аналитику нужно увидеть различия сохранённых
источников/версий, пока новые внешние доступы и frontend развиваются отдельно.
Сходство текста не устанавливает идентичность объекта или нарушение.

## Options Considered

1. Семантическая модель/новая библиотека diff и автоматические кластеры дублей.
2. Неограниченный character diff синхронно в API.
3. Явный выбор двух сохранённых текстов, stdlib line diff с входными пределами.

## Decision

Вариант3: отдельный read-only session GET в контракте0.13.0-mvp, предел100000
символов/1000строк на сторону, SequenceMatcher с сохранением line endings.
Default — точный DB original_text; анализ/OCR/архив выбираются explicit UUID с
проверкой принадлежности версии и исходного Asset. Нет silent fallback,
нормализации или обрезки. Отсутствие текста отдельно от равенства.

## Reasoning

Решение использует текущую модель и стандартную библиотеку, сохраняет понятный
источник каждого текста. Предельная длина ограничивает квадратичный алгоритм;
отказ413 честнее совпадения обрезанных префиксов. Новые entity/risk решения для
полезного просмотра изменений не нужны.

## Consequences

Можно точно показать строки до/после без записи в БД. Неизвестные даты/URL
остаются неизвестными, SHA относится к выбранному DB-тексту, не к проверенным
байтам файла. Текстовое равенство не превращается в автоматический дубль.

## Risks

Line diff не подсвечивает отдельные символы внутри длинного абзаца. Большой
сохранённый текст может превысить предел сравнения. Без чтения storage нельзя
утверждать текущую целостность/доступность оригинала. Frontend должен выводить
plain text и явно показывать ошибки/границы вместо ложного совпадения.

## Future Work

Подключить UI с explicit version selectors и source provenance; провести
браузерные проверки. Кластеры/семантические изменения и image comparison
проектировать отдельно после появления проверенного набора и реального
пользовательского сценария.
