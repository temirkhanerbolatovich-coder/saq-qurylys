# ADR-024: Управляемое расписание точных открытых URL

Status: Accepted locally. Date:2026-10-19.

## Context

Ручной bounded импорт двух проверенных источников уже работает; следующий прежний
этап — включаемое расписание с историей, квотами и восстановлением. Новый parser-v2
отложен пользователем. Search Threads пока без доступа и не должен запускаться
автоматически; URL-коннектор не использует поисковый профиль.

## Options Considered

1. Внешний scheduler/cron: дополнительный сервис и отдельная координация состояния.
2. Таймер API: несколько процессов и рестарт теряют согласованное состояние.
3. Небольшой due-check в прежнем worker, durable настройки/попытки и прежние jobs.

## Decision / Reasoning

Вариант3 без зависимости/сервиса. PostgreSQL transaction advisory lock сериализует
короткий scheduler tick, row lock защищает настройки. Общий enqueue URL сохраняет
валидацию/дедуп/очередь/audit. HTTP и сохранение материала выполняет прежний
leased IMPORT_URL worker. Настройки создаются OFF, включение отдельной командой
назначает now+interval. Catch-up burst отсутствует. Выключение не отменяет
уже поставленный job: это сохраняет понятную атомарность получения/истории,
не вводит несовместимую отмену AnalysisJob и честно описано пользователю.

Две таблицы: UrlSchedule текущей настройки/состояния и UrlScheduleRun со снимком
на момент попытки. Рабочие переходы/pauses обновляются транзакционно; GET читает
job outcome без записи. Более старая ревизия run не управляет новой настройкой.
Expected revision, UUID command idempotency и auth/CSRF прежние.

## Consequences

Бюджет на source_id межпроцессный, учитывает существующие ручные постановки,
поскольку удерживается та же queue lock. Он ограничивает именно новые
плановые постановки; прежний ручной endpoint и bounded lease retries сохраняют
своё поведение. Не объявлять это глобальным HTTP rate limiter. Три временные
ошибки/постоянная ошибка останавливают расписание до явного включения.

## Risks

Worker должен работать, planned time может сдвигаться; это не SLA. Включение
является разрешением фонового получения от имени аналитика до выключения,
даже после logout. Перед каждой постановкой повторно проверяются роль и source.
Уже поставленный job сохраняет обычные существующие права исполнения.
Пилот ограничен100URL; нет архива/retention/распределённого HTTP quota gateway.
Локальный источник может менять HTML и условия: BLOCKED требует проверки,
расширять transport/URL policy автоматически нельзя.

## Future Work

Поисковое расписание с profile_id+revision только после подтверждённого доступа
к конкретному API; не имитировать привязку профиля к URL. Отдельно нагрузочный
пилот, retention/архив и при необходимости общая квота фактических запросов.
Parser-v2 остаётся DEFERRED до закрытия прежних этапов и свежего gap-analysis.
