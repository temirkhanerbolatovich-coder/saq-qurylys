# ADR-022: История явных поисковых запусков

Status: Accepted locally · Date:2026-10-19

## Context

Существующий Threads preview хранил только process-local последний исход.
После ухода с экрана результат терялся, после restart не было истории попыток.
Новое ТЗ требует источник/время/охват, причины недоступности и повторное чтение.

## Options / Decision

Рассмотрены второй универсальный pipeline, перевод10-секундного preview в jobs
и отдельная таблица намерения/исхода вокруг текущего endpoint. Выбран третий
вариант: одна `monitoring_runs`, существующая маршрутизация/транспорт/квота,
дополнительные read-only catalogue/list/detail. Новый API запуска не требуется.
Для будущего фонового сбора остаются существующие AnalysisJob/worker/leases.

## Reasoning

Запись намерения коммитится до внешнего I/O. Actor+command_key уникальны,
advisory lock сериализует конкурирующие одинаковые ключи. Вторая попытка не
переотправляет внешний запрос даже при незавершённом результате. Terminal
результат фиксируется вместе с audit; whitelist response позволяет открыть его
после ухода со страницы. Сам Advertisement/решения аналитика не создаются.

## Consequences / Risks

Это две транзакции, потому возможен RUNNING без результата при аварии. Он
показывается INTERRUPTED после30с без изменения БД и без автоматического retry.
Сохранённая ошибка не подменяется EMPTY. Raw response хранится только как SHA,
снимок содержит валидированные поля, а не все байты/медиа источника.
Квота пока process-local: этот срез не разрешает запуск нескольких API workers
с независимыми gate. Текущий токен не считается проверенным по старому успеху.

## Future Work

Один разрешённый рекламный источник и явное продвижение материала, общий budget
запросов для scale-out, RU/KZ dictionary, затем расписание. Не добавлять generic
source framework/новый scheduler до доказанной необходимости.
