# ADR-015: ограниченная очистка истории main от раскрытого ZIP

Status: Accepted · Date: 2026-10-17

## Context

При интеграции frontend две загруженные версии ZIP удалены из текущего дерева,
но сохранились в истории. Внутри есть populated .env и credentials.txt.
Подготовлен изолированный candidate с доказанным сохранением приложения;
пользователю показаны изменения восьми SHA и ограничения PR/cache. После вопроса
о применении пользователь поручил «продолжай». Доступа к установке, которой
принадлежали раскрытые пароли, нет; локальная установка использует другие значения.

## Options Considered

1. Оставить исторические ZIP: исходники сохранены, раскрытые конфигурации доступны
   каждому новому обычному clone main.
2. Заменить репозиторий единственным новым коммитом: теряется история разработки.
3. Удалить только архивный путь из истории, сохранить каждый коммит и текущий код,
   опубликовать только main с точным expected-SHA lease.

## Decision

Выбран вариант 3. git-filter-repo 2.47.0 применяется только в отдельном свежем
mirror; пустые после удаления ZIP коммиты, сообщения, author/committer и топология
сохраняются. До применения сохранены приватные bundle и исходные материалы.

Повторная проверка remote подтвердила отсутствие новых main commits, веток,
тегов, открытых PR и forks. Только `refs/heads/main` обновлён
`97d2bff842cabbd0e36417fc897a876d33e21bff` → `6059064572b64571f4e910d4483af167ef99bbdc`
через точный `--force-with-lease`. Mirror push и изменение чужих refs не применялись.
Документация перенесена на очищенную историю cherry-pick, не merge старых родителей.

## Reasoning

Это убирает обе архивные версии из истории, получаемой новым обычным клоном main,
и сохраняет работу фронтенда/бэкенда вместе с историей разработки. Exact-SHA lease
не позволяет незаметно перезаписать новый чужой main. Смена паролей чужой установки
не подменяется ненужным изменением наших рабочих доступов.

## Consequences

Сохранены все 38 коммитов; изменились 8 SHA, подписи четырёх затронутых коммитов
не сохраняются. Все 38 деревьев равны исходным, кроме удалённого ZIP; текущее
дерево до добавления документации побайтово совпадает. Свежий GitHub main clone
подтвердил отсутствие обоих архивных blob и целостность `fsck --full --strict`.
CI очищенной ревизии завершён success по backend/frontend/browser;
точные результаты фиксируются в PROJECT_STATUS.
Разработчикам нужны новые клоны либо контролируемый перенос собственных diff.

## Risks

Старые клоны, приватные backups и read-only PR №1 всё ещё могут содержать архивы;
очистка main не доказывает их удаления. GitHub Support может отказать в очистке
PR/cache, если риск можно закрыть ротацией. Отзыв раскрытых credentials пока
не подтверждён. Старую историю нельзя повторно объединять с main.

## Future Work

Пользователь подтвердил: затронута копия frontend-разработчика, доступа к ней нет.
Владелец должен заменить пароль роли БД/хеш аналитика/private env,
закрыть старые соединения и серверные сессии, проверить отказ старых доступов.
Обработка PR/cache через владельца и GitHub Support остаётся отдельным шагом;
никакие сообщения третьим лицам автоматически не отправляются.
