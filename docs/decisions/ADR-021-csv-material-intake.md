# ADR-021: Предпросмотр CSV и неизменяемые квитанции поступления

Status: Accepted locally · Date: 2026-10-19

## Context

Первый согласованный этап Social Monitor переносит пакетный ручной импорт на сайт.
Ранее импортированные реальные материалы, ID, решения и исходники нужно сохранить.
Открытие вкладки и предпросмотр не должны запускать сбор/анализ или бизнес-решения.

## Options / Decision

Рассмотрены вызовы одиночного создания Advertisement из браузера, отдельная очередь
импортных jobs и ограниченная серверная транзакция. Выбран третий вариант: до100
строк/256КиБ, read-only preview с digest и отдельный commit. Новые таблицы квитанций
и fingerprints дополняют Advertisement/Asset; не создаётся параллельный workflow.

## Reasoning

Браузерный цикл оставлял бы частично импортированный пакет и плохо переживал retry.
Новая очередь не нужна для небольшого локального файла без network/OCR. Общий
advisory lock вместе с unique keys делает конкурентные CSV imports последовательными.
Idempotency-Key возвращает исходный ответ; fingerprint не зависит от имени файла.
REAL/DEMO входят в ключ. Строки исследования не приравниваются к оригиналу поста.

## Consequences / Risks

Старые материалы и решения неизменяемы; изменённое содержимое — новая публикация
с provenance предыдущей версии. Journal — снимок решения об импорте, не текущий
статус проверки материала. CSV всегда сохраняется точными байтами. При ошибке
транзакции возможны файлы без Asset-ссылки; это принятое ограничение существующего
content-addressed storage, не основание удалять пользовательские файлы.

Matching по названию показывает только подсказки. Семантический fuzzy-dedup и
доказательство тождества не входят в этот срез. URL fallback legacy lookup линейный;
строгие ограничения файла удерживают размер одной операции, но не размер архива.

## Future Work

Разрешённый коннектор/источник, история попыток получения и управляемое расписание —
отдельные блоки после проверки доступа. При росте архива — миграция нормализованных
legacy identity keys и измерение latency; при больших файлах — существующая очередь
jobs, а не увеличение HTTP limits без проверки.
