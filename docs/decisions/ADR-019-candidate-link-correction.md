# ADR-019: Отмена ошибочной связи кандидата

Status: Accepted locally · Date: 2026-10-19

## Context

После явной идентификации аналитик может обнаружить, что LINKED указывает на
другую очередь/объект. Нужен исправимый сценарий, сохраняющий прежнее решение
и самостоятельность публикаций/риска. CREATED обозначает происхождение досье.

## Options / Decision

Автоматическая перепривязка с переносом материалов отвергнута: она скрывает два
самостоятельных решения. Выбран явный unlink только для LINKED, затем обычный
link отдельным действием. CREATED не отменяется и не переносится этим сценарием.
Новая миграция не требуется; прежняя пара nullable FK/kind очищается атомарно.

Контракт0.24: POST candidates/{id}/unlink-dossier принимает текущий property_id,
expected_revision кандидата, expected_property_revision досье, reason и строгое
unlink_confirmed=true. Команда проверяет analyst/CSRF/idempotency, блокирует
candidate→property, проверяет обе ревизии и текущую связь. Новая ревизия только
у кандидата. Равенство города/DEMO при снятии не проверяется: изменение метаданных
не должно удерживать ошибочную связь; аналитик просматривает актуальное досье.

## Reasoning / Consequences

Кандидат остаётся с наблюдениями/историей и без текущей связи. Публикации,
сравнения, инциденты, основания, факторы, сигналы и уведомления не изменяются.
Существующие привязки публикаций аналитик проверяет отдельно.
MONITORING_DOSSIER_UNLINKED и PROPERTY_CANDIDATE_UNLINKED записывают причину,
снимки обеих идентичностей/версий, наблюдения, before_property_id и ссылку на
предыдущее link-событие. Транзакция сохраняет связь и аудит либо откатывает всё.
Повтор исходного key/body возвращает исторический ответ, не отменяя более позднюю
связь. Новая команда со старой ревизией получает409, в том числе при возврате
к тому же property_id после промежуточной отмены.

## History / UI

GET candidates/{id}/dossier-history — Page[AuditEventOut] с actor display name,
20 записей по умолчанию, максимум100. Выбираются только candidate-scoped события
CREATED/LINKED/UNLINKED, независимо от текущего FK. Все страницы доступны.
Новые CREATED события получают полный provenance; старые записи не переписываются.
Историческое имя читается из сохранённых details; при отсутствии используется ID.
Property audit уже включает события прежнего досье по property/before_property_id.

Native details раскрывает форму без POST. Причина хранится по пользователю,
сессии, кандидату, текущему property_id и ревизии кандидата. При чужом unlink/relink
форма пересоздаётся и ждёт точного ID досье; старое решение не переносит свой черновик
в новую связь. Checkbox не сохраняется; refresh/reload
требует повторного подтверждения. При409 ввод остаётся. Disabled fieldset
защищает ввод во время команды. После успеха история перезагружается по новой
ревизии кандидата и появляется обычная форма выбора досье. CREATED и viewer
не получают отмену; история остаётся читаемой. Названия audit actions и переход
к кандидату добавлены в существующий PropertyHistory.

## Risks / Future Work

Это исправление LINKED, не merge, редактирование идентичности, удаление досье
или перенос происхождения CREATED. Безопасный перенос ошибочного происхождения
и коррекция самостоятельных решений публикаций/инцидентов остаются отдельными
сценариями. Production/API, нагрузка и независимая предметная приёмка открыты.

## Validation

test_candidate_unlink.py проверяет полный цикл, replay и устаревшие версии,
историю/пагинацию, provenance/имена, CREATED, auth/role/CSRF, concurrency/ABA и
rollback. Browser regressions проверяют draft/reload/409/refresh/viewer/history;
gated live DEMO test — три отдельные UI-команды link→unlink→link.
Фактические результаты текущего запуска — PROJECT_STATUS/UI_AUDIT.
