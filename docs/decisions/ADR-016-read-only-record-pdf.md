# ADR-016: Производные PDF без изменения доказательств

Status: Accepted for local implementation. Date: 2026-10-18.

## Context

Пользователь отдельно разрешил минимальные backend/API изменения для PDF всех
доступных сохранённых материалов. Прежний durable pipeline покрывал сигналы,
а raw download — исходники. TXT/изображения и структурированные решения не имели
единого способа скачивания PDF. Нельзя менять historical snapshots и создавать
видимость нового доказательства при экспорте.

## Options Considered

1. Browser print: не гарантирует скачанный файл и одинаковое содержимое.
2. Новый durable export pipeline/хранилище: добавляет jobs и жизненный цикл без
потребности сохранять каждую рабочую копию.
3. Read-only export поверх существующих DTO, storage и WeasyPrint.

## Decision

Вариант 3: один конечный типизированный GET-контракт, точные байты существующего
PDF или ограниченный renderer производной копии. Исторический сигнал использует
прежний frozen payload, готовый PDF — прежнюю проверку asset/revision.

## Reasoning

Не нужны dependencies, migrations, новые evidence и изменения решения человека.
Источник сохраняется отдельно; дата экспорта и происхождение видимы.

## Consequences

Генерация копии повторяется при скачивании. Общая рекурсивная раскладка сохраняет
поля без молчаливой обрезки; длинные записи могут занимать много страниц.
Исходный HTML представлен текстом; PDF источника не изменяется.

## Risks

Рендер ресурсоёмкий: semaphore, payload/output caps, timeout и Linux process
limits ограничивают нагрузку. Нет external/file URL fetch. Проверка storage
path/SHA/size предшествует включению исходника. Роли используют существующий
общий read scope; отдельный tenant ACL здесь не изобретается.

## Future Work

После пользовательской приёмки можно адаптировать конкретные отчёты по частоте
использования и добавить очередь при доказанной нагрузке. Новые доступы/источники
и сохранение экспорта как evidence потребуют отдельного решения.
