# PDF сохранённых материалов

Локальная реализация по дополнению пользователя U18.10.2026. Контракт
`0.14.0-mvp`, `GET /api/v1/exports/{kind}/{id}/pdf`. Это чтение доступной записи,
а не принятие доказательства, решение аналитика или сохранение нового снимка.

| Материал | kind | Содержание |
|---|---|---|
| Исходник TXT/HTML/PNG/JPEG/PDF | assets | Точные PDF-байты либо явно производная копия текста/изображения |
| Доказательство | evidence | Сохранённые сведения, объект, источник и его содержимое |
| Проверка документа | legal-bases | Реквизиты, применимость, фактическое решение и источник |
| Решение по фактору | risk-factors | Статус, версия, причина, связанные источники |
| Публикация | advertisements | Оригинальный текст, даты, статус и сохранённые исходники |
| Результат AI/OCR | extractions | Выбранная версия анализа, гипотезы и отдельные решения |
| Досье | properties | Текущее серверное состояние, основания, факторы и происхождение |
| Сигнал | signals | Сохранённый PDF выбранной ревизии либо копия её frozen payload |
| Сверка / кандидат / инцидент | comparisons / candidates / incidents | Сохранённые результаты и ограничения предварительного вывода |
| DEMO-версия реестра | registry-snapshots | Неизменяемая версия, охват, записи, SHA-256 |
| Открытый PDF КЖК | open-registry | Точный исходный файл; прежняя ссылка скачивания также сохранена |
| История решения | audit | Событие, сотрудник, дата, причина, before/after |
| Сравнение публикаций | publication-comparison | Выбранная пара и версии текста, provenance и ограничения |

Для сравнения обязательный `right_id`; необязательные `left_extraction_id` и
`right_extraction_id` имеют прежний смысл выбранных версий. Нет автоматического
перехода с оригинала на OCR. Экспорт не запускает сбор данных или анализ.

Кнопки расположены у соответствующего документа/записи; отчёт объекта — во вкладке
«Сигналы и отчёты». Оригиналы доступны отдельно. Скачивание проверяет MIME и
PDF-заголовок, показывает подготовку, ошибку и повтор; не открывает print dialog.
Наличие ID не гарантирует физическую доступность файла: отказ проверки SHA-256,
размера или пути возвращает 409, без фиктивного успешного файла.

Доступ: действующая session cookie; analyst/viewer читают тот же общий реестр,
что и существующие read endpoints. В проекте нет tenant/object-owner ACL;
экспорт не вводит обход существующих прав. Неизвестный ID — 404, вид/UUID — 422.
Нет изменения ролей, auth, risk, snapshots, audit или idempotency.

Производные PDF используют имеющийся WeasyPrint в Linux Docker, DejaVu и A4.
Дата формирования отделена от дат источника. DEMO и ограничения сохраняются.
HTML источника превращается в экранированный текст; script/style не исполняются.
Renderer принимает только явно переданные проверенные PNG/JPEG data URI, не
читает file URLs и сеть. Для PDF-оригинала преобразование не выполняется.
Копия HTML передаёт текст, а не исходную браузерную вёрстку; оригинал остаётся.

Ограничения: два одновременных render-процесса на API process, payload ≤20 MiB,
deadline ≤12 секунд, Linux CPU/address-space limits, результат ≤max_upload_bytes.
503 при занятости/таймауте/недоступном runtime, 413 при превышении размера, 415
для неподдерживаемого исходника. Длинный архив не обрезается молча: предлагается
скачать оригиналы отдельно. Native Windows не заменяет Linux renderer.

Исторический signal берёт только `pdf_payload(signal)`; актуальное досье не
пересчитывается. Готовый сохранённый PDF обязан пройти прежнюю проверку связи
asset с signal/revision. Экспорт копии не создаёт durable job/PDF asset.

Проверки: `backend/tests/test_document_exports.py`, контракт, browser download
и сценарии вкладок в `frontend/tests/dossier-*.spec.ts`. Реальные Linux-файлы,
визуальная проверка и текущие результаты — в UI_AUDIT и PROJECT_STATUS.
Юридическая/пользовательская приёмка не выводится из количества тестов.
