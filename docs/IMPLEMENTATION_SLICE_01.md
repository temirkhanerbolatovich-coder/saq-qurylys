# Первый вертикальный срез SAQ QURYLYS

Исторический checkpoint первого среза. Актуальный этап — [срез 02](IMPLEMENTATION_SLICE_02.md): добавлены OCR/worker/review и лимит chunked-body. Приведённые ниже 23/4 проверки относятся к первому этапу.

Реализуется после разрешения пользователя 14.10.2026. Это начальный работающий срез, не полный P0.

## Поведение

- Серверная сессия аналитика: login/logout/me, HttpOnly SameSite cookie, подписанный CSRF с привязкой к сессии, проверка Origin, hash пароля, ограничение попыток входа. Роль viewer читает, analyst добавляет материалы. Идентичность не принимается из тела команды.
- PostgreSQL и Alembic: пользователи/сессии, застройщики, объекты, публикации/материалы, DEMO-доказательства/основания/факторы, аудит, идемпотентные команды.
- Аддитивный seed: 8 вымышленных объектов и 12 публикаций. Повтор seed не сбрасывает пользовательские записи и не меняет уже существующие данные. Все учебные решения, включая фиктивную гарантию и отсутствие основания, явно DEMO. Демоавтор — синтетическая identity с неизвестным случайным паролем.
- Обзор, реестр с поиском по имени/адресу, фильтры по зоне/основанию, карточка с исходниками доказательств, лента/карточка публикации, форма нового текста. Фильтры в URL, черновик формы в sessionStorage текущей вкладки.
- Новый текст сохраняется без изменения символов и переносов, с источником, nullable published_at, отдельным captured_at и UTF-8 файлом с SHA-256. Ссылка сохраняется как метаданные, не скачивается. Повтор одной команды возвращает тот же результат; другой payload с тем же ключом даёт 409. PostgreSQL advisory transaction lock защищает и от одновременных повторов.
- Аудит добавления содержит серверного автора, время, entity/request ID. Сессии и данные сохраняются после рестарта API. Пересчёт риска использует только подтверждённые коды из БД; новое необработанное объявление не создаёт факторы.

## Контракт

Базовый контракт принят к реализации; `x-implementation-status` различает 13 реализованных операций и 22 планируемые. Их наличие в проектном OpenAPI не означает, что они работают. Актуальные маршруты первого среза перечисляет `/openapi.json` backend (внутренний порт API). Контрактные тесты проверяют реальные ответы, а также отсутствие незаявленных operationId.

`as_of` в GET property risk пока не поддерживается: явная 400, без подмены исторической оценки текущей. Начальные записи факторов имеют один текущий статус; история ручного пересмотра появится вместе с review. Формула и веса не изменены.

## Запуск

Основной рецепт — в README. Настройки генерируются `scripts/configure_local.py` один раз, существующий `.env` сохраняется. Локальные credentials — `.local/credentials.txt`, файл игнорируется Git. Для тестов не снимать DOM/trace с заполненным паролем; browser-тесты получают сессию через API. Пароль в ошибках не выводится.

Docker: отдельный проект `saq-qurylys`; PostgreSQL в именованном volume, исходные тексты в `./storage` bind mount. Host API и контейнер видят одни и те же файлы при использовании одной БД. Без dev override наружу открыт только frontend на 127.0.0.1. При локальном запуске API — 127.0.0.1:8000; PostgreSQL через dev override — 127.0.0.1:55432.

Секреты, .venv, node_modules, storage, browser-результаты и локальные журналы не коммитятся. Команда `docker compose down` сохраняет БД; `down -v` удаляет данные и не входит в обычный сценарий. Unrelated контейнеры не запускать и не останавливать.

## Технические решения и ограничения

Для первого среза ORM нормализует основные сущности. Неизменяемые DEMO-снимки evidence/legal_bases временно хранятся как структурированный JSON с типизированным read DTO; typed write DTO, ограничения подтверждения и история появятся в review-срезе. Это не универсальный JSON CRUD.

Frontend — Next.js 16.4.0/React 19.3.1, TypeScript 6.0.3 и Tailwind 4.3.3. Локальный Button использует композицию Slot/CVA; компоненты shadcn CLI не генерировались. TypeScript 7 не использован из-за несовместимости текущего typescript-eslint; ESLint проверяет core+TypeScript без eslint-config-next, чья цепочка содержала уязвимый braces. Lock-файл фиксирует итоговый набор. Декоративные изображения, внешние шрифты и тайлы не нужны первому срезу.

Пока отсутствуют: worker/jobs, OCR, upload изображений, разрешённый collector, extraction/matching, ручной review факторов/документов, полноценные signal snapshots/решения/PDF, карта, родительская агрегация очередей, поиск БИН, историческая оценка, полный RU/KZ UI. Пункты меню будущих модулей ведут на честные пояснения, без mock-успеха и фиктивных счётчиков выполненной проверки.

Сессии и login throttling рассчитаны на локальный однопроцессный MVP; distributed rate limiting, retention очистки sessions/commands, SSO, усиленный аудит и промышленная эксплуатация ещё не реализованы. Текущий порог размера HTTP-запроса проверяет Content-Length; до файлового импорта необходим также потоковый лимит на прокси/API для chunked-запросов. Файлы создаются до транзакции БД, поэтому при неуспешной записи возможен неиспользуемый content-hash файл; он не выдаётся без записи asset. Очистка таких файлов — отдельная эксплуатационная задача.

## Проверки

Backend-тесты используют отдельную случайную PostgreSQL schema `test_<uuid>` в SAQ-БД, выполняют реальные миграции и удаляют только собственную schema. Public schema и пользовательские записи не сбрасываются. Проверяются A/B/C, отсутствие ложного R1, уникальность факторов, отрицание/пересчёт статуса на scorer, auth/CSRF/роль, nullable дата, точность исходника, idempotency/concurrency, аудит, новое app instance и OpenAPI.

Playwright: анонимный вход, authenticated API/dashboard, фильтр и доказательство, новый текст/черновик/перезагрузка, mobile overflow. Авторизация тестов через API не является тестом всех интерактивных ошибок формы login. Результаты и точные ограничения выполнения фиксируются в PROJECT_STATUS.md. Наличие workflow не означает выполненный GitHub CI; удалённого репозитория пока нет.
