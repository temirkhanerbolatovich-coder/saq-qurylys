# Карта объектов

Реализовано 15.10.2026. `/properties?view=map` открывает карту и тот же список; ссылка есть в обзоре. Карта помогает выбрать очередь/корпус, а правовые решения остаются в карточке объекта. Зелёная зона не подтверждает безопасность.

## Данные и поведение

- Один authenticated `GET /api/v1/properties` снабжает список и карту. Поиск, зона, правовой статус и страница хранятся в URL. `view` используется только UI; переключение вида сохраняет фильтры/страницу.
- Метки показывают готовые серверные баллы/зоны. Выбор открывает компактную карточку с подтверждёнными кодами и ссылкой на полную карточку. Клиент не рассчитывает риск.
- Карта показывает только текущую страницу, по умолчанию 25 объектов, максимум API 100. Подпись явно указывает охват; «Предыдущая/Следующая» доступны и для списка. Смена фильтра сбрасывает страницу и старые метки/выбор; ошибка API не показывает прежнюю выборку под новыми фильтрами.
- Координаты уже существовали в модели, DTO и DEMO-seed. UI принимает конечные числа с longitude в пределах ±180 и latitude ±85.05112878 (предел Web Mercator). Null, неполная пара и непригодные значения не превращаются в точку 0/0; объект остаётся в таблице. При отсутствии пригодных точек карта не запрашивает тайлы.
- DEMO-координаты условные, не привязаны к реальным строительным проектам. Ручного редактирования координат и геокодирования пока нет.

## Реализация и отказы

`frontend/components/property-map.tsx` загружает Leaflet 1.9.4 только в браузере при открытии карты. Используется один XYZ raster-провайдер, без React Leaflet, GIS-сервера и новой API-операции. Это реализация принятого [ADR-001](decisions/ADR-001-mvp-baseline.md), нового архитектурного решения нет. [Официальный API Leaflet](https://leafletjs.com/reference.html) проверен при реализации.

Ошибка тайла либо загрузка дольше 12 секунд показывает предупреждение; метки и таблица остаются доступны. «Повторить карту» пересоздаёт слой; предупреждение сохраняется до явной повторной попытки. Ошибка загрузки JS также оставляет список. При отказе API доступна повторная загрузка данных. Отсутствие данных/сети не меняет правовые статусы или риск.

Метки доступны через Tab, Enter и пробел; после выбора фокус переходит на карточку. Стрелки и +/- управляют картой, колесо прокручивает страницу. Есть обход карты ссылкой «Перейти к списку объектов». На узкой ширине карточка располагается под картой; таблица сохраняет собственную горизонтальную прокрутку. Это не полная приёмка со screen reader или пользователями.

## Провайдер и конфигурация

По умолчанию используется `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, видимая атрибуция ведёт на OSM copyright. Подключение соответствует обычному просмотру: нет bulk download, offline tile pack, собственного cache bypass, proxy или предзагрузки областей. Условия проверены по [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) 15.10.2026; сервис не даёт SLA и может ограничивать доступ.

Браузер обращается к провайдеру напрямую: тот видит IP, User-Agent/Referer и номера тайлов области просмотра. Бизнес-поля/факторы в URL тайла не добавляются. Не размещайте секреты в этих **публичных build-time** значениях:

| Переменная | Значение по умолчанию / поведение |
|---|---|
| `NEXT_PUBLIC_MAP_TILE_URL` | OSM XYZ URL выше; пустое/отсутствующее значение использует default, `disabled` отключает карту |
| `NEXT_PUBLIC_MAP_ATTRIBUTION` | `OpenStreetMap contributors`, обычный текст, без HTML |
| `NEXT_PUBLIC_MAP_ATTRIBUTION_URL` | `https://www.openstreetmap.org/copyright` |

URL тайлов должен быть HTTPS с `{z}`, `{x}`, `{y}` без иных placeholders, user/password и fragment; ссылка атрибуции — HTTPS, текст непустой. Неверная конфигурация отключает карту, список доступен. Провайдер должен поддерживать используемые XYZ zoom 2–19. Его условия/лимиты проверяются отдельно.

В Compose значения читаются из корневого `.env` как build args. После изменения: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build --no-deps frontend` (если dev override не используется, убрать оба `-f`). Runtime env уже собранный JS не меняет. Для host `npm run dev/build` задайте переменные в shell либо `frontend/.env.local` (игнорируется Git); корневой `.env` Next.js сам не читает. Прежние плановые `MAP_TILE_URL/MAP_ATTRIBUTION` не использовались и заменены публичными именами.
