# Источники и история запусков Social Monitor

## Управляемое расписание открытых URL ·19.10.2026

В «Источниках» отдельно доступно [расписание подключённых страниц](FEATURE_URL_SCHEDULES.md).
Создание OFF, явное включение, source admission budget/backoff и собственная
история рядом с настройкой. Вкладка «Запуски» по-прежнему показывает сохранённые
Threads preview; не смешивать поисковую выдачу с сохранёнными материалами URL.
Установлено и проверено согласно PROJECT_STATUS. Указания ниже об отсутствии
scheduler относятся к прежнему срезу Threads; поисковое расписание остаётся OPEN.

## Параметры поиска ·19.10.2026

Внутри существующего инструмента Threads доступны сохранённые профили
помощника1.0, с выбором неизменяемой версии и явным применением параметров.
Это не новый источник/Run, сохранение не меняет Threads status и не выполняет
поиск. Детали — [FEATURE_QUERY_PROFILES](FEATURE_QUERY_PROFILES.md).

Срез от19.10.2026 расширяет существующую «Сверку». Каталог находится в
`/monitoring?section=sources`, история — `/monitoring?section=runs`.
Прежние CSV, страницы КЖК и Threads controls остаются в своих mounted панелях.

## Возможности

Каталог из пяти методов показывает текущие настройки и фактические границы:

| Метод | Что действительно выполняется |
|---|---|
| CSV | Ручной файл, preview/commit; отдельный журнал квитанций |
| Threads | Явный ограниченный keyword preview, если включён и настроен доступ |
| Открытые страницы AN GROUPS / Primeminister.kz | Явный импорт коммерческой страницы `/payment` либо проверенной информационной статьи через job queue; HTML/SHA и текст |
| PDF КЖК | Ручная загрузка/поиск в предоставленном документе |
| Другие социальные площадки | Автоматический коннектор отсутствует; доступны ручные материалы |

READY означает готовность метода к ручному действию. Оно не является live health
проверкой внешнего сайта. Каталог/раскрытие инструмента/история используют только
GET и не обращаются к внешним источникам. Применимость правового документа,
тождество ЖК, факторы и сигнал сохраняют самостоятельные подтверждения.

Код `LICENSED_NEWS` сохранён для совместимости, method=`PUBLIC_PAGE_URL`,
access_status=`REVIEWED_PUBLIC_PAGES`, coverage=`EXACT_REVIEWED_URL_ONLY`.
Это не обещание лицензии для AN GROUPS: CC BY относится к Primeminister.
Последняя попытка/успех используют существующие IMPORT_URL jobs обоих источников;
журнал Runs по-прежнему показывает именно Threads. Границы AN GROUPS, selectors
и неизвестная дата/ЖК — [FEATURE_URL_IMPORT](FEATURE_URL_IMPORT.md).

## Запуск и история Threads

Существующий POST `/api/v1/monitoring/threads/search` теперь сохраняет попытку
до внешнего обращения. Параметры/лимиты/защита транспорта прежние. В успешном
ответе дополнительно возвращается `run_id`. UI передаёт Idempotency-Key;
для старых клиентов заголовок остаётся необязательным (без него каждая команда
создаёт новую попытку). Невалидный запрос/чужая роль/CSRF не создают запуск.

В таблице `monitoring_runs`: источник, автор UUID, query/порядок/лимит,
начало/завершение/deadline, ключ/хеш запроса, состояние, безопасный код ошибки,
HTTP status и валидированный ответ API. В audit пишутся начало/завершение.
Секрет, служебные paging URLs, upstream exception и HTTP headers не сохраняются.
Текст публикации выводится как текст; ссылки проходят существующий whitelist.

| Состояние | Значение |
|---|---|
| RUNNING | Зафиксирован запуск, ожидается исход |
| SUCCEEDED | Получен непустой валидный ответ |
| EMPTY | Валидный ответ без публикаций, не доказательство отсутствия рекламы |
| BLOCKED | Метод отключён или доступ не настроен |
| RATE_LIMITED | Локальная пауза/занятый поиск либо лимит площадки |
| ERROR | Безопасный код ошибки получения/проверки |
| INTERRUPTED | Запуск не завершён за30с; исход неизвестен, GET не меняет БД |

Только один ответ, до50 записей, без получения следующей страницы/медиа. Raw API
response не архивируется: SHA относится к исходным байтам, в истории сохранён
валидированный whitelist snapshot. Это результат поискового API, не снимок
оригинальной страницы и не проверенное рекламное нарушение.

Повтор ключа и тела возвращает сохранённый результат либо сохранённую ошибку;
не вызывает источник ещё раз. Другой body с тем же ключом →409. Повтор RUNNING,
включая INTERRUPTED, →409, без resubmission. В UI ключ сохраняется при сетевой
неопределённости/500; новый успешный поиск или явная попытка после известной
ошибки получает новый ключ. После полной перезагрузки используйте историю;
автоматического восстановления POST нет.

Сохранённый terminal исход не заменяется, если подтверждение commit потеряно.
Ошибку записи после внешнего запроса нельзя считать нулевым результатом: остаётся
исходная запись намерения, которая становится INTERRUPTED в read-only представлении.
Синхронный preview ограничен10с; новый worker/scheduler не добавлен. Gate квот
по-прежнему один на API process; горизонтальное масштабирование требует общей
квоты/lease прежде включения нескольких API workers. История сохраняется при
перезапуске, но старый успех не сертифицирует текущий токен.

## API и UX

- GET `/api/v1/monitoring/sources` — catalogue, настройки, текущий gate, предыдущий
  успех и последняя попытка Threads; актуальные CSV/URL даты из существующих записей.
- GET `/api/v1/monitoring/runs` — page/page_size/source_code/state; сначала новые,
  стабильный ID при одинаковом времени. Список не содержит тексты ответов.
- GET `/api/v1/monitoring/runs/{id}` — metadata и snapshot результата, если получен.

Чтение доступно analyst/viewer, запуск только analyst с CSRF/Origin.
`run_id`, `run_state`, `run_page`, `run_source` живут в URL. Изменение фильтра
сбрасывает страницу и run_id; прочие параметры/выбранные IDs сохраняются.
Старая страница не выдаётся за новый фильтр во время loading/error. GET retry,
Back/reload, keyboard scroll и mounted черновик Threads сохраняют общий workflow.
Новые каталог/история имеют RU/KZ; длинные старые инструкции Threads остаются
отдельной задачей редакторского перевода.

CSV-квитанции и IMPORT_URL jobs сохраняют свои механизмы; в новый журнал они
не копируются и не превращаются в поисковые запуски. История до установки
этого среза не восстанавливается задним числом. Нет фонового опроса, расписания,
нового поиска Instagram/TikTok, продвижения поста в Advertisement или автоскоринга.
