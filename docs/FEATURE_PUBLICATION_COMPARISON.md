# Сравнение сохранённых публикаций и версий текста

17.10.2026. Контракт **0.13.0-mvp**, read-only
`GET /api/v1/advertisements/compare`. Первый backend-срез сравнивает два явно
выбранных DB-текста и сохраняет контекст источников. Frontend `/comparison`
подключён отдельным срезом ниже. Это не автоматическая группировка дублей, не установление идентичности
ЖК и не вывод об изменении юридического статуса.

## Запрос и выбор текста

В интерфейсе: «Проверка» → «Сравнение публикаций». Выберите две стороны из
сохранённых материалов с серверной пагинацией, затем для каждой стороны явно
выберите оригинал или конкретную версию OCR/расшифровки. Можно сравнить две версии
одного материала. Выбор сторон, extraction IDs и страница каталога сохраняются
в URL и переживают reload/Back. Быстрый повторный выбор блокируется на время
перехода URL, чтобы не терять первую сторону. После выбора интерфейс выполняет
только GET, не запускает анализ и не принимает решений.

Показываются точный line diff, полные тексты, даты, версии, SHA и исходные файлы.
Отсутствие текста не подменяется совпадением, 404/422/413 сохраняют возможность
исправить выбор. Длинные значения переносятся, широкая таблица прокручивается
внутри области. HTML остаётся текстом; небезопасные URL-схемы не становятся ссылками.

`publication-comparison.spec.ts` проверяет presentation состояния и ширины;
`zz-publication-comparison-live.spec.ts` проверяет реальный API/worker/UI на
одноразовом loopback стенде с `SAQ_ISOLATED_ACCEPTANCE=1`. Результаты — PROJECT_STATUS.

Обязательны `left_id`, `right_id` — UUID сохранённых Advertisement. Оба материала
должны относиться к одному режиму DEMO/REAL. Авторизация session, analyst/viewer.
Сетевых запросов к источникам нет.

По умолчанию сравнивается **точный original_text**. Параметры
`left_extraction_id`, `right_extraction_id` явно выбирают analysis_text нужной
extraction соответствующей стороны, в том числе архивной. Один и тот же
материал можно выбрать с двух сторон для сравнения его версий. Принадлежность
версии и её source_asset проверяется. Чужая/несуществующая версия возвращает422,
несуществующая публикация404. По отсутствующей версии нет fallback на последнюю.

У изображения original_text может быть пустым. Сохранённый OCR или расшифровка
не подставляются автоматически: для них нужно выбрать extraction_id. Исправления
отдельных гипотез не переписывают analysis_text; сравнивается выбранный текст,
а не подстановка всех reviewed_value. Для сравнения исправленной расшифровки
нужна её отдельная дочерняя extraction.

## Ответ и смысл результата

Каждая сторона содержит advertisement_id/revision, источник/URL, отдельно
published_at и captured_at, DEMO, text_basis ORIGINAL/EXTRACTION, идентификатор,
revision, pipeline_version и время выбранного анализа, точный text, text_sha256,
source_asset_id и metadata связанных оригинальных TEXT/HTML/IMAGE Assets.
Отсутствующая дата остаётся null; направление left→right задаёт пользователь,
оно не доказывает временную последовательность публикаций.

`text_sha256` вычислен по UTF-8 **выбранного DB-текста**. Это не хеш изображения
или HTML и не повторная проверка существования/целостности файла в storage.
Для ORIGINAL source_asset_id назначается только TEXT-asset с тем же сохранённым
SHA; если такого нет, поле null. Для EXTRACTION используется её проверенный
source_asset_id. Metadata оригиналов не подтверждает текущую доступность файла.
Скачать/проверить исходник можно существующим authenticated Asset-сценарием.

| status | Значение |
|---|---|
| IDENTICAL_TEXT | Два доступных выбранных текста совпадают символ в символ |
| DIFFERENT_TEXT | Доступные выбранные тексты различаются |
| TEXT_UNAVAILABLE | Хотя бы одна сторона отсутствует, пуста или содержит только whitespace; changes пуст |

Нет normalize/casefold/обрезки текста: RU/KZ-буквы, emoji, пробелы, LF/CRLF и
последний перенос строки существенны. `.strip()` используется только для
определения наличия непустого содержимого, а не для сравнения.

`same_advertisement` сообщает равенство сохранённых UUID. `same_source_url`
сравнивает два известных URL буквально; если хотя бы один неизвестен, значение
null. Равенство текста или URL не доказывает дубль, перепост, авторство или
связь версий. Числового confidence/процента идентичности объекта нет.

`changes` содержит REPLACE/INSERT/DELETE с точными left_text/right_text и
left_start_line/left_end_line/right_start_line/right_end_line. Индексы строк
**с нуля, конец не включён**. Строки выделены `splitlines(keepends=True)`, поэтому
блоки сохраняют окончания строк. Неизменённые блоки не возвращаются; полные
тексты сторон позволяют восстановить весь контекст. Это line diff, без
автоматического толкования «платёж исчез/нарушение подтверждено».

## Пределы и отказ

Каждый выбранный текст ограничен100000Unicode-символов и1000строк. Превышение
даёт413 **до** сравнения, даже для одинаковых текстов; источник не обрезается.
SequenceMatcher stdlib работает по ограниченному списку строк с autojunk=False,
чтобы не терять повторяющиеся строки. Новых зависимостей/процессов/миграций нет.
Стоимость может быть квадратичной по числу строк, поэтому лимит нельзя снимать
без отдельного измерения/нового bounded исполнения.

Указанные пределы ограничивают выбранные тексты и diff, но не число связанных
Assets: metadata оригиналов читается из всей истории двух материалов. Для
большого числа связанных файлов нужна отдельная нагрузочная проверка и
пагинация metadata; текущая функция не заявляет жёсткий предел всего ответа.

Выдача не рендерит HTML; frontend должен отображать блоки как обычный текст,
не через innerHTML. Ошибку422/413/404 нужно показывать явно, не выдавать пустые
changes за совпадение. Отдельное подключение UI должно сохранить версии,
маркировку DEMO, неизвестные даты и переход к оригиналу.

GET не меняет Advertisement/Extraction revisions, привязки, риск, очередь,
signals/PDF, Telegram или audit. Параллельная команда может изменить metadata
review между чтениями; этот ответ не подтверждает историческое бизнес-решение.

## Проверки и дальнейшая работа

Из backend:

```powershell
../.venv/Scripts/python.exe -X utf8 -m pytest -q -rs tests/test_publication_comparison.py tests/test_review_queue.py tests/test_contract.py
```

Проверяются exact Unicode/newline diff с восстановлением правого текста,
явные исторические версии, отсутствие OCR fallback, границы, права,
DEMO/REAL, текущие маршруты и отсутствие записей от GET. Результаты —
[PROJECT_STATUS](../PROJECT_STATUS.md), решение — [ADR-013](decisions/ADR-013-bounded-saved-text-comparison.md).

Автоматические кластеры репостов, общая история источника, семантическая
классификация изменений, сравнение изображений/видео/PDF-страниц, проверка
исчезновения на площадке остаются отдельными функциями.
