# SAQ QURYLYS — UX-рекомендации

## Стабилизация поиска, риска и версии реестра ·18.10

- q и точный city в реестре накапливаются вместе, применяются через350ms после
  последнего изменения либо сразу Enter; сбрасывается page, сохраняется view.
  Reset очищает оба draft/URL и фокусирует поиск. Back/reload восстанавливают URL.
- Мобильный глобальный поиск открывается отдельной кнопкой с focus, Escape
  сохраняет draft и закрывает форму; Enter ведёт в реестр с encoded q. Это поиск
  объекта, не отдельный поиск по всем сущностям проекта.
- GREEN рядом с UNKNOWN/PENDING/REJECTED имеет явную подпись статуса основания;
  она не меняет score и не сообщает, что объект безопасен. Понятность проверить
  с сотрудниками, не выводить из прохождения browser tests.
- В сверке версия выбирается по label/городу/дате из списка со страницами10;
  описание выбранной версии/ID сохраняется вне текущей страницы и при retry.
  Выбор не запускает compare. «Без версии» остаётся допустимым исходом;
  REAL+DEMO запрет прежний. Manual UUID в details без придуманного описания.
  Полный reload сбрасывает выбранную версию и несохранённое основание сверки;
  это ограничение текущего мониторинга, не обещание durable draft.

## Поиск сигналов по всему набору · локальный блок18.10

Поиск очереди запускается Enter/кнопкой по текущему и frozen имени, ID, метке
версии и статусу. q≤300 сохраняется в URL, при submit page сбрасывается, текущий
signal_id фиксируется; pagination его сохраняет. Reload/Back восстанавливают
q/page. Ввод без submit не меняет результаты; фильтры применяются вместе с q.
Empty/error/pending не скрывают открытый historical snapshot. Сброс очищает весь
query/selection и фокусирует selector объекта, как прежде. Global total относится
ко всем совпадениям; counts DRAFT/stale остаются только текущей страницы.
Literal substring не подтверждает идентичность или правовое основание.

## Глобальный рабочий приоритет · локальный блок18.10

Список обзора выбирается сервером из всего доступного набора до pagination:
PENDING → UNKNOWN/REJECTED → остальные; внутри отсутствие даты → более давняя
last_reviewed_at → больший server score → ID. Браузер не пересортировывает ответ.
Это очередь проверки, не вывод о нарушении и не дедлайн; UNKNOWN не становится R1.
Подробный вид показывает5, краткий3. total относится ко всему набору. Ошибка
списка явно отличается от empty и не блокирует другие рабочие очереди.
Обычный порядок реестра/выбора объекта без order остаётся name/ID.
На mobile пояснение следующего действия занимает полную ширину строки, а балл
и ссылка на досье расположены выше; текст не сжимается между двумя controls.

## Реальные отношения объектов · локальный блок18.10

Родители/дети/соседи следуют только parent_id, уровень — сохранённому level.
Названия и общий застройщик не создают связи. В раскрытии прямо указано, что
документы/правовой статус/риск проверяются отдельно. Отсутствие родителя/детей
показано как отсутствие сохранённых сведений; ошибка имеет отдельное сообщение
и retry. Корневые объекты не объединяются в одну фиктивную семью.
Связанные досье открываются в «Обзоре» с прежним registry context; Back/Forward
сохраняют обычную историю. Пагинация детей/соседей независима, локальна досье и
сбрасывается после reload; загрузка страницы не меняет выбранный объект/решения.

## Расширенный поиск и объекты сигналов · локальный блок18.10

Существующий q в properties/dashboard ищет подстроку без учёта регистра по имени,
адресу, отдельному альтернативному названию, застройщику и БИН. Внешние пробелы
удаляются; пустой q не ограничивает выборку. БИН допускает полный или частичный
ввод; поиск не проверяет его подлинность. %, _ и backslash ищутся буквально.
Нет fuzzy/транслитерации/автоматического подтверждения совпадения.
Город остаётся точным; глобальная пользовательская сортировка не добавлена.

Объект сигнала выбирается общим PropertyPicker по всему разрешённому реестру,
страницы25. Фильтр читает DEMO и REAL; match picker по-прежнему ограничен
категорией материала. Поиск запускается кнопкой/Enter, pagination возвращает
фокус к select. Пустой/ошибочный результат не стирает выбранный ID; он остаётся
в URL property_id и восстанавливается после reload/Back. Текст поиска picker
локален странице и после reload сбрасывается. «Все объекты» очищает фильтр.

Дополнительные имена объектов текущей страницы сигналов читаются по ID, если их
нет в initial100. До получения имени показывается ID, ошибка имеет явный retry;
ошибка названия не выдаётся за пустую очередь. Поиск *самих сигналов* всё ещё
локален загруженной странице25; это отдельное ограничение UX-06.

## Первый блок по аудиту18.10 · локальные исправления

Реестр показывает рабочие фильтры и список/карту в обоих режимах. Query/page/view,
контекст возврата и прежние серверные пределы сохраняются. Поиск по-прежнему
name/address, город точный; глобальная сортировка не имитируется.

При выбранном материале «Сменить материал · очередь и фильтры» закрыта по умолчанию.
Открытие/закрытие не размонтирует содержимое и не отправляет решений. Переход к
другому материалу закрывает очередь, а форма самого материала остаётся вне неё.
Это одинаковое поведение для processing и remaining-actions очередей.

Сверка явно открывает источники/версии и раскрывает соответствующий инструмент
после commit выбранной вкладки. Выбор DEMO-версии возвращает к существующему
кандидату с сохранением ввода. UUID-ввод пока сохранён: полноценный chooser и
reload выбранной версии этим блоком не заявляются.

В материале основная ссылка анализа находится в statusbar. Исходный PDF
обозначается по имеющемуся mime_type; для других типов/старого DTO — PDF-копия,
с пояснением и отдельным оригиналом. В сигнале скачивание копии без сохранения
отделено от формирования архивного PDF. Риски, роли и снимки не меняются.

## Вкладки вместо последовательности секций · U18.10.2026

Текущая локальная структура заменяет прежние anchors досье/мониторинга,
описанные ниже в истории. Обзор открывается по умолчанию. Глобальные пять зон
отделены от локальных tabs; действия PDF/решения находятся у записи.
«Публикации» выбраны вместо пустого объектного «Мониторинга»: существующий
monitoring candidate не имеет подтверждённого property_id. Связь не выдумывается.

`?section=` открывает ровно одну mounted панель, reload/Back/Forward сохраняют
раздел. Next-integrated History API обновляет URL синхронно, без scroll к якорю.
ArrowLeft/Right, Home/End управляют roving tab focus; Enter/Space — native button.
Tab ведёт к панели. Legacy hash открывает нужный tab, раскрывает редактор и
переносит фокус после commit; #dossier-document-UUID сбрасывает конфликтующий
фильтр и открывает страницу документа. Skip link сохранён.

Документы: поиск по номеру/издателю/области, статус и страницы по10. Это весь
полученный список legal_bases конкретного объекта, не имитация глобального server
sort. Невидимые формы документов остаются mounted. Публикации/сигналы объекта
читаются через существующие серверные pages по10; история также paged.
Скрытые панели могут выполнять GET; переключение не запускает бизнес-команд.

Неизвестность, pending, отсутствие подтверждённых факторов и установленное
отсутствие основания остаются разными состояниями. DEMO и краткое юридическое
ограничение остаются у состояния. Справка о сроке черновика проверки раскрывается
по запросу; предупреждение о восстановлении/повторном выборе файла не скрывается.
Контекстные ссылки на оригинал/фрагмент внутри единого сценария анализа сохраняют
назначение; они не выдаются за вкладки карточки и не заменяют новый tablist.

PDF источника и [производный экспорт](FEATURE_RECORD_PDF.md) различаются;
экспорт не принимает гипотезу/фактор/сигнал и не меняет historical snapshot.
Отсутствующий/повреждённый исходник даёт ошибку, а не фиктивный PDF успеха.
Результаты тестов не заменяют приёмку обычным сотрудником.

## Локальная доработка после аудита · 18.10.2026

Документы основания показаны native details. В закрытой строке видны номер,
дата, механизм, статус, область и период; источник, доказательства и решения
раскрываются вместе. LegalBasisDecision остаётся mounted, поэтому сворачивание
сохраняет ввод, ревизию и retry state. Ссылка следующего действия открывает
первый ожидающий решения документ. Прямой #dossier-document-UUID также
раскрывается и получает фокус. Семь локальных anchors сохранены по утверждённому
плану: это навигация по секциям, не ARIA tabs.

Выбор ЖК в анализе использует q по имени/адресу и серверную пагинацию25,
с явным фильтром DEMO/REAL. Поиск запускается кнопкой/Enter, смена страницы
не подтверждает связь и не меняет выбранный ID. Выбранный объект читается
отдельно по ID и остаётся в select вне текущих результатов, при пустом поиске,
ошибке и восстановлении review draft. Нет fuzzy-подтверждения или поиска
по не поддержанным API полям. Родительские mutation guards сохраняются.

Фильтр города реестра — точное название, поддержанное существующим API.
Фильтры/page/view остаются в URL. Перед открытием досье сохраняются позиция
страницы, источник фокуса и выбранная метка; возврат восстанавливает их после
загрузки того же query. Контекст ограничен пользователем/вкладкой,12часами;
logout/401 очищают его. Если storage недоступно, обычные ссылки и URL продолжают
работать; точное восстановление позиции не гарантируется.

Порядок объектов обзора: основание PENDING → UNKNOWN/REJECTED → остальные;
внутри группы более давняя/неизвестная проверка, затем серверный балл.
Это порядок работы в загруженной выборке до100, не глобальная сортировка реестра
и не полный список незавершённых решений по объекту. Сроков задач в API нет —
срочность не выдумывается. Общая очередь материалов остаётся отдельным точным API.
Формула риска и правовой статус не пересчитываются этим порядком.

## B3: рабочий путь в «Сверке» · 18.10.2026

Сначала найти кандидата, затем изучить выбранную сверку и предварительные
инциденты. КЖК — справочный поиск по страницам; Threads — ограниченный preview
с реальным состоянием подключения; DEMO-версии — учебная настройка. Они больше
не вытесняют очередь с начала экрана. Нет заявления о scheduler или доступе
к закрытому/государственному API.

Локальная ссылка открывает нужный native disclosure и переводит фокус; прежние
IDs, query filters/pagination/candidate_id и прямой hash сохранены. Hash работает
при прямом открытии/reload/Back и при повторном клике после ручного сворачивания.
Раскрытие не выполняет search/import/compare/review. Компоненты не размонтируются:
при перемещении между блоками сохраняются причина сверки, введённый snapshot ID,
запрос Threads, незавершённая DEMO-версия и выбранный File. Это сохранность внутри
текущей страницы, не новая гарантия восстановления monitoring-форм после reload;
перезагрузка по-прежнему сохраняет только существующий URL-контекст.

Ошибки справочных источников не подменяют результаты очереди и не запрещают её
чтение. Viewer видит разрешённое чтение тех же блоков; mutation controls остаются
только у analyst. Справочная страница/нет совпадения/предварительный инцидент
не подтверждают R1 и не меняют исторические сигналы/PDF.

## Семь разделов досье · B2/S3 · 18.10.2026

Локальная навигация: Обзор → Основания → Реклама → Факторы риска →
Доказательства → История → Сигналы. Секции доступны в кратком/подробном виде.
Реклама и сигналы ведут в действующие списки с property_id; добавление рекламы
не делает привязку автоматически. Нет выдуманных totals или новых API.

Редакторы факторов раскрываются локально. Все формы, File inputs, причины,
scoped drafts и retry state сохраняют mounted state при сворачивании и смене
вида. «Проверить R1/R3/R4/R5/R6» открывает нужный редактор; R2 ведёт к публикациям,
где остаются оригинал/гипотеза/привязка/evidence и отдельное решение. Старый hash
#dossier-materials и новые #dossier-editor-R… раскрывают ancestors при прямом
переходе/reload/Back, переводят фокус и не отправляют команды. Наличие hash не
запрещает пользователю затем переключить краткий вид. Пустые/неизвестные факторы
не маскируются: «Не зафиксирован» отличается от CONFIRMED/REJECTED.

Кнопка доказательств у фактора открывает общий раздел и выбранную группу.
Выбор источника/даты/исходника использует прежние evidence reads только по
запросу; счётчик уникальных IDs относится к факторам и основаниям этого ответа,
а не ко всем когда-либо загруженным материалам. Повторные ссылки на один ID не
создают дополнительные нарушения. История — существующий paged audit;
«Сигналы» объясняет неизменяемый snapshot и ведёт к версиям конкретного объекта.
В кратком виде аналитик может локально открыть проверку/добавление основания,
не разыскивая глобальный переключатель. Viewer получает чтение без загрузки
документов и команд принятия решений.

## Сохранность форм досье · B0+B1 · 18.10.2026

Формы R1, R4, R3/R5/R6, создания основания и решения по конкретному основанию
восстанавливают введённые поля при menu/Back/другом объекте/reload. Область —
пользователь + вкладка + объект + форма (для решения основания — ID документа).
Это локальный черновик, не сохранённое доказательство и не принятое решение.
Перед командой делается локальная контрольная копия текущих полей — в том числе
причины, уже использованной при сохранении документа. После успешной команды
завершённый черновик очищается; отклонение старого фактора сохраняет ещё не
загруженные новые материалы. 409/422 и сетевой отказ ввод не очищают.
Выбранные новые evidence IDs/дата R1/полнота и retry context сохраняются при SPA
в памяти; правка одной причины R4 не подменяет новое доказательство старым.
Новая ревизия документа не отправляет решение автоматически:
пользователь видит восстановленный ввод, актуальная expected_revision берётся
из текущего API. Правовые проверки остаются серверными.

Текст хранится в scoped sessionStorage с теми же ограничениями и fallback, что
review drafts. Срок12часов проверяется при восстановлении; это не таймер
физического удаления. Выбранные File-объекты и прежние retry caches сохраняются
только в памяти вкладки для переходов внутри приложения. Файлы не сериализуются
в Web Storage. После reload/закрытия вкладки файл нужно выбрать заново:
это явно указано при выборе и в восстановленной форме. Beforeunload предупреждает
о несохранённом вводе, когда браузер допускает такое предупреждение. Logout и 401 при `/auth/me`
очищают текстовый namespace и память файлов/повторов; истёкшая запись не восстанавливается.

Восстановление native fields не вызывает change/submit; controlled reason,
результаты трёх механизмов и статус R6 восстанавливают своё React-состояние.
Асинхронные варианты публикации R3 и условная дата R6 восстанавливаются после
их появления. Draft-формы разных объектов keyed по ID. Новые файлы не подменяют
сохранённые доказательства: R1/R3/R5/R6 по-прежнему требуют явного сохранения
изменённых материалов перед CONFIRM. R4 также блокирует подтверждение новых
несохранённых реквизитов; после reload с потерянным файлом требуется явный
повторный выбор и сохранение материалов перед подтверждением. Подсказки появляются только у изменённой
или восстановленной формы, не добавляя одинаковых предупреждений ко всем пустым формам.

Точный action total уже реализован в предыдущем блоке. READY_FOR_REVIEW остаётся
processing status; подписи или модель очереди заново не переделывались. R4 browser
regression использует Самал с другими подтверждёнными факторами и проверяет
сохранность baseline/добавление только R4 вместо допущения общего score0.

## Публикации и ограниченные диаграммы · 17.10.2026

Карточка даёт краткий текст; полный оригинал, происхождение и SHA — в деталях. Возврат сохраняет серверные фильтры/страницу. Необязательные поля остаются native disclosure; новое оформление сохраняет черновики/idempotency. Заголовок review различает выбранный материал. Диаграммы показывают loaded count/server total; первые100 не выдаются за весь реестр. DEMO/image/site/text не пересекаются, processing readiness отдельно от точных нерешённых действий.

## Точные действия и выбранные тексты · 17.10.2026

В обзоре «Материалы с нерешёнными действиями» — точный server total отдельного
review-queue API. READY остаётся только состоянием обработки в прежнем режиме.
Материалы и действия не складываются; сброс фильтров не закрывает выбранный
оригинал. Переход к задаче не отправляет команду решения. Исторический R2 всегда
показывает свой объект/доказательства и причину; 409/422 не стирают черновик.

В сравнении оригинал и конкретная extraction выбираются явно, без OCR fallback.
URL хранит только IDs/страницу, чтение не меняет риск/решения. Совпадение не
называется доказанным дублем; направление не означает хронологию. Полный текст,
точный фрагмент diff, metadata и UNKNOWN даты остаются доступны. Повторный выбор
стороны во время URL transition временно блокируется, предотвращая потерю выбора.

## Интеграция frontend 17.10.2026

Общий поиск принимает название/адрес и открывает реестр с q; это не новый поиск
по всей истории/сигналам. Обзор показывает реальные server totals и текущие
очереди, а не вымышленные временные ряды. Первоначальная READY очередь теперь
сохранена только в режиме processing; точная очередь описана дополнением выше.

Карта строит маршрут «найти → выбрать → открыть досье»; охват относится к текущей
серверной странице. Выбранная метка имеет aria-pressed/focus и соответствует
строке реестра. Объекты без координат остаются в доступной таблице.

Сигналы строят маршрут «выбрать снимок → проверить факты → решение/PDF».
Поиск в очереди явно ограничен загруженной страницей и не сбрасывает выбранный
исторический снимок. Дополнительные фильтры и группы фактов — native details;
конфликт revisions сохраняет введённую причину. Новое оформление не меняет
ролей, API, идемпотентности, исторических snapshots и необходимости ручных решений.

Причины match/hypothesis/R2, изменённый текст гипотезы и OCR, выбранные контекстные значения и fingerprint/UUID неопределённой команды сохраняются в sessionStorage, scoped к пользователю/вкладке/материалу/версии. Неизменённый исходник/OCR, файлы, credentials и command payload не сериализуются.

Текущий implementation tradeoff заменяет минимальный guard из первоначального плана, сохраняя ввод при SPA-переходах и настоящем reload без вмешательства в router.

Число действий ниже — walkthrough-модель по существующему UI, не результат user testing. Одно заполненное поле/выбор/активация = действие; чтение, ожидание OCR и прокрутка отдельно. Начальная точка указана; ошибки и дополнительные документы увеличивают число. Не удалять необходимые human decisions ради меньшего числа.

|---|---|
| Найти объект / реестр | Ввести q → открыть строку: 2; зона/основание добавляют по 1. API ищет по всему набору, global sorting не поддержана |
| Снять q+зону+основание / реестр | Раньше 3 изменения controls; теперь 1 «Сбросить фильтры», page сбрасывается, view сохраняется, focus в поиск. Каждое поле остаётся отдельно доступным |
| Доказательство / готовая карточка | «Факторы и решения» → «Доказательства»: 2; anchor уменьшает поиск/прокрутку, не изменяет решение |

| Продолжить после сохранения текста | «Перейти к проверке»: 1 вместо прежних 2 (карточка → review). Запуск анализа отдельно: ещё 1, подтверждения не объединяются |
| Файл / обзор | Добавить → «Файл» → происхождение → выбрать файл → сохранить: 5; действия внутри системного file chooser зависят от ОС |
| OCR и matching / сохранённый материал | Перейти в проверку и при необходимости запустить анализ; затем отдельное решение по каждой гипотезе и отдельная привязка к очереди. Число зависит от hypotheses; исправление требует значения/причины |
| R2 / проверенные оплата и match | Выбрать проверенную гипотезу/обосновать по форме → сохранить evidence/PENDING → отдельное подтверждение. Число зависит от уже сохранённых evidence/revision; эти действия нельзя объединить |

1. Обзор → приоритетный объект → причина и доказательство. Сводка показывает проверяемые серверные числа и помогает перейти к работе.
2. Реестр → фильтр → точная очередь/корпус → карточка. Поиск и фильтры сохраняются в URL. Список остаётся доступным без карты/тайлов; зелёная зона не означает безопасность.
3. Новый текст/файл → сохранённый оригинал → анализ → ручная сверка OCR → привязка объекта → evidence → отдельное решение фактора. Не объединять эти подтверждения и не скрывать исходник.
4. Объект → текущая ревизия → снимок сигнала → подтверждение/возврат с причиной → PDF точной версии. Старый снимок не заменяется свежими фактами. Stale state объясняется с вариантом обновить сведения.

## Ясность и иерархия

С 16.10.2026 обзор показывает пять объектов по серверному баллу среди полученной выборки; при total >100 явно указано ограничение. Общие KPI берутся только из summary. Новые материалы — ровно backend `new_advertisements`, ссылка ведёт к status=NEW, без подмены числом всех публикаций.

Досье получает только закодированную query реестра (`registry`), ссылка возврата всегда имеет фиксированный локальный путь `/properties`. Это сохраняет поиск/страницу/list-map даже после reload, без произвольного redirect. Аналогичный `materials` сохраняет фильтры/страницу рекламы. На карте и в таблице общий выбранный объект, при смене API-выборки выбор сбрасывается. Глобальной сортировки API нет.

Реклама использует существующие status/page/page_size; поиск по тексту не имитируется фильтрацией одной страницы. При новом запросе/ошибке старая очередь скрыта. Даты публикации и фиксации показаны отдельно; неизвестная дата не заменяется текущей. Review хранит выбранный advertisement_id в URL; Back/reload не запускают анализ. Selector ограничен существующими первыми 100 материалами, остальное открывается через пагинируемый реестр. В signals anchors к фактам, решению, PDF и истории перемещают фокус, не размонтируют reason и не создают новую версию.

- Один h1 описывает задачу, h2 — рабочий раздел. Не заменять заголовки uppercase надписями. Глаголы кнопок описывают результат: сохранить материал, подтвердить фактор, открыть версию.
- Коды R1–R6 сопровождаются понятной расшифровкой. Сохранять различие гипотезы, документа, фактора и сигнала. В списке достаточно короткого смысла; полные условия/даты — в досье.
- UNKNOWN, ошибка реестра и «не найдено» не являются подтверждённым отсутствием. Сохранять оговорки в нужном контексте, не повторять общий дисклеймер в каждом визуальном блоке.
- У каждого рабочего блока понятный следующий шаг; опасное/необратимое решение визуально отличается от просмотра. Сохранение supporting-файла само не начисляет баллы.
- Предметные подписи и даты переводить последовательно. Внешний текст/имена рендерить как text, без innerHTML. Неподтверждённые числа или искусственный progress не добавлять ради вида.

## Навигация и длинные формы

История доступна из anchor-навигации досье и в существующем раскрываемом журнале review. События показывают сохранённые переходы и причины, а текущий балл остаётся в RiskSummary. Пагинация использует `history_page`, сохраняет остальную query и фокусирует заголовок; смена публикации сбрасывает её. Переход к факторам/основаниям внутри текущего досье не теряет фильтры возврата. Обновление/просмотр журнала не принимает решение и не запускает анализ. Прежние события скрыты при запросе другой страницы или ошибке. У автора показывается текущее имя профиля; сохранённый ID доступен в записи аудита.

После сохранения нового текста «Перейти к проверке» открывает существующий review за одно действие вместо двух (карточка → review); «Открыть публикацию» остаётся отдельной вторичной кнопкой. Переход не запускает анализ автоматически, исходник/DEMO/даты и обязательное подтверждение каждого факта сохраняются. Фокус после сохранения приходит к результату операции.

На review четыре явных anchor-этапа показывают, где сверять оригинал, сколько гипотез разобрано и требуется ли подтверждение очереди. Это не автоматическое одобрение и не процент готовности юридического заключения. Формы и несохранённые причины сохраняются при переходах между этапами. Главное действие review — анализ текущего материала; новую публикацию можно добавить через раздел «Реклама».

В сигналах фильтры и страница живут в URL, выбор версии/history links сохраняет их, browser Back/reload восстанавливает контекст. Смена фильтра сбрасывает page/выбранный signal_id; reset возвращает focus первому select. Исторический снимок по прямой ссылке может не входить в фильтрованную очередь — это подписывается отдельно. Пока новая очередь загружается или её запрос упал, старые строки не показывать под новыми фильтрами.

- Три основных пункта, в подробном виде шесть, доступны на desktop и mobile; роль и выход также доступны. Добавлять skip-to-main и ясный focus.
- Для длинной карточки использовать anchor-навигацию к сведениям, основаниям, факторам и добавлению материалов. Anchor сохраняет DOM и введённые значения. Не заменять рабочие формы вкладками с unmount.
- Primary action страницы не должен конкурировать с пятью другими primary. В локальном решении primary подтверждает конкретный шаг, outline предлагает просмотр/возврат, danger обозначает отклонение.
- Формы группируются по задаче, labels видимы, необязательные поля подписаны. Подсказки располагаются до ошибки, а не только после неудачного submit. Required/format/size проверяются как сейчас сервером и браузером.
- Не менять IDs/names/roles/API payloads ради стилизации. При ответе 409 показать причину и разрешённое следующее действие, а не автоматически повторять команду.
- Кнопка во время запроса показывает реальное ожидание и disabled. Ошибка не стирает ввод. Данные draft/выбранного файла не должны исчезать из-за закрытия соседнего блока.

## Доступность и адаптивность

Keyboard: Tab в естественном DOM-порядке; Enter/Space работают по нативной семантике; Escape/focus return обязательны для будущих dialogs. Все icon-only действия имеют accessible name. Не убирать outline и не делать интерактивным только hover.

Таблица сохраняет все важные столбцы; горизонтальная прокрутка ограничена подписанным контейнером, доступным с клавиатуры. Вёрстка страницы переносится без горизонтального overflow. Не добавлять `overflow-x:hidden` всему body как исправление.

При 375/768/1024/1440 px проверять: навигацию/выход, заголовок/главное действие, фильтры, длинное название объекта, строки таблицы, inputs/select/file и bottom действия форм. Zoom 200% проверять отдельно от уменьшения viewport. Карта не должна перехватывать прокрутку страницы колесом. Поддерживать `prefers-reduced-motion`.

## Что считать доказательством

Для каждого блока фиксировать страницы/роль/ширины и наблюдавшийся результат. Проверять реальные API и browser E2E, включая ручное решение/PDF. Автоматический contrast/focus тест не заменяет screen-reader и пользовательскую приёмку; соответствие WCAG не объявляется по одному Lighthouse/axe баллу. Состояния ошибок можно воспроизвести перехватом запросов в тесте, обозначив подмену.

Перед публикацией обновлять [UI_AUDIT](UI_AUDIT.md) и PROJECT_STATUS фактическими проверками. Доступность важнее декоративной консистентности; при конфликте сохранять понятный безопасный сценарий.
