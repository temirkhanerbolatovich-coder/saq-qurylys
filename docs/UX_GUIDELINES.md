## Версии поискового профиля ·19.10.2026

409/ошибка оставляют ввод, обновление — GET, ожидаемая ревизия требует сверки.
Выбранные profile ID/revision живут в URL вместе с candidate/q, подсказки и профиль
находятся вне внешней поисковой формы. Клавиша Enter там не отправляет команду.

## Импорт открытой страницы ·19.10.2026

Импорт запускает только явная кнопка; открытие ссылки/инструмента не отправляет
команду. Источники и лицензии разделяются: CC BY относится только к Primeminister,
не ко всем HTML. Для AN GROUPS указывается область извлечения мобильных карточек,
возможное отличие desktop, неизвестные дата/ЖК/очередь. Полный HTML доступен для
сверки; текст источника не исправляется и не переводится. Прежние Button/Notice,
native label/input, job deep links, loading/error/retry и ручные решения сохранены.

## Текущий редизайн · Master2.0 ·19.10.2026

Общая навигация отделена от вкладок досье; источник и дата находятся рядом с
фактом. RU/KZ меняет authored interface copy без смены маршрута, remount или
команд. Оригиналы, названия и причины аналитика не переводятся. Часть длинных
специализированных инструкций имеет русский fallback; независимая языковая
приёмка всего продукта не заявляется.

Строка таблицы открывает детали справа. Просмотр, смена вкладки и выбор параметров
не создают бизнес-команд. Скачивание — отдельный GET с ожиданием, ошибкой/повтором
и отменой. PDF досье отражает текущее состояние на момент формирования;
исторический PDF сигнала сохраняет собственную версию. Сводка и оговорки обязательны.

Материал строки импорта не означает подтверждённую связь с ЖК. Следующий шаг ведёт
к уже сохранённому материалу для проверки идентичности; гипотеза, связь, фактор
и сигнал подтверждаются отдельно. При смене ID прежнее досье не показывается
в новом контексте. Неизвестные сведения доступны через native disclosure,
не подменяются благоприятным результатом.

19.10, ТЗv2: прямой /review начинает с нерешённых действий, а не processing.
Переключение всегда записывает queue=actions/processing; reset фильтра не меняет
вид. Старые ссылки с query без queue остаются processing (status/page/material),
чтобы не менять прежнюю семантику сохранённого ID. Выбор материала и drafts прежние.
На телефоне все5зон сохраняют видимые icon+label, native link≥44px, без modal-menu.
Inter не внедрён: A/B ухудшил плотность таблиц без доказанного выигрыша читаемости.

19.10: быстрые изменения фильтров реестра объединяются с актуальным URL через
native history.replaceState (Next/useSearchParams). Debounce уважает Back/Forward;
смена вида сохраняет фильтры, reset — вид/page_size и прочий контекст.

19.10: коррекция LINKED — «Исправить ошибочную связь» → причина/confirmation →
«Отменить ошибочную связь», затем отдельный выбор досье. На форме явно сказано,
что публикации и решения остаются на месте. Checkbox после reload/refresh пустой;
409 сохраняет причину, pending блокирует поля. История показывает каждое решение,
дату/аналитика/причину и сохранённое имя досье; старый ID остаётся честным fallback.
CREATED защищён и объяснён, viewer читает историю без controls отмены.

19.10: «Связать с существующим досье» и «Создать досье объекта» — отдельные
раскрываемые действия аналитика. Для связи видны исходное имя/адрес/очередь и
выбранное досье/застройщик. Подтверждение не переносит публикации или решения.
Выбор и причина сохраняются по кандидату; checkbox после reload/refresh требует
повторного подтверждения. Пока идёт команда, native fieldset блокирует ввод.
На досье count считает LINKED; переход открывает все относящиеся находки, включая
CREATED с явной подписью. property_id и selected candidate сохраняются в URL.

19.10, сквозной сценарий досье: поиск дублей начинается с исходного имени ЖК,
чтобы автоматически добавленная очередь не сужала результат. Полное имя/очередь
аналитик проверяет в форме. Отсутствующий БИН показывается как «Не указан»;
DEMO определяется признаком записи. Компактная сетка формы сохраняет порядок
полей и native labels; на телефоне одна колонка. В dev live-проверке Enter
на summary раскрывает форму без POST; отдельный match подтверждается позже.

19.10: «Создать досье объекта» — отдельное явное действие аналитика в кандидате.
Раскрытие только показывает форму. Поиск дублей открывается отдельной вкладкой;
исходный candidate_id и черновик сохраняются. Проверка checkbox не восстанавливается
после reload. Ошибка оставляет ввод; успех даёт ссылку на новое досье и очищает
сохранённый черновик. Досье содержит обратный переход к кандидату/источникам.
Привязки публикаций и подтверждения риска/сигнала остаются отдельными действиями.

## Область материалов и очередь сигналов ·19.10

Публикации и оба вида очереди поддерживают одинаковый режим DEMO/реальные/все.
is_demo передаётся серверу до подсчёта и пагинации. Переключение вида очереди
сохраняет режим, q и выбранный материал; выбор режима сбрасывает page.

Вход /signals без query открывает актуальные DRAFT («К проверке»). Существующие
deep links с параметрами сохраняют прежний смысл. «Все версии» включает историю,
«Устаревшие» применяет is_stale=true; это не удаление и не архивирование записей.
Смена вида, фильтра и сброс сохраняют открытый signal_id и его черновик.
Порядок/счётчики серверные; последняя версия каждого объекта здесь не вычисляется.


## Поиск материалов ·19.10

Текст публикации или название источника ищется по всему серверному набору с
учётом фильтров, не только на текущей странице. Enter/«Найти материалы» изменяет
q и сбрасывает page; «Сбросить поиск» удаляет только q/page. Открытый материал,
версия и черновик остаются. Пустая очередь предлагает изменить фильтры и не
свидетельствует о безопасности источников. Ошибка сохраняет запрос и даёт retry.
OCR/гипотезы/внешние источники исключены из этой семантики явно.
Рекомендация Skill об autocomplete здесь не применяется: выбран явный submit
как в существующем поиске сигналов, без дополнительного API подсказок.


## Черновики сверки ·19.10.2026

Причина и выбранная публикация принадлежат кандидату, состояние/причины решения —
конкретному инциденту. Используется общий useReviewDraft: пользователь + сессия
вкладки, восстановление до 12 часов после изменения, очистка при выходе/401.
DEMO-версия хранится отдельно для каждого кандидата. Выбор версии до кандидата
остаётся временным и присваивается следующему явно выбранному кандидату.
Успешная сверка очищает её ввод, но сохраняет выбор версии; успешное решение
очищает только свой черновик. Ошибка сохраняет ввод. Если публикация недоступна,
нужен явный новый выбор — автоматической подмены нет.

Короткая отметка восстановления находится у формы, сбой хранилища — в Notice.
При недоступном sessionStorage работает память приложения с явным ограничением
перезагрузки. Раскрытие инструментов, навигация и восстановление не отправляют
команды. Повтор требует кнопки; неизменённый payload использует прежний ключ,
изменение причины или актуальной серверной ревизии создаёт новый ключ.
Новые формы кандидата/версии и поиск Threads этим блоком не сохраняются после reload.

## Понятные задачи и файлы ·19.10

- Название R2 берётся по точному ID задачи, одним batch read. Это текущее имя
  реестра, не выдуманное историческое имя. Перепривязка не меняет target/evidence;
  UUID доступен вторым уровнем/fallback. Причины и idempotency прежние.
- Известные коды STAGE переведены только при чтении, код доступен в details.
  Исправление и подтверждение остаются отдельными действиями.
- При неизвестном MIME кнопка PDF объясняет оригинал/производную копию. Имя
  содержит тип/название/дату/ID; сигнал — frozen имя и v/r. Скачивание не создаёт
  доказательства или PDF job. Ошибки имени дают безопасный fallback.

## Согласованная композиция ·19.10 · локальный блок

- Обзор начинает работу со счётчиков и реальной серверной очереди:3 в кратком,
  5 в подробном режиме. Аналитика следует после действий. Счётчики независимы,
  не суммируются в выдуманное число дел, ошибки не превращаются в ноль.
- На desktop оба режима реестра используют таблицу. Brief phone — полные
  карточки; detailed сохраняет клавиатурно доступную горизонтальную прокрутку.
  Название/застройщик/основание/риск/подтверждённые коды/дата остаются доступны.
- Возврат из досье сохраняет exact query/scroll/selection и фокусирует видимую
  ветвь реестра; скрытый desktop-дубль не перехватывает mobile focus.
- Ход проверки начинается с точного следующего действия. На узком экране он
  идёт перед сведениями об объекте. Вкладки/переходы не размонтируют редакторы.
  Оговорки и неизвестность остаются явными; код R не становится подтверждённым
  от перехода или нажатия на панель. PDF/сигнал остаются историческими версиями.

## Сохранность и точные действия ·19.10 · локальный блок

- Новый текстовый материал использует существующий user/session-scoped
  useReviewDraft: переходы/reload, TTL12часов, восстановление без отправки,
  очистка после успешного сохранения и на logout/401. Старый `saq-ad-draft`
  без автора не восстанавливается и удаляется на границе авторизации.
- Причина решения сигнала привязана к user/session и signal_id. Переход на
  другую версию не переносит причину; Back/reload/409 сохраняют свой ввод.
  Только успешное решение очищает черновик этой версии. При недоступном Web
  Storage явно показан режим памяти вкладки и ограничение перезагрузки.
- В «Ходе проверки» pending-документ открывает свой документ, pending R1/R3–R6
  — свой редактор с focus, выбранной вкладкой и раскрытыми native details.
  Публикация не требуется для открытия ожидающего R4/R5/R6. R2 сохраняет
  прежний путь через публикации. Viewer получает только чтение.
- [Макет трёх экранов](prototypes/README.md) — отдельное локальное предложение.
  Его данные синтетические, API отсутствует; в приложение композиция не перенесена.

## Стабилизация поиска, риска и версии реестра ·18.10

- q и точный city в реестре накапливаются вместе, применяются через350ms после
  последнего изменения либо сразу Enter; сбрасывается page, сохраняется view.
  Reset очищает оба draft/URL и фокусирует поиск. Back/reload восстанавливают URL.
- Мобильный глобальный поиск открывается отдельной кнопкой с focus, Escape
  сохраняет draft и закрывает форму; Enter ведёт в реестр с encoded q. Это поиск
  объекта, не отдельный поиск по всем сущностям проекта.
- GREEN рядом с UNKNOWN/PENDING/REJECTED имеет явную подпись статуса основания;
  она не меняет score и не сообщает, что объект безопасен. Понятность проверить
  с сотрудниками, не выводить из прохождения browser tests.
- В сверке версия выбирается по label/городу/дате из списка со страницами10;
  описание выбранной версии/ID сохраняется вне текущей страницы и при retry.
  Выбор не запускает compare. «Без версии» остаётся допустимым исходом;
  REAL+DEMO запрет прежний. Manual UUID в details без придуманного описания.
  Полный reload сбрасывает выбранную версию и несохранённое основание сверки;
  это ограничение текущего мониторинга, не обещание durable draft.

## Поиск сигналов по всему набору · локальный блок18.10

Поиск очереди запускается Enter/кнопкой по текущему и frozen имени, ID, метке
версии и статусу. q≤300 сохраняется в URL, при submit page сбрасывается, текущий
signal_id фиксируется; pagination его сохраняет. Reload/Back восстанавливают
q/page. Ввод без submit не меняет результаты; фильтры применяются вместе с q.
Empty/error/pending не скрывают открытый historical snapshot. Сброс очищает весь
query/selection и фокусирует selector объекта, как прежде. Global total относится
ко всем совпадениям; counts DRAFT/stale остаются только текущей страницы.
Literal substring не подтверждает идентичность или правовое основание.

## Глобальный рабочий приоритет · локальный блок18.10

Список обзора выбирается сервером из всего доступного набора до pagination:
PENDING → UNKNOWN/REJECTED → остальные; внутри отсутствие даты → более давняя
last_reviewed_at → больший server score → ID. Браузер не пересортировывает ответ.
Это очередь проверки, не вывод о нарушении и не дедлайн; UNKNOWN не становится R1.
Подробный вид показывает5, краткий3. total относится ко всему набору. Ошибка
списка явно отличается от empty и не блокирует другие рабочие очереди.
Обычный порядок реестра/выбора объекта без order остаётся name/ID.
На mobile пояснение следующего действия занимает полную ширину строки, а балл
и ссылка на досье расположены выше; текст не сжимается между двумя controls.

## Реальные отношения объектов · локальный блок18.10

Родители/дети/соседи следуют только parent_id, уровень — сохранённому level.
Названия и общий застройщик не создают связи. В раскрытии прямо указано, что
документы/правовой статус/риск проверяются отдельно. Отсутствие родителя/детей
показано как отсутствие сохранённых сведений; ошибка имеет отдельное сообщение
и retry. Корневые объекты не объединяются в одну фиктивную семью.
Связанные досье открываются в «Обзоре» с прежним registry context; Back/Forward
сохраняют обычную историю. Пагинация детей/соседей независима, локальна досье и
сбрасывается после reload; загрузка страницы не меняет выбранный объект/решения.

## Расширенный поиск и объекты сигналов · локальный блок18.10

Существующий q в properties/dashboard ищет подстроку без учёта регистра по имени,
адресу, отдельному альтернативному названию, застройщику и БИН. Внешние пробелы
удаляются; пустой q не ограничивает выборку. БИН допускает полный или частичный
ввод; поиск не проверяет его подлинность. %, _ и backslash ищутся буквально.
Нет fuzzy/транслитерации/автоматического подтверждения совпадения.

пользователь видит восстановленный ввод, актуальная expected_revision берётся

их появления. Draft-формы разных объектов keyed по ID. Новые файлы не подменяют
сохранённые доказательства: R1/R3/R5/R6 по-прежнему требуют явного сохранения
изменённых материалов перед CONFIRM. R4 также блокирует подтверждение новых
несохранённых реквизитов; после reload с потерянным файлом требуется явный
повторный выбор и сохранение материалов перед подтверждением. Подсказки появляются только у изменённой
или восстановленной формы, не добавляя одинаковых предупреждений ко всем пустым формам.

Точный action total уже реализован в предыдущем блоке. READY_FOR_REVIEW остаётся

## Реализовано S0–S2 · 17.10.2026

Уточнение повторного аудита `f9db50b`: гарантия S0 относится к формам `/review`. Причина R4 в досье пока теряется при переходе в реестр и повторном открытии объекта; переключение краткий/подробный сохраняет mounted формы, но не заменяет защиту ухода с маршрута. Это открытый P0, а не реализованная общая гарантия. READY_FOR_REVIEW — статус результата обработки; текущий backend не переводит новые материалы в REVIEWED после всех решений. Его total нельзя интерпретировать как точное число оставшихся действий аналитика. План исправления подписи и защиты — контрольная точка B в UI_IMPLEMENTATION_PLAN.

Пять зон доступны в обоих видах. Обзор сначала показывает действующие очереди NEW / READY_FOR_REVIEW / FAILED / DRAFT и переходы к работе. Проверка использует серверные status/page/page_size (10/20/50), сохраняет `advertisement_id`, фильтры, страницу и Back/reload. Без ID материал не выбирается автоматически. Прямая ссылка загружает выбранный материал независимо от ошибки/фильтра очереди. Выбор и навигация не вызывают команд анализа или подтверждения.

S0 реализован как восстановление черновиков с предупреждением beforeunload, без перехвата истории Next.js. Причины match/hypothesis/R2, изменённый текст гипотезы и OCR, выбранные контекстные значения и fingerprint/UUID неопределённой команды сохраняются в sessionStorage, scoped к пользователю/вкладке/материалу/версии. Восстановление допускается в течение 12 часов после последнего изменения; истечение проверяется при чтении, это не фоновое удаление таймером. Успешная команда очищает соответствующий черновик; 409 и сетевой отказ сохраняют ввод/ключ. Выход или 401 очищает review namespace, включая fallback памяти. Неизменённый исходник/OCR, файлы, credentials и command payload не сериализуются.

При отказе storage действует память только до reload с явным предупреждением. Копия вкладки подчиняется обычной семантике sessionStorage браузера; синхронизация между устройствами не обещается. Восстановленный ввод требует повторной проверки актуальных версий; он не становится серверным решением. Native beforeunload зависит от браузера и предшествующего пользовательского действия. Текущий implementation tradeoff заменяет минимальный guard из первоначального плана, сохраняя ввод при SPA-переходах и настоящем reload без вмешательства в router.

R1–R6, роли, API, источники, исторические snapshots/PDF и разделение REAL/DEMO сохранены. Порядок внутренних инструментов `/monitoring` и перегруппировка досье остаются будущим S3. Ниже исходные предложения фаз 0–1 — историческое основание, а не перечень завершённых возможностей.

## Предложение для аналитического workspace · 17.10.2026 · НЕ УТВЕРЖДЕНО

Причины, исправленный OCR, файлы и ключи команд не теряются при локальном раскрытии; сохранённый draft не равен принятому решению. Число действий ниже — walkthrough-модель по существующему UI, не результат user testing. Одно заполненное поле/выбор/активация = действие; чтение, ожидание OCR и прокрутка отдельно. Начальная точка указана; ошибки и дополнительные документы увеличивают число. Не удалять необходимые human decisions ради меньшего числа.

|---|---|
| Найти объект / реестр | Ввести q → открыть строку: 2; зона/основание добавляют по 1. API ищет по всему набору, global sorting не поддержана |
| Снять q+зону+основание / реестр | Раньше 3 изменения controls; теперь 1 «Сбросить фильтры», page сбрасывается, view сохраняется, focus в поиск. Каждое поле остаётся отдельно доступным |
| Доказательство / готовая карточка | «Факторы и решения» → «Доказательства»: 2; anchor уменьшает поиск/прокрутку, не изменяет решение |
| Новый текст / обзор | «Добавить публикацию» → происхождение → текст → сохранить: 4; URL/дата добавляют по 1, DEMO default явный |
| Продолжить после сохранения текста | «Перейти к проверке»: 1 вместо прежних 2 (карточка → review). Запуск анализа отдельно: ещё 1, подтверждения не объединяются |
| Файл / обзор | Добавить → «Файл» → происхождение → выбрать файл → сохранить: 5; действия внутри системного file chooser зависят от ОС |
| OCR и matching / сохранённый материал | Перейти в проверку и при необходимости запустить анализ; затем отдельное решение по каждой гипотезе и отдельная привязка к очереди. Число зависит от hypotheses; исправление требует значения/причины |
| R2 / проверенные оплата и match | Выбрать проверенную гипотезу/обосновать по форме → сохранить evidence/PENDING → отдельное подтверждение. Число зависит от уже сохранённых evidence/revision; эти действия нельзя объединить |

1. Обзор → приоритетный объект → причина и доказательство. Сводка показывает проверяемые серверные числа и помогает перейти к работе.
2. Реестр → фильтр → точная очередь/корпус → карточка. Поиск и фильтры сохраняются в URL. Список остаётся доступным без карты/тайлов; зелёная зона не означает безопасность.
3. Новый текст/файл → сохранённый оригинал → анализ → ручная сверка OCR → привязка объекта → evidence → отдельное решение фактора. Не объединять эти подтверждения и не скрывать исходник.
4. Объект → текущая ревизия → снимок сигнала → подтверждение/возврат с причиной → PDF точной версии. Старый снимок не заменяется свежими фактами. Stale state объясняется с вариантом обновить сведения.

## Ясность и иерархия

С 16.10.2026 обзор показывает пять объектов по серверному баллу среди полученной выборки; при total >100 явно указано ограничение. Общие KPI берутся только из summary. Новые материалы — ровно backend `new_advertisements`, ссылка ведёт к status=NEW, без подмены числом всех публикаций.

Досье получает только закодированную query реестра (`registry`), ссылка возврата всегда имеет фиксированный локальный путь `/properties`. Это сохраняет поиск/страницу/list-map даже после reload, без произвольного redirect. Аналогичный `materials` сохраняет фильтры/страницу рекламы. На карте и в таблице общий выбранный объект, при смене API-выборки выбор сбрасывается. Глобальной сортировки API нет.

Реклама использует существующие status/page/page_size; поиск по тексту не имитируется фильтрацией одной страницы. При новом запросе/ошибке старая очередь скрыта. Даты публикации и фиксации показаны отдельно; неизвестная дата не заменяется текущей. Review хранит выбранный advertisement_id в URL; Back/reload не запускают анализ. Selector ограничен существующими первыми 100 материалами, остальное открывается через пагинируемый реестр. В signals anchors к фактам, решению, PDF и истории перемещают фокус, не размонтируют reason и не создают новую версию.

- Один h1 описывает задачу, h2 — рабочий раздел. Не заменять заголовки uppercase надписями. Глаголы кнопок описывают результат: сохранить материал, подтвердить фактор, открыть версию.
- Коды R1–R6 сопровождаются понятной расшифровкой. Сохранять различие гипотезы, документа, фактора и сигнала. В списке достаточно короткого смысла; полные условия/даты — в досье.
- UNKNOWN, ошибка реестра и «не найдено» не являются подтверждённым отсутствием. Сохранять оговорки в нужном контексте, не повторять общий дисклеймер в каждом визуальном блоке.
- У каждого рабочего блока понятный следующий шаг; опасное/необратимое решение визуально отличается от просмотра. Сохранение supporting-файла само не начисляет баллы.
- Предметные подписи и даты переводить последовательно. Внешний текст/имена рендерить как text, без innerHTML. Неподтверждённые числа или искусственный progress не добавлять ради вида.

## Навигация и длинные формы

История доступна из anchor-навигации досье и в существующем раскрываемом журнале review. События показывают сохранённые переходы и причины, а текущий балл остаётся в RiskSummary. Пагинация использует `history_page`, сохраняет остальную query и фокусирует заголовок; смена публикации сбрасывает её. Переход к факторам/основаниям внутри текущего досье не теряет фильтры возврата. Обновление/просмотр журнала не принимает решение и не запускает анализ. Прежние события скрыты при запросе другой страницы или ошибке. У автора показывается текущее имя профиля; сохранённый ID доступен в записи аудита.

После сохранения нового текста «Перейти к проверке» открывает существующий review за одно действие вместо двух (карточка → review); «Открыть публикацию» остаётся отдельной вторичной кнопкой. Переход не запускает анализ автоматически, исходник/DEMO/даты и обязательное подтверждение каждого факта сохраняются. Фокус после сохранения приходит к результату операции.

На review четыре явных anchor-этапа показывают, где сверять оригинал, сколько гипотез разобрано и требуется ли подтверждение очереди. Это не автоматическое одобрение и не процент готовности юридического заключения. Формы и несохранённые причины сохраняются при переходах между этапами. Главное действие review — анализ текущего материала; новую публикацию можно добавить через раздел «Реклама».

В сигналах фильтры и страница живут в URL, выбор версии/history links сохраняет их, browser Back/reload восстанавливает контекст. Смена фильтра сбрасывает page/выбранный signal_id; reset возвращает focus первому select. Исторический снимок по прямой ссылке может не входить в фильтрованную очередь — это подписывается отдельно. Пока новая очередь загружается или её запрос упал, старые строки не показывать под новыми фильтрами.

- Три основных пункта, в подробном виде шесть, доступны на desktop и mobile; роль и выход также доступны. Добавлять skip-to-main и ясный focus.
- Для длинной карточки использовать anchor-навигацию к сведениям, основаниям, факторам и добавлению материалов. Anchor сохраняет DOM и введённые значения. Не заменять рабочие формы вкладками с unmount.
- Primary action страницы не должен конкурировать с пятью другими primary. В локальном решении primary подтверждает конкретный шаг, outline предлагает просмотр/возврат, danger обозначает отклонение.
- Формы группируются по задаче, labels видимы, необязательные поля подписаны. Подсказки располагаются до ошибки, а не только после неудачного submit. Required/format/size проверяются как сейчас сервером и браузером.
- Не менять IDs/names/roles/API payloads ради стилизации. При ответе 409 показать причину и разрешённое следующее действие, а не автоматически повторять команду.
- Кнопка во время запроса показывает реальное ожидание и disabled. Ошибка не стирает ввод. Данные draft/выбранного файла не должны исчезать из-за закрытия соседнего блока.

## Доступность и адаптивность

Keyboard: Tab в естественном DOM-порядке; Enter/Space работают по нативной семантике; Escape/focus return обязательны для будущих dialogs. Все icon-only действия имеют accessible name. Не убирать outline и не делать интерактивным только hover.

Таблица сохраняет все важные столбцы; горизонтальная прокрутка ограничена подписанным контейнером, доступным с клавиатуры. Вёрстка страницы переносится без горизонтального overflow. Не добавлять `overflow-x:hidden` всему body как исправление.

При 375/768/1024/1440 px проверять: навигацию/выход, заголовок/главное действие, фильтры, длинное название объекта, строки таблицы, inputs/select/file и bottom действия форм. Zoom 200% проверять отдельно от уменьшения viewport. Карта не должна перехватывать прокрутку страницы колесом. Поддерживать `prefers-reduced-motion`.

## Что считать доказательством

Для каждого блока фиксировать страницы/роль/ширины и наблюдавшийся результат. Проверять реальные API и browser E2E, включая ручное решение/PDF. Автоматический contrast/focus тест не заменяет screen-reader и пользовательскую приёмку; соответствие WCAG не объявляется по одному Lighthouse/axe баллу. Состояния ошибок можно воспроизвести перехватом запросов в тесте, обозначив подмену.

Перед публикацией обновлять [UI_AUDIT](UI_AUDIT.md) и PROJECT_STATUS фактическими проверками. Доступность важнее декоративной консистентности; при конфликте сохранять понятный безопасный сценарий.
