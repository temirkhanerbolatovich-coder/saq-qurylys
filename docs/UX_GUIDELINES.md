# SAQ QURYLYS — UX-рекомендации

Обязательно читать вместе с [DESIGN_SYSTEM](DESIGN_SYSTEM.md) перед frontend-задачами. Основной пользователь — аналитик, сопоставляющий оригинал, объект и доказательства; viewer просматривает сведения. Границы ролей задаёт backend, UI не расширяет полномочия.

## Основные маршруты

1. Обзор → приоритетный объект → причина и доказательство. Сводка показывает проверяемые серверные числа и помогает перейти к работе.
2. Реестр → фильтр → точная очередь/корпус → карточка. Поиск и фильтры сохраняются в URL. Список остаётся доступным без карты/тайлов; зелёная зона не означает безопасность.
3. Новый текст/файл → сохранённый оригинал → анализ → ручная сверка OCR → привязка объекта → evidence → отдельное решение фактора. Не объединять эти подтверждения и не скрывать исходник.
4. Объект → текущая ревизия → снимок сигнала → подтверждение/возврат с причиной → PDF точной версии. Старый снимок не заменяется свежими фактами. Stale state объясняется с вариантом обновить сведения.

## Ясность и иерархия

- Один h1 описывает задачу, h2 — рабочий раздел. Не заменять заголовки uppercase надписями. Глаголы кнопок описывают результат: сохранить материал, подтвердить фактор, открыть версию.
- Коды R1–R6 сопровождаются понятной расшифровкой. Сохранять различие гипотезы, документа, фактора и сигнала. В списке достаточно короткого смысла; полные условия/даты — в досье.
- UNKNOWN, ошибка реестра и «не найдено» не являются подтверждённым отсутствием. Сохранять оговорки в нужном контексте, не повторять общий дисклеймер в каждом визуальном блоке.
- У каждого рабочего блока понятный следующий шаг; опасное/необратимое решение визуально отличается от просмотра. Сохранение supporting-файла само не начисляет баллы.
- Предметные подписи и даты переводить последовательно. Внешний текст/имена рендерить как text, без innerHTML. Неподтверждённые числа или искусственный progress не добавлять ради вида.

## Навигация и длинные формы

- Пять пунктов основной навигации остаются доступны на desktop и mobile; роль и выход также доступны. Добавлять skip-to-main и ясный focus.
- Для длинной карточки использовать anchor-навигацию к сведениям, основаниям, факторам и добавлению материалов. Anchor сохраняет DOM и введённые значения. Не заменять рабочие формы вкладками с unmount.
- Primary action страницы не должен конкурировать с пятью другими primary. В локальном решении primary подтверждает конкретный шаг, outline предлагает просмотр/возврат, danger обозначает отклонение.
- Формы группируются по задаче, labels видимы, необязательные поля подписаны. Подсказки располагаются до ошибки, а не только после неудачного submit. Required/format/size проверяются как сейчас сервером и браузером.
- Не менять IDs/names/roles/API payloads ради стилизации. При ответе 409 показать причину и разрешённое следующее действие, а не автоматически повторять команду.
- Кнопка во время запроса показывает реальное ожидание и disabled. Ошибка не стирает ввод. Данные draft/выбранного файла не должны исчезать из-за закрытия соседнего блока.

## Доступность и адаптивность

Keyboard: Tab в естественном DOM-порядке; Enter/Space работают по нативной семантике; Escape/focus return обязательны для будущих dialogs. Все icon-only действия имеют accessible name. Не убирать outline и не делать интерактивным только hover.

Таблица сохраняет все важные столбцы; горизонтальная прокрутка ограничена подписанным контейнером, доступным с клавиатуры. Вёрстка страницы переносится без горизонтального overflow. Не добавлять `overflow-x:hidden` всему body как исправление.

При 375/768/1024/1440 px проверять: навигацию/выход, заголовок/главное действие, фильтры, длинное название объекта, строки таблицы, inputs/select/file и bottom действия форм. Zoom 200% проверять отдельно от уменьшения viewport. Карта не должна перехватывать прокрутку страницы колесом. Поддерживать `prefers-reduced-motion`.

## Что считать доказательством

Для каждого блока фиксировать страницы/роль/ширины и наблюдавшийся результат. Проверять реальные API и browser E2E, включая ручное решение/PDF. Автоматический contrast/focus тест не заменяет screen-reader и пользовательскую приёмку; соответствие WCAG не объявляется по одному Lighthouse/axe баллу. Состояния ошибок можно воспроизвести перехватом запросов в тесте, обозначив подмену.

Перед публикацией обновлять [UI_AUDIT](UI_AUDIT.md) и PROJECT_STATUS фактическими проверками. Доступность важнее декоративной консистентности; при конфликте сохранять понятный безопасный сценарий.
