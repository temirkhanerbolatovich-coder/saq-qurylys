# SAQ QURYLYS — UX-рекомендации

## Реализовано S0–S2 · 17.10.2026

Уточнение повторного аудита `f9db50b`: гарантия S0 относится к формам `/review`. Причина R4 в досье пока теряется при переходе в реестр и повторном открытии объекта; переключение краткий/подробный сохраняет mounted формы, но не заменяет защиту ухода с маршрута. Это открытый P0, а не реализованная общая гарантия. READY_FOR_REVIEW — статус результата обработки; текущий backend не переводит новые материалы в REVIEWED после всех решений. Его total нельзя интерпретировать как точное число оставшихся действий аналитика. План исправления подписи и защиты — контрольная точка B в UI_IMPLEMENTATION_PLAN.

Пять зон доступны в обоих видах. Обзор сначала показывает действующие очереди NEW / READY_FOR_REVIEW / FAILED / DRAFT и переходы к работе. Проверка использует серверные status/page/page_size (10/20/50), сохраняет `advertisement_id`, фильтры, страницу и Back/reload. Без ID материал не выбирается автоматически. Прямая ссылка загружает выбранный материал независимо от ошибки/фильтра очереди. Выбор и навигация не вызывают команд анализа или подтверждения.

S0 реализован как восстановление черновиков с предупреждением beforeunload, без перехвата истории Next.js. Причины match/hypothesis/R2, изменённый текст гипотезы и OCR, выбранные контекстные значения и fingerprint/UUID неопределённой команды сохраняются в sessionStorage, scoped к пользователю/вкладке/материалу/версии. Восстановление допускается в течение 12 часов после последнего изменения; истечение проверяется при чтении, это не фоновое удаление таймером. Успешная команда очищает соответствующий черновик; 409 и сетевой отказ сохраняют ввод/ключ. Выход или 401 очищает review namespace, включая fallback памяти. Неизменённый исходник/OCR, файлы, credentials и command payload не сериализуются.

При отказе storage действует память только до reload с явным предупреждением. Копия вкладки подчиняется обычной семантике sessionStorage браузера; синхронизация между устройствами не обещается. Восстановленный ввод требует повторной проверки актуальных версий; он не становится серверным решением. Native beforeunload зависит от браузера и предшествующего пользовательского действия. Текущий implementation tradeoff заменяет минимальный guard из первоначального плана, сохраняя ввод при SPA-переходах и настоящем reload без вмешательства в router.

R1–R6, роли, API, источники, исторические snapshots/PDF и разделение REAL/DEMO сохранены. Порядок внутренних инструментов `/monitoring` и перегруппировка досье остаются будущим S3. Ниже исходные предложения фаз 0–1 — историческое основание, а не перечень завершённых возможностей.

## Предложение для аналитического workspace · 17.10.2026 · НЕ УТВЕРЖДЕНО

Это результат фаз0–1, не действующий новый workflow. [Аудит и baseline](UI_AUDIT.md), [карта/ownership/план](UI_IMPLEMENTATION_PLAN.md); прежние правила ниже сохранены. До approval приложение не меняется.

1. **Пять постоянных зон:** Обзор / Объекты / Реклама / Проверка / Сигналы. `/monitoring` — вложенная «Сверка находок», прежний URL и все ручные функции доступны. Глобальный переключатель плотности не должен скрывать целый этап работы аналитика. Это предложение меняет simple-mode16.10 только после подтверждения пользователя.
2. **Показывать следующий шаг по фактам.** Основной обзор отвечает, какое действие ожидается сейчас; score-приоритет объектов отдельный. Не придумывать urgency/SLA/assignment/всеобщие counts без API. NEW-counter уже исправлен.
3. **Сохранять ввод.** В baseline воспроизведён сброс matchReason при review selector A→B→A. До перемещения форм добавить защиту перехода либо scoped session draft. Причины, исправленный OCR, файлы и ключи команд не теряются при локальном раскрытии; сохранённый draft не равен принятому решению. Сохранение после reload/между устройствами отдельно, не обещать его по одному state hook.
4. **Очередь и материал — разные уровни.** Queue использует действующие status/page API, выбранный `advertisement_id` сохраняется; форма не фильтрует первые100 под видом полного поиска. Loading/error/empty различаются. При delayed response не показывать прежний материал под новым ID.
5. **Две панели уже есть.** Улучшить provenance и приоритет правой панели, сохранить оригинал/точный фрагмент. Publication date и capture date различны; отсутствующая дата подписывается. Версия extraction, AI suggested/human confirmed/rejected/unknown/pending различимы; никакого фиктивного confidence.
6. **Досье по задачам.** Сводка/следующий шаг, затем основания/реклама/факторы/доказательства/история/сигналы. Вначале anchors/native disclosures с mounted формами; вкладки не должны сбрасывать решения или скрывать неизвестность. Остальные R1–R6 выполняются в существующих профильных формах, не дублируются в review.
7. **Контекстные инструменты.** Threads относится к поиску источников, КЖК — к справочным документам, DEMO snapshots — к учебной сверке. На первом срезе дать ссылки в нужный существующий раздел `/monitoring`, а не создавать несколько независимых копий формы.
8. **Точный смысл поиска.** Реестр ищет имя/адрес; город — отдельный поддержанный фильтр. Поиск по застройщику/БИН/документам и global sort не поддержаны. Карта ограничена страницей. `risk.as_of` — дата оценки, не гарантированная дата ручной проверки.
9. **Сигнал и инцидент различаются.** Сигнал/PDF хранит конкретную версию/решение/основания; предварительный incident не добавляет R1 и не означает направление во внешний орган. REAL не сравнивается с DEMO.

После approval UX-acceptance: аналитик без подсказки находит ЖК→возвращается к фильтрам; добавляет новый материал→проверяет оригинал→подтверждает доступный фактор→сигнал/PDF; объясняет неизвестный статус и различие гипотезы/решения. Планируемый короткий тест с3–5людьми — критерий: все завершают ключевой путь без блокирующей ошибки; время/неудачные переходы фиксируются, baseline человеческой скорости пока отсутствует. Автотесты не заменяют эту проверку.

Дополнение17.10.2026: досье отвечает «Что найдено / Что подтверждено / Чего не хватает / Что сделать дальше». Analyst без материала идёт к добавлению, с pending documents — к основаниям с раскрытием инструментов, с остальными материалами — в связанный список; viewer — к доказательствам. Это навигация, не автоматическое решение. Импорт по ссылке доступен из формы добавления: URL сохраняется при ошибке, job status объявляется role=status, terminal result получает фокус. Новое намерение после terminal создаёт новый idempotency key; неопределённый сетевой повтор сохраняет старый. Источник/CC BY/извлечение текста показаны до и после импорта. Реестровый поиск показывает дату выбранного PDF, страницу, совпавшие слова и границы; при смене запроса прежняя выдача скрывается. Поиск и загрузка PDF взаимно блокируются на время команды, чтобы результат не оказался от другой выбранной версии. Успех не делает источник юридически применимым.

## Простой интерфейс по умолчанию · 16.10.2026

Начальная навигация: Обзор → Объекты → Реклама. Главное действие обзора — добавить материал; поиск объекта занимает отдельную понятную ссылку. Реестр — поиск и карточки с причинами, DEMO/датой/серверным баллом. URL-фильтры не теряются при переключении вида: активные условия и сброс видны даже при скрытых экспертных selectors. Не выдавать неполную приоритетную выборку за глобальную сортировку.

«Инструменты аналитика» раскрывает подробное меню, фильтры/карту, формы и историю. Это вид интерфейса, не повышение роли. В досье доступна локальная кнопка «Открыть инструменты». Основные факты/источники/доказательства/оговорки доступны и в простом режиме. Сохранение публикации → проверка остаётся явным переходом; анализ/сопоставление/подтверждения не объединяются автоматически.

Ввод требует источник+текст либо источник+файл. URL/дата необязательны и свёрнуты native details; DEMO виден всегда. Переключение режима сохраняет смонтированные формы, выбранный файл и черновики. Режим хранится в localStorage; это не обещает сохранение всех форм после reload (текстовый draft использует прежний sessionStorage). Дополнение 16.10.2026 — Threads: показывать отключённый/неподтверждённый доступ явно; GET статуса и восстановление подключения не запускают внешний поиск. Только явная отправка формы передаёт фразу. При новом запросе/изменении параметров убрать прежнюю выдачу, при отказе сохранить фразу. После результата перенести фокус к уже смонтированному заголовку; ошибки объявлять через role=alert. Не обещать импорт, полноту охвата, географию или проверку правового статуса. Тестовые ответы отделять от фактической доступности источника.

Дополнение 16.10.2026 — [сверка рекламы](FEATURE_MONITORING_CASES.md): из оригинала перейти в `/monitoring?advertisement_id=…`, вручную описать объект, выбрать версию DEMO-списка и сохранить объяснимую сверку. Неподключённые источники/реестр показаны постоянно. Последняя выполненная сверка подписана датой и версиями; ошибка новой команды не должна оставлять старый success. Инцидент — предварительная внутренняя карточка, решение и обоснование аналитика отдельны; viewer видит только чтение. Учебный пример заполняет редактируемую форму, запись происходит только явным сохранением. Длинные UUID/названия переносятся, две колонки становятся одной; DEMO/UNKNOWN/даты/ограничения сохраняются. Новых motion/цветовых правил поверх DESIGN_SYSTEM нет.

Обязательно читать вместе с [DESIGN_SYSTEM](DESIGN_SYSTEM.md) перед frontend-задачами. Основной пользователь — аналитик, сопоставляющий оригинал, объект и доказательства; viewer просматривает сведения. Границы ролей задаёт backend, UI не расширяет полномочия.

## Основные маршруты

Число действий ниже — walkthrough-модель по существующему UI, не результат user testing. Одно заполненное поле/выбор/активация = действие; чтение, ожидание OCR и прокрутка отдельно. Начальная точка указана; ошибки и дополнительные документы увеличивают число. Не удалять необходимые human decisions ради меньшего числа.

| Сценарий / старт | Действия и границы |
|---|---|
| Найти объект / реестр | Ввести q → открыть строку: 2; зона/основание добавляют по 1. API ищет по всему набору, global sorting не поддержана |
| Снять q+зону+основание / реестр | Раньше 3 изменения controls; теперь 1 «Сбросить фильтры», page сбрасывается, view сохраняется, focus в поиск. Каждое поле остаётся отдельно доступным |
| Доказательство / готовая карточка | «Факторы и решения» → «Доказательства»: 2; anchor уменьшает поиск/прокрутку, не изменяет решение |
| Новый текст / обзор | «Добавить публикацию» → происхождение → текст → сохранить: 4; URL/дата добавляют по 1, DEMO default явный |
| Продолжить после сохранения текста | «Перейти к проверке»: 1 вместо прежних 2 (карточка → review). Запуск анализа отдельно: ещё 1, подтверждения не объединяются |
| Файл / обзор | Добавить → «Файл» → происхождение → выбрать файл → сохранить: 5; действия внутри системного file chooser зависят от ОС |
| OCR и matching / сохранённый материал | Перейти в проверку и при необходимости запустить анализ; затем отдельное решение по каждой гипотезе и отдельная привязка к очереди. Число зависит от hypotheses; исправление требует значения/причины |
| R2 / проверенные оплата и match | Выбрать проверенную гипотезу/обосновать по форме → сохранить evidence/PENDING → отдельное подтверждение. Число зависит от уже сохранённых evidence/revision; эти действия нельзя объединить |
| R1/R3/R4/R5/R6 / карточка | Материалы → раскрыть форму → обязательные датированные поля/источники → сохранить → отдельное решение с причиной. Для R1 три механизма, для R5 два сопоставимых документа; UI не сокращает предметные проверки |
| Сигнал / готовая карточка | Создать черновик: 1, открывается версия. Проверить снимок → причина → отдельная кнопка подтвердить/вернуть: минимум 2 взаимодействия с формой; PDF скачивается отдельно после READY |
| Следующая страница / реестр или сигналы | 1 активация; общий Pagination показывает номер/границы. Не нарезать текущие 25 строк под видом серверного набора |
| Оригинал / гипотеза на телефоне | Показать в оригинале: 1, focus к исходнику; к выбранной гипотезе: ещё 1 для возврата |

Точные минимумы для сложных правовых форм зависят от наличия материалов; фиксированное обещание «проверить объект одним кликом» неверно. В следующей UX-сессии измерить время/ошибки по этим начальным точкам. Количество полей оптимизировать группировкой/подписями, сохраняя происхождение/дату/область.

1. Обзор → приоритетный объект → причина и доказательство. Сводка показывает проверяемые серверные числа и помогает перейти к работе.
2. Реестр → фильтр → точная очередь/корпус → карточка. Поиск и фильтры сохраняются в URL. Список остаётся доступным без карты/тайлов; зелёная зона не означает безопасность.
3. Новый текст/файл → сохранённый оригинал → анализ → ручная сверка OCR → привязка объекта → evidence → отдельное решение фактора. Не объединять эти подтверждения и не скрывать исходник.
4. Объект → текущая ревизия → снимок сигнала → подтверждение/возврат с причиной → PDF точной версии. Старый снимок не заменяется свежими фактами. Stale state объясняется с вариантом обновить сведения.

## Ясность и иерархия

С 16.10.2026 обзор показывает пять объектов по серверному баллу среди полученной выборки; при total >100 явно указано ограничение. Общие KPI берутся только из summary. Новые материалы — ровно backend `new_advertisements`, ссылка ведёт к status=NEW, без подмены числом всех публикаций.

Досье получает только закодированную query реестра (`registry`), ссылка возврата всегда имеет фиксированный локальный путь `/properties`. Это сохраняет поиск/страницу/list-map даже после reload, без произвольного redirect. Аналогичный `materials` сохраняет фильтры/страницу рекламы. На карте и в таблице общий выбранный объект, при смене API-выборки выбор сбрасывается. Глобальной сортировки API нет.

Реклама использует существующие status/page/page_size; поиск по тексту не имитируется фильтрацией одной страницы. При новом запросе/ошибке старая очередь скрыта. Даты публикации и фиксации показаны отдельно; неизвестная дата не заменяется текущей. Review хранит выбранный advertisement_id в URL; Back/reload не запускают анализ. Selector ограничен существующими первыми 100 материалами, остальное открывается через пагинируемый реестр. В signals anchors к фактам, решению, PDF и истории перемещают фокус, не размонтируют reason и не создают новую версию.

- Один h1 описывает задачу, h2 — рабочий раздел. Не заменять заголовки uppercase надписями. Глаголы кнопок описывают результат: сохранить материал, подтвердить фактор, открыть версию.
- Коды R1–R6 сопровождаются понятной расшифровкой. Сохранять различие гипотезы, документа, фактора и сигнала. В списке достаточно короткого смысла; полные условия/даты — в досье.
- UNKNOWN, ошибка реестра и «не найдено» не являются подтверждённым отсутствием. Сохранять оговорки в нужном контексте, не повторять общий дисклеймер в каждом визуальном блоке.
- У каждого рабочего блока понятный следующий шаг; опасное/необратимое решение визуально отличается от просмотра. Сохранение supporting-файла само не начисляет баллы.
- Предметные подписи и даты переводить последовательно. Внешний текст/имена рендерить как text, без innerHTML. Неподтверждённые числа или искусственный progress не добавлять ради вида.

## Навигация и длинные формы

История доступна из anchor-навигации досье и в существующем раскрываемом журнале review. События показывают сохранённые переходы и причины, а текущий балл остаётся в RiskSummary. Пагинация использует `history_page`, сохраняет остальную query и фокусирует заголовок; смена публикации сбрасывает её. Переход к факторам/основаниям внутри текущего досье не теряет фильтры возврата. Обновление/просмотр журнала не принимает решение и не запускает анализ. Прежние события скрыты при запросе другой страницы или ошибке. У автора показывается текущее имя профиля; сохранённый ID доступен в записи аудита.

После сохранения нового текста «Перейти к проверке» открывает существующий review за одно действие вместо двух (карточка → review); «Открыть публикацию» остаётся отдельной вторичной кнопкой. Переход не запускает анализ автоматически, исходник/DEMO/даты и обязательное подтверждение каждого факта сохраняются. Фокус после сохранения приходит к результату операции.

На review четыре явных anchor-этапа показывают, где сверять оригинал, сколько гипотез разобрано и требуется ли подтверждение очереди. Это не автоматическое одобрение и не процент готовности юридического заключения. Формы и несохранённые причины сохраняются при переходах между этапами. Главное действие review — анализ текущего материала; новую публикацию можно добавить через раздел «Реклама».

В сигналах фильтры и страница живут в URL, выбор версии/history links сохраняет их, browser Back/reload восстанавливает контекст. Смена фильтра сбрасывает page/выбранный signal_id; reset возвращает focus первому select. Исторический снимок по прямой ссылке может не входить в фильтрованную очередь — это подписывается отдельно. Пока новая очередь загружается или её запрос упал, старые строки не показывать под новыми фильтрами.

- Три основных пункта, в подробном виде шесть, доступны на desktop и mobile; роль и выход также доступны. Добавлять skip-to-main и ясный focus.
- Для длинной карточки использовать anchor-навигацию к сведениям, основаниям, факторам и добавлению материалов. Anchor сохраняет DOM и введённые значения. Не заменять рабочие формы вкладками с unmount.
- Primary action страницы не должен конкурировать с пятью другими primary. В локальном решении primary подтверждает конкретный шаг, outline предлагает просмотр/возврат, danger обозначает отклонение.
- Формы группируются по задаче, labels видимы, необязательные поля подписаны. Подсказки располагаются до ошибки, а не только после неудачного submit. Required/format/size проверяются как сейчас сервером и браузером.
- Не менять IDs/names/roles/API payloads ради стилизации. При ответе 409 показать причину и разрешённое следующее действие, а не автоматически повторять команду.
- Кнопка во время запроса показывает реальное ожидание и disabled. Ошибка не стирает ввод. Данные draft/выбранного файла не должны исчезать из-за закрытия соседнего блока.

## Доступность и адаптивность

Keyboard: Tab в естественном DOM-порядке; Enter/Space работают по нативной семантике; Escape/focus return обязательны для будущих dialogs. Все icon-only действия имеют accessible name. Не убирать outline и не делать интерактивным только hover.

Таблица сохраняет все важные столбцы; горизонтальная прокрутка ограничена подписанным контейнером, доступным с клавиатуры. Вёрстка страницы переносится без горизонтального overflow. Не добавлять `overflow-x:hidden` всему body как исправление.

При 375/768/1024/1440 px проверять: навигацию/выход, заголовок/главное действие, фильтры, длинное название объекта, строки таблицы, inputs/select/file и bottom действия форм. Zoom 200% проверять отдельно от уменьшения viewport. Карта не должна перехватывать прокрутку страницы колесом. Поддерживать `prefers-reduced-motion`.

## Что считать доказательством

Для каждого блока фиксировать страницы/роль/ширины и наблюдавшийся результат. Проверять реальные API и browser E2E, включая ручное решение/PDF. Автоматический contrast/focus тест не заменяет screen-reader и пользовательскую приёмку; соответствие WCAG не объявляется по одному Lighthouse/axe баллу. Состояния ошибок можно воспроизвести перехватом запросов в тесте, обозначив подмену.

Перед публикацией обновлять [UI_AUDIT](UI_AUDIT.md) и PROJECT_STATUS фактическими проверками. Доступность важнее декоративной консистентности; при конфликте сохранять понятный безопасный сценарий.
