# Коллективное обращение / R4

Реализовано 15.10.2026. Это дополнительный ручной путь поверх среза 02; не полный P0.

В карточке ЖК аналитик загружает самостоятельный TXT (UTF-8 ≤100000 символов) либо PNG/JPEG (≤25 MP), файл ≤10 MiB. PDF отклоняется до отдельного этапа безопасного document handling. Автор из сессии; источник/небудущая дата/число заявителей ≥2/основание ручной проверки обязательны. Число и методология — сведения проверяющего, не автоматическая экспертиза подлинности подписей. Не загружайте реальные персональные данные в DEMO.

POST assets/upload сохраняет оригинальные байты/SHA-256 вне webroot и immutable source_details: property_id, source_label/url, event_at, methodology, signatory_count, created_by. Сервер устанавливает captured_at. Документ скачивается только авторизованным пользователем как attachment, inline даже для изображения не разрешён. Источник не загружается по URL. Миграция c4f1a903b812 добавляет nullable JSON к assets; прежние записи сохраняются.

POST evidence с COLLECTIVE_APPEAL требует отдельного DOCUMENT asset того же ЖК и DEMO scope; рекламные/правовые/measurement ссылки здесь недопустимы. Клиентские source/date/method/count не подменяют сохранённое происхождение: копии берутся сервером из asset. Источник, дата, число заявителей и метод видны в доказательстве карточки.

Создание R4 требует такого доказательства и даёт PENDING/0. Подтверждение отдельной командой повторяет guards и даёт +15; отклонение/неопределённость дают 0. Серверные actor/time, reason, optimistic revision, property lock, risk revision и before/after audit используют прежний workflow; устаревшая версия — 409. Текущий фактор один на property/code, повторные доказательства не повторяют вес. Это не правовая верификация R1 и не решение по сигналу.

UI выполняет upload, evidence и pending-factor как последовательные идемпотентные команды. Частичный отказ может оставить сохранённый документ/доказательство без фактора; риск сам не начисляется, данные не удаляются. История/ошибка остаются видимыми; повторное решение всегда отдельное. Quotas/retention/антивирус и production hardening ещё не реализованы. Созданный документ может использоваться повторно только для того же ЖК; синтетические seed документы без provenance не проходят новый R4 guard.

Проверено: PostgreSQL migrations + 85 backend tests (в том числе 7 новых appeal cases), 9 Playwright tests на Docker (в том числе R4 upload/pending/confirm/reject), build/types/lint/format и Alembic check. Неверный ЖК/DEMO, future date, count=1, blank methodology, invalid URL и viewer отклоняются. API принимает только R2/R4 из ручных факторов; R1/R3/R5/R6 пока 422. PDF, реестр оснований, сигналы, независимая предметная приёмка и внешний CI остаются открытыми. Новых зависимостей и значимых архитектурных решений нет.
