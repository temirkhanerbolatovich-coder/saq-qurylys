## Основание и возможности

[Официальная коллекция Meta](https://www.postman.com/meta/threads/request/m9j4i2x/search-for-threads-posts) описывает `GET https://graph.threads.net/keyword_search`, `q`, `search_type=TOP/RECENT`, `limit`, `fields`; в коллекции указан `threads_keyword_search`. В текущей проверке полные [Meta docs](https://developers.facebook.com/docs/threads/keyword-search/) вернули 429. Точное предоставление доступа нашему приложению, app review, квоты и поддержка отдельных режимов подтверждаются живым запросом после получения токена. Bearer — реализация авторизации клиента; её фактическое принятие этим endpoint ещё не проверено.

Модуль выполняет один явный запрос по фразе. `#тег` в `q` остаётся текстом запроса: отдельный TAG API-режим не заявляется. Он не делает автоматическую раскладку RU/KZ-запросов, географический поиск, классификацию рекламы или вывод о полноте выдачи. Установленные пределы 50 результатов / 1 MiB / 60 секунд — локальные пределы SAQ, не квоты Meta.

## Веб-панель и настройка

На экране «Сверка» панель «Поиск в Threads» показывает подключение без сетевого запроса к Meta. Analyst может явно отправить одну фразу, выбрать RECENT/TOP и 1–50 результатов. Viewer читает статус, но не запускает поиск. Результаты живут только на странице: уход со страницы удаляет предпросмотр, публикации/Asset/кандидаты/инциденты не создаются. Поисковая фраза передаётся Threads только при отправке формы; интерфейс предупреждает об этом.

API-контракт **0.10.0-mvp** добавляет `GET /api/v1/monitoring/threads/status` и `POST /api/v1/monitoring/threads/search`. GET требует session; POST — analyst и CSRF. Нет автоматических повторов и гарантии воспроизведения по Idempotency-Key: это временный поиск, не сохраняемая команда. После потери ответа возможен только новый явный запрос с учётом паузы.

| Серверная переменная | Default / ограничение |
|---|---|
| `THREADS_SEARCH_ENABLED` | `false`; включать только после настройки официального доступа |
| `THREADS_ACCESS_TOKEN` | пустой `SecretStr`, только приватная `.env`; не браузер/чат/URL |
| `THREADS_SEARCH_TIMEOUT_SECONDS` | 10, диапазон 1–10 секунд; меньше 15-секундного timeout proxy |
| `THREADS_SEARCH_INTERVAL_SECONDS` | 30, диапазон 1–3600 секунд |

CLI-файл токена и серверная переменная — разные настройки; автоматического копирования между ними нет. После настройки `.env` требуется пересоздать API через `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --no-deps --wait api`. В текущем блоке `.env` и токены не менялись.

`DISABLED`, `TOKEN_MISSING`, `TOKEN_INVALID` блокируют поиск; `CONFIGURED_UNVERIFIED` означает только наличие настройки. `ACCESS_VERIFIED` появляется после успешного ответа последнего запроса и сбрасывается после отказа или рестарта; это не бессрочная гарантия доступа. Ошибка обновления статуса отключает запуск; форма сохраняет введённую фразу. Новый запрос и изменение параметров убирают прошлые результаты. После получения ответа фокус переходит к смонтированному заголовку; ошибки объявляются через Notice/role=alert. Пустая выдача не доказывает отсутствия рекламы или основания.

Один общий `SearchGate` на API-процесс блокирует параллельные поиски и выдерживает паузу, включая Retry-After источника. Очереди/фонового расписания нет. Ограничение хранится в памяти и сбрасывается при рестарте; перед несколькими API workers/репликами нужен общий durable quota/lease. Локальные CLI-запуски не участвуют в этом ограничении. Результаты/фразы не записываются в БД или отдельный журнал поиска; до пилота нужны правила аудита/retention и общий контроль квот.

## Запуск CLI

Из корня проекта, с установленной `.venv`:

```powershell
.venv/Scripts/python.exe -X utf8 scripts/search_threads.py status
.venv/Scripts/python.exe -X utf8 scripts/search_threads.py search --query "Өскемен ЖК" --order RECENT --limit 20 --timeout 20
```

`status` не обращается к сети. Без токена возвращает `TOKEN_MISSING` и exit 2; наличие строки токена возвращает `TOKEN_CONFIGURED; API_ACCESS_UNVERIFIED`, а не успешную интеграцию.

Для живого запроса нужен токен приложения Meta с фактическим доступом к `threads_keyword_search`. Сохранить его **только локально** в игнорируемом `.local/threads-access-token.txt`, одной строкой; не передавать токен в чат/аргументы CLI/URL и не коммитить. Для одного keyword access spike не запрашивать права публикации, удаления или личных сообщений. Скрипт не создаёт приложение, не принимает условия платформы и не получает разрешения за владельца.

CLI работает на хосте; деплой/пересборка приложения для его запуска не нужны. Он не использует серверный `THREADS_SEARCH_ENABLED`.

## Результат и сохранение

Успешная команда пишет новый файл `.local/threads-search/<UTC>-<uuid>.json`, не перезаписывает прежние результаты. Консоль показывает только количество, наличие следующей страницы и путь. Отчёт содержит исходную фразу, порядок/лимит, время получения, SHA-256 полученного ответа и проверенные поля публикаций: `id`, точный `text`, `timestamp`, `permalink`, `media_type`. Неизвестная дата/отсутствующий текст сохраняются как null. Повтор одного ID с одинаковыми полями объединяется; конфликтующие версии в одной странице отклоняются целиком.

`coverage=SINGLE_PAGE_NOT_EXHAUSTIVE`, `review_status=UNREVIEWED_SEARCH_RESULTS`, `registry_status=NOT_CHECKED` действуют и при пустом списке. Настоящий ответ API имеет `is_demo=false`; тестовые ответы существуют только внутри автотестов и не загружаются в рабочую БД.

Исходный полный JSON **не архивируется**: paging.next может содержать секрет. Сохраняется его хеш и нормализованный набор запрошенных полей. Это диагностический результат поиска, ещё не доказательственный оригинал Asset и не импорт Advertisement. Изображения/видео/вложенные документы не скачиваются. До промышленного импорта нужен отдельный контракт сохранения исходников, происхождения/версий, удаления и сроков хранения.

## Сеть и отказы

Код — `backend/app/threads_search.py`, CLI — `scripts/search_threads.py`. Переиспользуются проверка всех DNS-адресов и IP-pinned HTTPS из `url_fetcher`; HTML-collector при этом не включается. Хост/путь фиксированы. TLS проверяется стандартным CA store, proxy из окружения не используется, redirects запрещены. Токен передаётся в subprocess через stdin и в HTTPS Bearer header, не через аргументы/URL. Общий subprocess deadline ограничивает DNS, TLS, headers и чтение тела. Ответ ограничен по байтам/числу записей, compressed/non-JSON ответы отклоняются.

Ошибки представлены безопасными кодами: отсутствие/неверный токен, 401, 403, 429, 5xx, redirect, TLS/DNS/timeout, неподходящая схема. HTTP 400 остаётся REQUEST_REJECTED: Graph может так сообщать и о токене/правах; не считать это автоматически ошибкой поисковой фразы. Сырые сообщения сервера и stderr дочернего процесса не выводятся. Для 429 сохраняется допустимый целочисленный Retry-After, автоматических повторов нет. `paging.next` не сохраняется и не запрашивается. Публичные permalink ограничены HTTPS-доменами Threads; переходы по ним модуль не выполняет.

Веб-слой — `backend/app/api/threads.py`, `frontend/components/threads-search.tsx`. Новых зависимостей, таблиц и миграций нет. Данные основного приложения, риск, предварительные карточки и Telegram не меняются. Ограничение одного ручного запуска не заменяет будущие централизованные quotas, scheduler и управление токенами.
