# Структура ЖК, очередей и корпусов

Локальный согласованный блок UX-04 от18.10.2026, база9e7f195.
Контракт0.16.0-mvp. На публичный сайт не установлен.

## Поведение

В досье видны уровень объекта и ссылки на сохранённую цепочку родителей.
Native disclosure «Очереди и корпуса» содержит непосредственных детей и другие
объекты с тем же ненулевым родителем. Каждый список имеет свои страницы по10.
Навигация ведёт в отдельное досье, сохраняет encoded registry query и открывает
«Обзор». Back/Forward работают как обычная навигация. Страницы списков и раскрытие
локальны текущему досье; после reload возвращаются к начальным значениям.
Сохранённые формы прежнего досье продолжают использовать существующие draft hooks.

Источником отношений служит только Property.parent_id, подписи уровней берутся
из level: PROJECT/PHASE/BUILDING. Имя, адрес, aliases и общий застройщик не
создают связи. Объекты без родителя не считаются соседями. DEMO отмечается у
каждой ссылки. Документы, основания, факторы и риск не наследуются и не суммируются.

## API и данные

`GET /api/v1/properties/{id}/structure` — существующая session auth, analyst/viewer.
Query: children_page≥1, siblings_page≥1, page_size1–100(default10).
Ответ: ancestors от корня к непосредственному родителю и children/siblings
с items/page/page_size/total. References содержат id,parent_id,level,name,address,is_demo;
они не включают risk или документы. Две SQL-выборки применяют count/order(name,id)/
offset/limit до преобразования, без factor_views для каждого найденного объекта.
Родительская цепочка читает максимум16 записей; циклы/превышение/отсутствующий
предок →409, неизвестный текущий объект →404, без сессии →401, неверные pages →422.

Ошибка связей видна в summary и раскрытом сообщении с retry; остальные разделы
досье доступны. Ошибка не выдаётся за пустой список. При смене страницы старые
строки не выдаются за новый результат; фокус остаётся внутри доступной области.
Открытие/листание/переходы не выполняют бизнес-команд. Миграций, seed-изменений,
новых dependencies, изменения auth/ролей/расчёта/snapshots нет.

## Реализация и проверка

Backend: app/api/properties.py и dto.py. Frontend: PropertyStructure с существующими
useData/LoadState/Pagination/Link, текущие semantic tokens и native details.

транзакционные synthetic rows с rollback,103 ребёнка, родители/соседи, отсутствие
ложного группирования, страницы/валидация, циклы/глубина, viewer и неизменность досье.

Browser: property-structure.spec.ts, responsive spec и явно presentation-only
fixture; дополнительно настоящий GET текущего DEMO-досье. Фактические результаты
и визуальные ограничения — [UI_AUDIT](UI_AUDIT.md), запуск — [PROJECT_STATUS](../PROJECT_STATUS.md).

## Ограничения

В текущем seed все8 объектов имеют parent_id=null и level=PHASE. Их названия
содержат слова «очередь/корпус», но это не доказательство структуры. Старые данные
не переписывались. Трёхуровневая навигация проверена на отдельных PostgreSQL rows
и browser presentation tree, а не на подтверждённых связях настоящего реестра.
Редактор/импорт parent_id, новая глобальная сортировка, полнотекстовый поиск и
нагрузочная проверка не входят в блок. Для реального наполнения нужна отдельно
проверенная структура; отсутствие связей не означает отсутствие очередей в мире.
