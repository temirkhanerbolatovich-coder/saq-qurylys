## Как использовать сведения

1. Сначала искать применимый документ по объекту/очереди, юридическому лицу и относящейся к событию дате в источниках первого приоритета. Проверять назначение: лицензия на строительные работы, сведения об организации и разрешение на привлечение денег — разные документы.
2. БИН помогает найти кандидата юридического лица; название, адрес, очередь и область действия документа проверяются отдельно человеком. Перечень организаций, наличие участка, налоговый статус и РНУ сами по себе не подтверждают применимое основание и не добавляют баллы R1–R6.
3. Сохранять исходную ссылку/копию, время получения, известную дату публикации/обновления, издателя, номер, область и период действия. Неизвестную дату оставлять неизвестной; время загрузки не подставлять вместо даты документа. Для набора дополнительно фиксировать его идентификатор и версию, охват и дату актуальности.
4. Доступный документ можно вручную приложить через существующий supporting upload с явным назначением и происхождением. Для PDF действуют [ограничения формата](FEATURE_SUPPORTING_PDF.md); upload не подтверждает документ, связь, фактор или сигнал. На синтетическом DEMO-объекте нельзя выдавать реальный документ за относящееся к нему основание.
5. Пустой поиск, ошибка сервиса, устаревший набор, отсутствие строки или несовпадение названия оставляют вопрос неизвестным. R1 требует [отдельной датированной проверки всех применимых механизмов](FEATURE_LEGAL_ABSENCE.md) и решения человека. Автоматического юридического вывода нет.

## Порядок дальнейшей интеграции

Первый шаг — проверить паспорт и разрешённую выгрузку указанного Ashyq-набора либо подходящего актуального набора data.egov.kz. Если доступен документированный способ, сохранить небольшой ограниченный образец и его происхождение, описать поля и правила ручного сопоставления, затем реализовать один импорт по существующим моделям. Не создавать общий слой адаптеров для всех порталов до первого рабочего источника. Если условия или содержание не установлены, сохранить конкретный блокер и продолжать ручной документальный путь.

Публичные страницы и документированный API — разные уровни доступа. Предложение пользователя разрешает исследовать эти источники для проекта; технические условия портала, охват, объём запросов и необходимость авторизации проверяются до регулярной загрузки. Без обхода login/CAPTCHA, выдуманных endpoint и массового сбора. Для будущего сетевого импорта сохраняются allowlist/SSRF/redirect/size/time limits из [архитектуры](ARCHITECTURE.md).

Этот каталог не закрывает **C-01**: там требуется фактический разрешённый URL/HTML-импорт рекламного материала. Импорт официального реестра — отдельный запланированный P1. Реестровые источники и карточка объекта не становятся рекламой автоматически; изменение объёма C-01 потребовало бы явной фиксации в требованиях. Текущий контракт и код collector не изменены.
