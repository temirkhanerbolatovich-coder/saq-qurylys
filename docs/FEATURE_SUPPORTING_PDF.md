# Исходные PDF-документы

Обычный PDF можно добавить в существующих формах правового основания, коллективного обращения, строительства/готовности/сроков и проверки отсутствия всех механизмов. Сохраняются исходные байты, SHA-256, конкретная очередь, DEMO-признак, источник, дата и методика. Загрузка не подтверждает документ, фактор или сигнал: решения аналитика остаются отдельными.

## Пользовательский сценарий

1. В карточке объекта выбрать назначение документа и заполнить существующие реквизиты.
2. Выбрать TXT, PNG, JPEG либо обычный PDF без пароля, форм, действий и вложений.
3. После проверки оригинал сохраняется как `DOCUMENT` с MIME `application/pdf`; дальнейшие evidence/review/snapshot используют его обычным способом.
4. «Открыть сохранённый материал» скачивает оригинал через авторизованный endpoint. PDF выдаётся как attachment с `application/octet-stream`, `nosniff` и CSP sandbox, включая запрос `inline=true`.

PDF не принимается в рекламную загрузку и не проходит автоматический OCR/извлечение. Сканированный PDF аналитик читает самостоятельно; указанные факты и область по-прежнему требуют проверки человеком. При отклонении оригинал и история сохраняются. PDF-экспорт сигнала — отдельный уже реализованный сценарий.

## Проверка файла

`pypdf==6.20.1` в strict-режиме проверяет структуру, а проектная политика ограничивает принимаемое содержимое. Проверяются PDF header/EOF, хотя бы одна страница, шифрование и все индексированные объекты, включая неиспользуемые и object streams. Запрещены формы/XFA, JavaScript, действия, ссылки действий, вложения, внешние файлы/потоки, multimedia и другие активные элементы. Это строгий приём, а не исправление или очистка PDF: байты не переписываются.

Разбор выполняется отдельным Linux subprocess с ограничениями CPU/address space. API ожидает его в thread pool; два слота на процесс API ограничивают одновременную проверку. После отказа ни Asset, ни файл не создаются. Политика и причины выбора — [ADR-007](decisions/ADR-007-bounded-passive-pdf-upload.md).

| Ограничение | Значение |
|---|---|
| Размер файла | `MAX_UPLOAD_BYTES`, по умолчанию 10 MiB; ограничения proxy/body middleware сохраняются |
| Страницы | `PDF_MAX_PAGES=100`, допустимо 1–500 |
| Время проверки | `PDF_VALIDATION_TIMEOUT_SECONDS=10`, допустимо 1–10; меньше 15-секундного proxy timeout |
| Память subprocess | 512 MiB address space |
| Сложность | До 10000 объектов, глубина до 50, до 100000 посещений узлов |
| Конкурентность | Два subprocess на процесс API; занятые слоты возвращают 503 |

Неподдерживаемый тип, повреждённая структура или активное содержимое дают 415; размер/страницы/сложность — 413; timeout, занятые слоты или недоступная среда — 503. Ответы не содержат внутренние исключения или содержимое документа. MIME, имя файла и сигнатура не заменяют структурную проверку.

## Запуск и проверка

Поддерживаемый runtime — Linux Docker. Native Windows API возвращает 503 для PDF: в нём отсутствуют используемые POSIX resource limits; TXT/PNG/JPEG продолжают работать. Установка Python-пакета на host сама по себе эту границу не снимает.

Миграции и новые endpoints не требуются. `POST /api/v1/assets/upload` расширяет форматы; `GET /api/v1/assets/{id}` сохраняет авторизацию и правила скачивания. Исторический контракт этого среза — 0.8.0-mvp (36 операций). Актуальный контракт 0.11.0-mvp содержит 49 операций, 48 implemented и 1 partial; коммерческий C-01 остаётся отдельным открытым требованием. Оставшийся partial у отдельного LegalBasis review намеренный: отсутствие всех механизмов подтверждается составным R1.

Тесты: `backend/tests/test_pdf_validation.py`, `backend/tests/test_supporting_pdf.py`, `frontend/tests/supporting-pdf.spec.ts`. Linux-прогон проверяет настоящий subprocess; host-результаты со skip не заменяют его. Фактические результаты: полный Linux backend **279 passed (110.26s)**, browser **17 passed (52.2s)**, включая настоящее скачивание PDF и сохранение решения. Результаты и история отказавшего первого тестового прогона записаны в [PROJECT_STATUS](../PROJECT_STATUS.md).

## Ограничения

Это не антивирус, доказательство подлинности или гарантия безопасности любой PDF-программы. Потоки страниц не декодируются и не рендерятся при загрузке. Некоторые легитимные документы с формами, подписями на полях, интерактивными оглавлениями/ссылками или нестандартной структурой будут отклонены. Для них нужен отдельный согласованный сценарий; автоматически изменять подписанный оригинал нельзя. Сетевой доступ для проверки не используется. Нагрузочная приёмка, quotas, retention и внешний антивирус остаются отдельными вопросами перед пилотом.
