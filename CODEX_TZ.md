## 1. Определение готового MVP (P0)
Система должна продемонстрировать новый вход, отсутствующий в seed:
1. Аналитик вручную добавляет URL, текст или изображение объявления; система сохраняет источник, время и оригинал.
2. Один реально работающий разрешённый URL/HTML-collector извлекает новое объявление/страницу (не имитируй интеграцию; если не удалось найти разрешённый источник, зафиксируй BLOCKED и реализуй ручной импорт, не выдавая его за автоматический).
3. OCR распознаёт RU/KZ текст на новом изображении (Tesseract rus+kaz+eng; проверка на собственном наборе).
4. Извлекаются название ЖК, формулировки оплаты, денежные суммы, ссылки на доказательные фрагменты; rule-based fallback допустим, но должен работать на новых текстах. Подключаемая LLM — P1, если есть время.
5. RapidFuzz выдаёт кандидатов на сопоставление с конкретным ЖК/очередью; аналитик подтверждает связь.
6. Для ЖК видны застройщик, адрес, стадия, координаты, правовые основания с типом, источником, датой и статусом проверки. Отсутствие сведений НЕ равно доказанному отсутствию основания.
7. Аналитик подтверждает или отклоняет гипотезы, R1–R6 начисляются только по подтверждённым факторам; ведётся аудит.
8. Формируются объяснимый балл/зона, сигнальная карточка с решением человека и PDF, содержащий источники, дату, автора и оговорку «Сигнал необходимости проверки; не устанавливает факт правонарушения».
9. Реестр и/или карта, Dashboard, карточка ЖК, лента объявлений, экран проверки гипотез, очередь сигналов работают на реальном API.
10. Seed: >=8 ЖК, >=12 объявлений, >=3 контрастных сценария, все вымышленные поля помечены DEMO; реальные документы не смешивать с фиктивными статусами.
11. README, `.env.example`, миграции, seed, воспроизводимый запуск, тесты, GitHub CI.

## 2. Формула риска — неизменяемая бизнес-логика
- R1 +35: документально установлено отсутствие применимого правового основания на соответствующую дату, не просто отсутствие записи.
- R2 +25: подтверждено прямое предложение внести деньги (платная бронь, депозит и аналогичные условия).
- R3 +10: подтверждена активная реклама жилья до завершения строительства.
- R4 +15: подтверждено коллективное обращение.
- R5 +10: подтверждено расхождение заявленной и проверенной готовности >=20 процентных пунктов, обе цифры с источниками/датами.
- R6 +5: документирован существенный простой или задержка.
Сумма уникальных подтверждённых факторов на объект, максимум 100. UNKNOWN, PENDING и REJECTED дают 0. Зелёная зона 0–24; жёлтая 25–59, а также >=60 без одновременных R1+R2; красная >=60 только при подтверждённых R1 и R2.
Тесты: A (R2+R3, неизвестное основание)=35/yellow; B (R1+R2+R3)=70/red; C (R3, подтверждённая гарантия)=10/green. Добавить тесты >=60 без R1+R2, дублей, отклонения и пересчёта.

Не считать ипотечный продукт банка разрешением на привлечение денег. Для каждого документа хранить тип, номер, дату, охват объекта/очереди, URL, дату получения, статус проверки. Импорт официального PDF-реестра гарантий КЖК через pdfplumber — P1, если не мешает P0.

## 4. Стек и структура
Один репозиторий. `frontend/` Next.js + TypeScript + Tailwind + shadcn/ui; `backend/` FastAPI + Pydantic + SQLAlchemy + Alembic + PostgreSQL; `contracts/` OpenAPI; `docs/`; `data/seed/`; `docker-compose.yml`; `AGENTS.md`; `PROJECT_STATUS.md`.
Для карты выбрать **один** стек (Leaflet + OSM либо MapLibre), не подключать оба. Для OCR Tesseract; RapidFuzz для entity matching; HTTPX+BeautifulSoup для разрешённого HTML; WeasyPrint для PDF. Background tasks — простой контролируемый worker/DB job queue, без Redis, пока не доказана необходимость. Секреты только через env. Приоритет простоты.

## 6. UX/UI — приоритет наравне с функциональностью
Пользователь — аналитик государственного органа. За 10–20 секунд (целевой UX-показатель, не подтверждённый факт) он должен найти новый риск, понять причину, открыть источник и действие.
Навигация: Обзор; Объекты; Реклама; Проверка; Сигналы. Не смешивать всё на одной странице.
- Dashboard: число объектов по зонам, новые публикации, ожидающие проверки, последние сигналы, фильтры; не использовать декоративные бессмысленные графики.
- Объекты: таблица с названием/очередью, адресом, статусом основания, баллом, последней проверкой; карта с теми же фильтрами.
- Карточка ЖК: статус документа с датой/источником, подтверждённые факторы, неизвестные сведения, реклама, история.
- Реклама: добавить URL/текст/изображение, статус анализа, оригинал, источник, время, OCR-фрагменты.
- Проверка: split view «оригинал ↔ гипотеза», подсветка фрагментов, кандидаты ЖК, кнопки принять/исправить/отклонить, причина решения.
- Сигналы: очередь, подтверждение/возврат с причиной, предпросмотр, PDF, версии.
Понятная типографика, состояния loading/empty/error, адаптивность, доступность с клавиатуры, подтверждение критических действий, DEMO-бейдж на фиктивных данных. Не показывать AI-гипотезу как факт.

## 9. Acceptance tests и демонстрация
- Чистый запуск по README на другом ПК.
- Импорт нового текста и изображения, OCR RU/KZ, сохранённый источник/время, анализ.
- Сопоставление с ЖК, ручная коррекция.

- Подтверждение и отклонение, аудит с автором/временем.
- Пересчёт и обновление Dashboard/карты.
- PDF открывается, кириллица корректна, доказательства и предупреждение видны.
- Реальный разрешённый источник подтверждён фактическим результатом; если нет — честно BLOCKED.
- Никаких hardcoded ответов AI только для seed.
