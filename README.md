# SAQ QURYLYS

Рабочее место аналитика для проверки признаков риска в рекламе долевого жилищного строительства Казахстана. Система помогает собрать проверяемый сигнал и не устанавливает факт правонарушения.

**На 15.10.2026 работает локальный сквозной сценарий:** вход/реестр/новый текст и PNG/JPEG/TXT → PostgreSQL worker → Tesseract RU/KZ OCR → гипотезы/кандидаты → ручная проверка → доказательства и отдельные решения R1–R6 → риск/аудит → исторический снимок сигнала → подтверждение или возврат → PDF. Также доступны сохранение и датированная проверка правового основания, включая исходные PDF. R1 требует документальной проверки всех трёх проектных механизмов на точный момент; R3/R5/R6 — отдельных документов и проверки дат/сопоставимости. Seed содержит 8 вымышленных DEMO-объектов и 12 исходных публикаций.

Интерфейс следует направлению «рабочее досье аналитика»: читаемые таблицы, объяснения факторов, навигация по карточке и доступные действия на телефоне. [Дизайн-система](docs/DESIGN_SYSTEM.md) и [UX-рекомендации](docs/UX_GUIDELINES.md) обязательны перед frontend-задачами. Текущий полный локальный прогон — **35 browser passed**, повторены 32 responsive observations на 375/768/1024/1440 px без page overflow. Keyboard/contrast входят в suite; прежняя отдельная проверка настоящего zoom 200% и границы приёмки описаны в [UI-аудите](docs/UI_AUDIT.md).

Repo Skill `.agents/skills/ui-ux-pro-max` закреплён на проверенном upstream commit; локальные Python search и Codex discovery проверены. [Каталог компонентов](docs/UI_COMPONENTS.md), [план поддержки](docs/UI_IMPLEMENTATION_PLAN.md) и AGENTS задают reuse Pagination/TableRegion, tokens H1–H6, доступность и browser verification. Skill передаётся через Git, новых runtime dependencies нет.

После сохранения текста можно сразу перейти к проверке, формы разделены на обязательный материал и необязательный контекст, review имеет четыре этапа с фактическим счётчиком гипотез. Фильтры/страница сигналов и выбранная версия сохраняются в URL; Back/reload и история версий удерживают контекст. Во время нового запроса прежняя очередь не выдаётся за отфильтрованный результат. Анализ и все решения остаются явными отдельными действиями; backend/API/формула риска сохранены.

Опубликованный [CI 8434d1b](https://github.com/temirkhanerbolatovich-coder/saq-qurylys/actions/runs/38779704092) подтвердил **294 backend / 35 browser / 27 tool tests**, offline Skill smoke и frontend checks/build. Качество OCR измерено отдельно и цели ещё не достигнуты. Полная приёмка P0 остаётся открытой: разрешённый collector, новый внешний OCR holdout, второй ПК и UX/предметная проверка людьми. Docker работает, запущены только контейнеры SAQ. Ревизии и проверки записаны в [статусе](PROJECT_STATUS.md); остальные задачи — [в чеклисте](docs/REMAINING_CHECKLIST.md). Изменения только Markdown не запускают повторную полную сборку.

## Быстрый запуск через Docker

Требования: Python 3.12+ только для генерации конфигурации, работающий Docker Desktop с Linux engine/WSL2 и Docker Compose, свободный localhost:3000. Если Docker Desktop остановлен, запустите его; проверьте, не настроен ли автозапуск посторонних контейнеров.

Из корня проекта:

```powershell
python scripts/configure_local.py
docker compose up --build -d --wait
```

Откройте http://localhost:3000. Логин/пароль записаны в приватном `.local/credentials.txt`. В Git эти данные не попадают. Генератор не перезаписывает существующий `.env`. После первого запуска можно использовать `docker compose up -d --wait`, без повторной сборки.

По умолчанию наружу открыт только UI на 127.0.0.1. API/БД доступны внутри Compose. БД хранится в volume `saq-qurylys_postgres_data`, исходники — в `storage/`. Для остановки без удаления данных:

```powershell
docker compose stop
```

Не используйте `down -v` для обычной остановки: это удаляет БД. Публикация в интернет, реальные персональные данные и ведомственное использование этим рецептом не предусмотрены.

### Первый запуск на Linux/WSL

На Linux/WSL с native filesystem перед первым стартом подготовьте права новой папки `storage` для пользователя контейнера. Это одноразовый шаг для пустого хранилища; существующие файлы не удаляются и рекурсивно не меняются:

```bash
docker compose build
mkdir -p storage
docker compose run --rm --no-deps --user root --entrypoint chown api saq:saq /app/storage
docker compose up --no-build -d --wait
```

Если используется dev override, добавляйте `-f docker-compose.yml -f docker-compose.dev.yml` во все Compose-команды этого шага. В GitHub browser E2E права готовятся таким же способом; API и worker продолжают работать без root.

## Локальная разработка без контейнеров API/UI

Сначала выполните генератор конфигурации выше. PostgreSQL можно оставить в Docker:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m app.seed
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Для image-анализа запустите worker в третьем терминале из backend: `..\.venv\Scripts\python.exe -m app.worker`; установите Tesseract с rus/kaz/eng или используйте Docker worker. При dev Compose всегда указывайте оба `-f` файла при последующем up, чтобы сохранить проброс PostgreSQL 55432.

При загрузке исходных PDF требуется API в Linux Docker: native Windows API возвращает 503 для этого формата, поскольку ограничение памяти/CPU parser использует POSIX resource limits. `PDF_MAX_PAGES=100`, `PDF_VALIDATION_TIMEOUT_SECONDS=10`; детали — [исходные PDF](docs/FEATURE_SUPPORTING_PDF.md).

Нужен Node.js 24. API proxy по умолчанию обращается к 127.0.0.1:8000. Альтернативный адрес задаётся серверной переменной `API_INTERNAL_URL`. Не запускайте host UI и контейнер frontend одновременно на порту 3000. Локальная production-проверка: `npm run build`, затем `npm start`. Перед новой сборкой остановите локальный standalone server: Windows блокирует его файлы.

## Первый тестовый сценарий

1. Войти, открыть обзор и реестр, отфильтровать красную зону. Переключить «Карта и список», выбрать метку мышью или Tab → Enter и открыть карточку. При отказе подложки остаётся список. Провайдер/отключение карты и публичные build-time параметры — [FEATURE_MAP](docs/FEATURE_MAP.md).
2. Открыть DEMO Бәйтерек: 70/red, факторы R1+R2+R3. Открыть доказательство R1 и его сохранённый синтетический текст.
3. DEMO Самал: 35/yellow, правовое основание неизвестно; R1 отсутствует. DEMO Өркен: подтверждённая DEMO-гарантия, 10/green.
4. Добавить собственный новый DEMO-текст и источник; дату публикации оставить неизвестной.
5. Открыть публикацию, проверить переносы/RU/KZ символы, отдельное время фиксации и скачать оригинал. Обновить страницу — запись остаётся. Новое объявление само не начисляет факторы.

6. Открыть «Проверка» из карточки, запустить анализ, сверить фрагменты. Подтвердить гипотезу оплаты и отдельно конкретную очередь; выбрать проверенную гипотезу и сохранить доказательство R2.
7. Созданный PENDING фактор не даёт баллов. Отдельно подтвердить R2 (+25), затем отклонить (0) и открыть журнал решений. Для первого нового R2 удобен DEMO Ертіс без исходных факторов.
8. Для OCR загрузить собственный PNG/JPEG через «Добавить публикацию → Файл»; после анализа показать bbox, исправить гипотезу/расшифровку. Предыдущие версии и исходник сохраняются.

9. В карточке объекта открыть «Строительство: документы и сравнение». Для R3 сохранить отдельный документ о незавершённой стройке на день датированной публикации; для R5 — два сопоставимых документа о готовности с расхождением ≥20 п.п.; для R6 — документ о сроках с ручным обоснованием существенности задержки. Сохранение материалов не начисляет баллы: требуется отдельное подтверждение или отклонение.

10. Для R1 открыть «Проверить три механизма на дату», загрузить отдельное DEMO-заключение, указать область, дату отсутствия и дату документа, результаты/обоснования каждого механизма. UNKNOWN/NOT_FOUND/UNAVAILABLE можно сохранить как материал, но они не подтверждают R1. Все три DOCUMENTED_ABSENT позволяют создать PENDING/0; отдельное решение подтверждает +35 или отклоняет/0. Применимые VERIFIED_VALID/PENDING документы требуют разрешить противоречие. Для совместного подтверждения R1/R2 нужна известная published_at проверенной оплаты, точно совпадающая с датой R1; неизвестную дату нельзя заменить импортом.

11. Создать сигнал по текущей ревизии, открыть сохранённые факторы/источники и явно подтвердить либо вернуть его с причиной. Дождаться готового PDF и скачать его. После изменения фактов создать следующую версию: прежний снимок и его PDF сохраняются. Устаревшее решение даёт 409.

Supporting documents принимают обычные PDF через [ограниченную проверку в Linux](docs/FEATURE_SUPPORTING_PDF.md); реклама загружается как TXT/PNG/JPEG. URL в ручной форме — сохранённая ссылка, не работающий collector. Зелёная зона не подтверждает безопасность объекта. Датированное отсутствие по R1 не выставляет бессрочный текущий VERIFIED_ABSENT: карточка отдельно показывает legal_absence_as_of.

## Проверки разработки

Локальная резервная копия PostgreSQL **вместе с файлами** и проверка восстановления в изолированный контейнер: `python scripts/backup_local.py create`, затем `python scripts/backup_local.py verify "ПУТЬ_КОПИИ"`. Копии остаются в приватной `.local/`, рабочая БД не перезаписывается. Подробные условия, краткая пауза API/worker и ограничения — [LOCAL_BACKUP](docs/LOCAL_BACKUP.md).

Тесты инструмента без Docker и дополнительных пакетов: `python -m unittest discover -s scripts -p "test_*.py" -v`.

Для host integration-тестов PostgreSQL должен быть доступен по localhost:55432 через dev override. Тесты создают случайную отдельную schema в SAQ-БД и удаляют только её, не сбрасывая public/пользовательские записи. Полный PDF runtime проверяется в Linux с Pango; Windows без этих библиотек пропускает render-тест. Полный прогон выполнен во временном Compose api test container с подключёнными read-only backend/contracts, временным venv (`--system-site-packages`) и отключёнными cache/pyc; рабочие API-зависимости не изменялись.

Для самостоятельного Linux-окружения перед `pip install -r backend/requirements-dev.txt` установите `libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0 fonts-dejavu-core`; OCR дополнительно требует Tesseract с rus/kaz/eng. Затем из backend выполните `python -m pytest -q`. Каталог contracts должен оставаться доступным рядом с backend.

Из backend:

```powershell
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m ruff check app tests alembic
..\.venv\Scripts\python.exe -m ruff format --check app tests alembic
..\.venv\Scripts\python.exe -m alembic check
```

Из frontend:

```powershell
npm run lint
npm run typecheck
npm run format:check
npm audit --audit-level=high
npm run build
```

При запущенном полном приложении:

```powershell
npm exec -- playwright install chromium
npm run test:e2e
```

Перед image E2E из корня выполните `.venv\Scripts\python.exe scripts/verify_ocr.py` при работающем приложении: он генерирует `output/qa/ocr-kz.png` и проверяет реальные RU/KZ задания. Требуются development requirements и Arial в Windows или DejaVu в Linux. Это два синтетических баннера, не независимая оценка точности. Для более широкого прогона добавлен `scripts/evaluate_ocr.py --output output/evaluation/new-run`: 36 новых синтетических изображений, отдельные OCR/payment/matching-метрики и сохранённые baseline/results. После исправления алиасов: precision 80%, recall 75%, top-3 18/24; **цели качества не достигнуты**. Методика/команды/ограничения — [OCR_EVALUATION](docs/OCR_EVALUATION.md). [CI cba28ec](https://github.com/temirkhanerbolatovich-coder/saq-qurylys/actions/runs/38756623850) прошёл: 294 backend / 22 browser / 27 tool tests и frontend checks/build; метрики качества совпали с локальными.

Browser-тесты создают новые DEMO-публикации, проверяют draft/navigation/reload, источники, ручные R1–R6, правовое основание, реальный OCR/bbox, сигналы/решения/PDF и мобильный реестр. Успешные сценарии оставляют историю по DEMO Ертіс с итоговыми отклонёнными R1–R6/0; проверка гонки R2 сохраняет новое evidence по Самал без изменения его фактора/балла. Пароль не вводится в DOM автоматического теста: сессия получается через API. Trace выключен; снимки и результаты лежат в игнорируемых `output/qa/` и `frontend/test-results/`.

## Архитектура и конфигурация

Next.js/TypeScript/Tailwind, FastAPI/Pydantic/SQLAlchemy/Alembic, PostgreSQL, локальные исходники вне webroot. Actor определяется серверной сессией; CSRF проверяет подпись/сессию/Origin. Idempotency-Key защищён транзакционной блокировкой PostgreSQL. Только backend считает риск: уникальные CONFIRMED R1–R6 с весами 35/25/10/15/10/5; красная зона >=60 и одновременно R1+R2.

`.env.example` различает используемые переменные и будущие параметры. `scripts/configure_local.py` создаёт уникальные локальные secrets. Смена BOOTSTRAP_ANALYST_PASSWORD в env сама по себе не сбрасывает пароль существующего пользователя: seed сохраняет существующие данные. Административное управление учётными записями и ротация — следующий отдельный сценарий.

`contracts/openapi.yaml` — контракт **0.8.0-mvp: 36 операций, 34 полностью реализованы, 1 частично, 1 PLANNED**. Частичен review отдельного LegalBasis: VERIFIED_ABSENT намеренно не подменяет составной R1. Единственная planned-операция — collector. Пользователь предоставил [11 источников реестров и открытых данных РК](docs/DATA_SOURCES.md); каталог фиксирует доступность и порядок исследования, но импорты ещё не реализованы и не заменяют рекламный collector C-01. Лимит chunked-body добавлен в API и proxy; production rate limiting, quotas/retention и SSO остаются открыты. Точные изменения и границы — в документах функций и PROJECT_STATUS.

API и worker используют одну Docker-сборку и общий storage; OCR выполняется вне HTTP/SQL-транзакции. Lease и claim token защищают от позднего worker. Пересмотр используемой гипотезы снимает зависимый CONFIRMED R2; изменение расшифровки/привязки снимает зависимые R2/R3 в PENDING. Новая автоматическая версия сама не меняет принятые решения.

TXT можно загрузить через ту же файловую форму: UTF-8 до 100000 символов, без бинарных управляющих символов. Исходные BOM/CRLF сохраняются; TXT проходит правила без OCR. UNKNOWN стадия показана как «Не проверена», факторы R1–R6 имеют отдельные подписи.

Коллективное обращение/R4: в карточке ЖК доступна загрузка TXT/PNG/JPEG с датой, источником, числом заявителей (от 2) и основанием ручной проверки. После сохранения доказательства нужен отдельный шаг подтверждения (+15) или отклонения (0). Обычный PDF поддерживается через [ограниченную проверку](docs/FEATURE_SUPPORTING_PDF.md). Подробнее: [сценарий R4](docs/FEATURE_COLLECTIVE_APPEAL.md).

Строительство/R3/R5/R6: точная область ЖК, неизменяемые факты документа и разные оригиналы. Один календарный день для R3 и одинаковые дата/методика/область R5 — консервативные правила MVP, а не утверждение о правовой норме. R6 не использует выдуманный порог дней: аналитик обосновывает существенность. См. [сценарии](docs/FEATURE_CONSTRUCTION_REVIEW.md) и [ADR-004](docs/decisions/ADR-004-dated-construction-evidence.md).

Правовые основания: в карточке ЖК раскройте «Ввести реквизиты и загрузить документ», загрузите собственный DEMO TXT/PNG/JPEG, укажите механизм, номер/дату/издателя, конкретную очередь и период. Сохранение даёт PENDING; применимость подтверждается или отклоняется отдельно с датой и причиной. Истёкший период не считается текущим VERIFIED_VALID; отклонение и неизвестность не дают R1. Отдельная проверка всех механизмов описана в [сценарии R1](docs/FEATURE_LEGAL_ABSENCE.md) и [ADR-005](docs/decisions/ADR-005-dated-all-mechanism-absence.md). Подробно об отдельном документе: [правовое основание](docs/FEATURE_LEGAL_BASIS.md), [ADR-003](docs/decisions/ADR-003-dated-legal-applicability.md).
